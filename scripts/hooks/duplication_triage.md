# 重复判定提示词：三问通用内核与仓库覆盖层

本文件是克隆门禁判定辅助的提示词工件，物理上只存此一份：判定任务包（`just dup-triage` 的输出）在开头嵌入全文，代理据此对单个克隆对给出语义判定。通用内核不含项目信息，可移植；仓库覆盖层把内核的抽象词落到本仓库的部署与边界事实。判定权在人：代理产出的三选一结论与基线登记都经拉取请求评审确认。

## 三问通用内核（逐问短路执行）

```text
## 重复判定程序（通用内核，逐问短路执行）

Q1 变化轴（这是知识重复还是碰巧相似？）
   问：这两段代码会因同一个需求变更而同时修改吗？
   ├─ 会（同一知识点散落多处）        ⇒ 知识重复 → 继续 Q2
   └─ 不会（各自有不同的演化原因）    ⇒ 文本重复 → 判定：retain

Q2 边界（合并是否破坏部署或所有权边界？）
   问：克隆两侧是否隔着部署单元、平台/适配层或独立演化方？
   ├─ 跨部署单元（服务、前后端、独立发布物）⇒ 判定：retain
   │     （共享代码引入版本与发布耦合）
   ├─ 跨平台/适配边界（统一会迫使抽象层泄漏平台概念）⇒ 判定：retain
   └─ 同侧、同发布单元                ⇒ 继续 Q3

Q3 抽象成本（错误抽象比重复贵）
   问：合并之后，调用方与后续维护者会变难读吗？
   ├─ 参数化导致开关堆积、回调嵌套、条件爆炸 ⇒ 判定：retain
   ├─ 既有接缝已能表达差异（传参/闭包表/数据表已存在）⇒ 判定：eliminate（成本最低）
   ├─ 这是第 ≥3 次出现（Rule of Three）      ⇒ 判定：eliminate
   └─ 第 2 次出现、需要新建抽象              ⇒ 判定：retain（观察）

默认值：信息不足时一律 retain——重复便宜，错误抽象贵。
判定的对象是“知识”，不是“字符”：相似但变化轴不同的代码合并不了也不该合。

## 输出契约（三选一，全部带缘由）
eliminate：<建议抽壳位置，一句话>
retain：<缘由一句话，供基线登记>
exempt：<缘由一句话，供就地放行标记>
```

## 仓库覆盖层

### 词表映射

内核抽象词到本仓库事实的对应，判定时先按此表替换词面再走三问：

- 部署单元 → 工作区分包（`gloss-core`、`gloss-platform`、`gloss-app`、`gloss-llm`、`gloss-eval`）与应用发布物；
- 平台与适配边界 → `crates/gloss-platform/src/` 下 `macos/` 与 `windows/` 目录对、平台事件线程与主线程的接缝、外部函数接口（FFI）调用面；
- 独立演化方 → 核心层端口契约（`crates/gloss-core/src/contract/`）与各适配器实现；
- 既有接缝 → 平台中立共享层（`crates/gloss-platform/src/common/`）、闭包表与数据表实参、既有端口方法；
- 测试模块 → `#[cfg(test)]` 内联测试、`tests/` 目录与 `tests/stubs/` 替身库。

### 仓库默认值

- 信息不足一律 `retain`：重复便宜，错误抽象贵；
- 跨 `macos/` 与 `windows/` 目录对的克隆默认 `retain`：平台适配面统一会迫使抽象层泄漏平台概念，外部函数接口调用面不做消除（架构既定）；
- 测试脚手架克隆的消除方向是收进包内共享测试助手，不为它抽象生产代码；
- 第三次出现按三次规则倾向 `eliminate`；既有接缝已能表达差异时 `eliminate` 成本最低；
- 禁止改判罚脚本、基线或阈值来消红牌：规则改动先改规则再改代码，且是人的决策；禁止无缘由放行；验证清单未全绿不交付。

### 少样本案例

案例取自 2026-11-21 的存量判定（门禁线宽实测登记），每条给克隆对上下文、三问走法与结论；确定性预填建议只是起点，结论按三问内核得出。结论类别 `retain`（保留）、`eliminate`（消除）、`todo`（待消登记）沿用输出契约。

1. 跨包测试替身：结论 `retain`——部署单元边界压过测试样板方向。
   - 上下文：`gloss-core/tests/stubs/engine.rs` 与 `gloss-app/tests/stubs/engine.rs` 整文件 181 行逐字同体（脚本引擎桩）；预填只命中“测试模块——收包内共享测试助手”。
   - 三问走法：`Q1` 会同改（桩契约随引擎端口演进两侧同变，是知识重复）；`Q2` 两侧分属不同工作区分包（部署单元），共享桩库需引入测试专用公共依赖并建立发布耦合，判 `retain`。
   - 示例点：预填建议只给方向不定结论——测试样板方向被更高序的边界问题压过。

2. 平台测试样板：结论 `todo`——预填的“跨平台保留”被边界事实推翻。
   - 上下文：`crates/gloss-platform/src/macos/events/mod.rs` 与 `windows/events/mod.rs` 五段内联测试装配样板逐字同体（合计 146 行）；预填同时命中“跨平台目录对建议保留”与“测试模块——收共享助手”两个相抵建议。
   - 三问走法：`Q1` 会同改（事件线程消费契约两侧同变）；`Q2` 克隆段不触平台调用面——两侧调用的 `crate::event_thread::spawn` 接缝已抽象，平台差异（运行循环与消息泵实参）在接缝实参里、不在测试体里，不跨适配边界；`Q3` 既有接缝已能表达差异，判 `eliminate`。
   - 结论：`todo`（消除拉取请求 G3-P3，收进包内共享测试助手）。示例点：判定对象是“知识”不是“目录对”，路径跨 `macos` 与 `windows` 不等于知识跨平台。

3. 平台编排骨架：结论 `todo`——既有接缝是消除的最短路径。
   - 上下文：`crates/gloss-platform/src/macos/selection/clipboard.rs` 与 `windows/selection/clipboard.rs` 各 32 行的兜底读取编排，仅闭包表实参两行不同；预填命中“跨平台建议保留”。
   - 三问走法：`Q1` 会同改（兜底读取编排是同一知识）；`Q2` 同包内，克隆段不触系统调用面；`Q3` `common/fallback.rs` 的接缝（编排函数与闭包表）已存在，差异本就能用实参表达，判 `eliminate`。
   - 结论：`todo`（消除拉取请求 G3-P1，两侧只留平台闭包表实参）。示例点：消除对象是编排骨架，两侧的平台调用面本身保留不动——跨平台保留的判据不适用于已被接缝抽象包住的骨架。

4. 同文件测试走查前缀：结论 `retain`——第二次出现、需新建抽象。
   - 上下文：`crates/gloss-app/src/update/mod.rs` 两条测试共用 24 行“走到下载态”的状态走查前缀；同文件的全程走查已抽成既有接缝。
   - 三问走法：`Q1` 会同改（更新流程状态机演进两侧同变）；`Q2` 无边界；`Q3` 既有接缝走全程、表达不了“止于下载分叉点”，本对是第二次出现、合并需新建中途停止的走查抽象，按观察判 `retain`。
   - 示例点：三次规则数的是知识出现次数而非字面克隆数，既有接缝不能表达差异时不强抽。

5. 同文件渲染夹具：语义判 `eliminate`、登记节奏 `retain`——结论与立项分离。
   - 上下文：`crates/gloss-eval/src/view/mod.rs` 三个测试各自内联同一渲染夹具构造（17 行克隆），系第三次出现。
   - 三问走法：`Q1` 会同改（检视页夹具随报告结构演进同变）；`Q2` 无边界；`Q3` 第三次出现，三次规则命中，判 `eliminate`（抽取渲染夹具助手）。
   - 结论：语义判 `eliminate`，但未列入本期消除计划，基线按 `retain` 登记待后续窗口——`todo` 登记只留给方案已立项的消除对象。
