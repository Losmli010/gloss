# 重复判定提示词：三问通用内核与仓库覆盖层

本文件是克隆门禁判定辅助的提示词工件，物理上只存此一份：判定任务包（`just dup-triage` 的输出）在开头嵌入全文，代理据此对单个克隆对给出语义判定。通用内核不含项目信息，可移植；仓库覆盖层把内核的抽象词落到本仓库的部署与边界事实。判定权在人：代理产出的三选一结论与基线登记都经拉取请求评审确认。

## 三问通用内核（逐问短路执行）

```text
## 重复判定程序（通用内核，逐问短路执行）

Q1 变化轴（这是知识重复还是碰巧相似？）
   问：这两段代码会因同一个需求变更而同时修改吗？
   ├─ 会（同一知识点散落多处）        ⇒ 知识重复 → 继续 Q2
   └─ 不会（各自有不同的演化原因）    ⇒ 文本重复 → 判定：retain

Q2 边界（合并是否破坏部署或所有权边界？）
   问：克隆两侧是否隔着部署单元、平台/适配层或独立演化方？
   ├─ 跨部署单元（服务、前后端、独立发布物）⇒ 判定：retain
   │     （共享代码引入版本与发布耦合）
   ├─ 跨平台/适配边界（统一会迫使抽象层泄漏平台概念）⇒ 判定：retain
   └─ 同侧、同发布单元                ⇒ 继续 Q3

Q3 抽象成本（错误抽象比重复贵）
   问：合并之后，调用方与后续维护者会变难读吗？
   ├─ 参数化导致开关堆积、回调嵌套、条件爆炸 ⇒ 判定：retain
   ├─ 既有接缝已能表达差异（传参/闭包表/数据表已存在）⇒ 判定：eliminate（成本最低）
   ├─ 这是第 ≥3 次出现（Rule of Three）      ⇒ 判定：eliminate
   └─ 第 2 次出现、需要新建抽象              ⇒ 判定：retain（观察）

默认值：信息不足时一律 retain——重复便宜，错误抽象贵。
判定的对象是“知识”，不是“字符”：相似但变化轴不同的代码合并不了也不该合。

## 输出契约（三选一，全部带缘由）
eliminate：<建议抽壳位置，一句话>
retain：<缘由一句话，供基线登记>
exempt：<缘由一句话，供就地放行标记>
```

## 仓库覆盖层

### 词表映射

内核抽象词到本仓库事实的对应，判定时先按此表替换词面再走三问：

- 部署单元 → 工作区分包（`gloss-core`、`gloss-platform`、`gloss-app`、`gloss-llm`、`gloss-eval`）与应用发布物；
- 平台与适配边界 → `crates/gloss-platform/src/` 下 `macos/` 与 `windows/` 目录对、平台事件线程与主线程的接缝、外部函数接口（FFI）调用面；
- 独立演化方 → 核心层端口契约（`crates/gloss-core/src/contract/`）与各适配器实现；
- 既有接缝 → 平台中立共享层（`crates/gloss-platform/src/common/`）、闭包表与数据表实参、既有端口方法；
- 测试模块 → `#[cfg(test)]` 内联测试、`tests/` 目录与 `tests/stubs/` 替身库。

### 仓库默认值

- 信息不足一律 `retain`：重复便宜，错误抽象贵；
- 跨 `macos/` 与 `windows/` 目录对的克隆默认 `retain`：平台适配面统一会迫使抽象层泄漏平台概念，外部函数接口调用面不做消除（架构既定）；
- 测试脚手架克隆的消除方向是收进包内共享测试助手，不为它抽象生产代码；
- 第三次出现按三次规则倾向 `eliminate`；既有接缝已能表达差异时 `eliminate` 成本最低；
- 禁止改判罚脚本、基线或阈值来消红牌：规则改动先改规则再改代码，且是人的决策；禁止无缘由放行；验证清单未全绿不交付。
