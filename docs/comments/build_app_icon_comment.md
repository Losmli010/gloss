## 工具选型

- 2026-09-18 只用系统自带的 sips（SVG→PNG、缩放）与 iconutil（iconset→.icns），零新增工具链：sips 自 macOS 13 起经 ImageIO 支持 SVG 输入，输出保留 alpha。

## 1024×1024 守卫

- 2026-09-18 光栅化尺寸取决于 SVG 声明的 width/height 属性：丢了它 sips 会按内嵌尺寸出小图，下面的档位会把小图上采样成模糊图标静默进仓库，这里当场拦下。

## Dock 图标尺寸

- 2026-09-18 256px 的原因：Retina Dock 上限 128pt@2x = 256px，再大只是增大二进制体积。

## web 站点图标（2026-10-07）

- 补 PNG favicon 的缘由：站点此前只声明 SVG favicon，Safari 不支持（站点受众是
  Mac 用户），标签页一直显示默认图标——用户观感即“站点图标没换”。新增
  `web/assets/favicon.png`（32px）与 `apple-touch-icon.png`（180px）兜底，SVG
  favicon 保留给支持的浏览器。
- web 两张 PNG 源选 `gloss-logo.svg`（满幅稿）而非 `gloss-app-icon.svg`：规范画布
  版四周留 100px 透明边距，缩到 32px 时图形占比过小、标签页里不可辨。
- 纳入本脚本而非一次性手工产出：换装 #100 时站点资产靠手工跟进，这次“图标没换”
  即由此而来；进 `just icons` 后换 Logo/调色重跑一次即全量覆盖，不再依赖记性。
- `web/assets/logo.svg` 拷贝不做程序化同步：沿用 assets/icons/README.md 的手工
  同步约定，避免脚本覆盖站点侧对主标的独立调整；本次只把新增 PNG 收编进脚本。
- 1024 守卫抽成 `raster1024` 供两处矢量源共用：web PNG 同样由 1024 主图降采样，
  小图上采样成模糊图标的风险与 .icns 链完全相同。

## 图标集（Windows）产出（2026-11-07，Windows 移植 P3a）

- 新增 `Gloss.ico`：与打包图标同一 1024 主图降采样七档（16/24/32/48/64/128/256），消费面是系统可执行文件资源与后置安装器（NSIS 落地时的图标来源）；产物进仓库与 `.icns` 同规，持续集成不重建。
- 容器（ICO）组装用纯标准库（`struct` 打目录头加档位项）而不是引入 Pillow 一类依赖：容器只是固定布局的拼装，位图数据保留 PNG 编码（系统（Windows）Vista 起的图标资源接受 PNG 档位），维持本脚本“零额外工具链”的口径。
- 组装后回读自检（`verify_ico`）：目录计数、档位、平面数与位深、偏移推进、每档位编码形态逐一核对，写坏当场失败——坏图标静默进仓库要到装机才可见，自检把失败拦在生成点。

## 小档位改传统位图（BMP）编码（2026-11-07，移植评审遗留 E5）

- 为什么不能全档位 PNG：非 256 的 PNG 小档位在系统（Windows）图标资源里的
  渲染兼容性未经验证（Vista 起官方支持的是 256 档 PNG，小档 PNG 各壳层视图
  的行为无文档背书），而容器（ICO）的传统位图（BMP）形态（四十字节信息头、
  自底向上像素加全零掩码）是全版本接受面。
- 处置：小档位（不超过 48 的各档：16/24/32/48）转传统位图（BMP）编码，大
  档位（64/128/256）保留 PNG 压缩。像素来源仍是图像转换工具（sips）——把
  单档位（PNG）转成位图（BMP）文件，纯标准库解析（`ico_bmp_payload`）：五
  版信息头核对几何与通道掩码（只认标准蓝绿红阿尔法，顶行序翻成自底向上，
  补全零掩码；写出别的通道面或缺阿尔法当场报错），不引入解码依赖。
- 回读自检扩展到两种形态（`bmp_entry_shape_ok`）：位图（BMP）档核对四十字
  节头、双高声明、无压缩与像素加掩码占满载荷；PNG 档署名核对不变。单测
  （`build_app_icon_test.py`）钉：顶行序与底行序输入的行序、掩码异常与截断
  与无阿尔法拒绝、容器回读双形态往返。
- 消费面落地时机：exe 资源内嵌随安装器里程碑才接入（当前产物已入库，本次
  改写即生效于下次重建）。
