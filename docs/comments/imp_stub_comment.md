## 占位与死码放行（2026-11-05，Windows 移植 P0）

- 非 macOS 目标下发现器恒无发现（`load_cjk`/`load_family` 返回空），命名字体族由父模块既有降级兜底到内置字形；Windows 的 DirectWrite 枚举加固定候选探测（§2）随 P2 ② 落地。
- 模块级 `#![allow(dead_code)]` 的缘由：家族字体（FamilyFont）与字节背衬（FontBacking）在此同名镜像、只被登记流程以类型引用，桩内无构造方——镜像是为了父模块流程零改动编译；`tests/stubs` 目录同款口径。P2 换真实现时本放行随桩一起删除。
- 与 macOS 实现的分工差异：字节背衬类型从父模块迁入各平台发现器（macOS 侧随 `imp.rs` 持有）——背衬形态（mmap/拷贝）是实现细节，父模块只依赖 `as_slice` 读面。
