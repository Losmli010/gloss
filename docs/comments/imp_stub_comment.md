## 占位与死码放行（2026-11-05，Windows 移植 P0；2026-11-06，P2② 起范围收敛；2026-11-17，方案 D4 镜像解散）

- 非 macOS、非 Windows 目标下发现器恒无发现（`load_cjk`/`load_family` 返回空），
  命名字体族由父模块既有降级兜底到内置字形；系统（Windows）的真实发现器
  （DirectWrite 枚举加固定候选探测，§2）已于 P2 ② 落地为 imp_win.rs，桩退为
  其余目标（Linux 占位等）服务。
- 模块级 `#![allow(dead_code)]` 的缘由（已随镜像退场）：家族字体（FamilyFont）
  与字节背衬（FontBacking）曾在同名镜像、只被登记流程以类型引用，桩内无构造
  方——镜像是为了父模块流程零改动编译。2026-11-17 随方案 D4 类型面上提共享
  背衬模块（backing.rs，见 backing 记录），桩只剩有调用方的无发现入口，放行
  标记一并删除。
- 与两侧真实发现器的分工：类型面住共享背衬模块（backing.rs），桩只交回
  “无发现”——背衬形态（mmap/拷贝）是实现细节，父模块只依赖 `as_slice` 读面。
