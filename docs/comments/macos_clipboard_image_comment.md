## 上移沿革（2026-11-14，方案 A4 P2）

- 共享管线（预算判定、降采样、PNG 编码与“竞态→交付不出→解码”三路）
  上移平台中立共享层只写一份；本模块收窄为绑定面：计数读数原语（粘贴板
  变更计数）、交付原语（按类型取数据风格）与格式映射（标记图像格式
  （TIFF）/便携式网络图形（PNG）→ 解码格式），观察记录句柄与端口实现
  引用面（`SystemImageReader::new`、`ClipboardImageReader::read`）零变化。
- 格式映射是纯查表（风格 → 解码格式）；数据经粘贴板数据的借用视图直通
  解码（不安全块的不变量见代码内 SAFETY 注释：借用被交付风格钉在取数
  原语的返回值上、由共享管线在同一轮读取内消费，不越出粘贴板数据的
  存活期）——迁移前后分配次数零变化，热路径零拷贝保持。
- 交付不出路径的系统（macOS）成因：15 及以上版本“允许粘贴”授权被拒时
  内容读取返回空，与“板上已无图像”同形——共享层按交付不出 warn 留痕、
  静默丢弃（取舍见共享层记录“为什么授权拒绝落静默丢弃而不是失败卡”）；
  共享层日志文案统一后不再点名授权成因，本模块头承载该成因指引。

## ClipboardImageReader 端口实现（2026-10-10，方案 §5.3；2026-10-10 评审修订）

- **为什么直读 NSPasteboard 的 flavor 数据而不是 arboard 的 `get_image`**
  （评审 HIGH 修订，推翻初版）：
  1. arboard 3.6.1 的 macOS 读图只请求 `public.tiff` 一种 flavor，PNG-only
     剪贴板（浏览器/文件复制常写 public.png）取材必失败且报
     `ContentNotAvailable`——若按竞态静默丢弃，用户“复制了图却毫无反应”
     且日志伪装成竞态，不可排查。方案 §5.3“arboard get_image() 得
     RGBA+尺寸”的前提（读图支持 TIFF/PNG）经源码核实不成立。
  2. arboard 的读图对解码无任何尺寸/字节设界——`get_image` 内部先整图
     解码再返回，像素面积上限只能判在分配之后，pastebomb 的最大一次内存
     分配（RGBA 位图，尺寸来自剪贴板内声明值）不受 `MAX_PIXELS` 约束。
  3. 直读 flavor（`dataForType:`，TIFF 先 PNG 后）让“哨兵认什么、取材读
     什么”在同一处对齐（两份候选表共用 `NSPasteboardTypeTIFF/PNG`），
     设界可以逐级前置。读内容触发 macOS 15+“允许粘贴”授权的时点不变
     （`dataForType:` 同样是内容读取）。设界的执行面现住共享层记录。
- **为什么竞态判定同时认两路（变更计数不匹配 / 无可读图像 flavor）**：
  ①与②之间剪贴板被覆盖有两种可观察形态——被换成别的内容（变更计数
  前进）或被清空/换成非图像内容（`dataForType:` 对两种 flavor 都返回
  nil）。前者由共享层按竞态丢弃；后者在内容确实还是图像时是交付不出
  （共享层 warn 丢弃）、在授权被拒时同形——两路都不弹失败卡打扰用户，
  与划词空选区误滑同型处置。只有“哨兵记录在、内容确实是可读图像、
  解码/编码环节真故障”才 `Err` 上抛 `TaskFailed`。
- **为什么映射候选表按 TIFF 先 PNG 后**：与哨兵的类型判定候选表共用
  优先序（见剪贴板模块记录）；截图工具普遍写 TIFF，浏览器与多数现代
  应用写 PNG，两表同序保证“哨兵认什么、取材读什么”对齐。

## 符号契约

- `map_pasteboard_flavor`：交付风格的系统（macOS）映射：粘贴板图像数据
  （标记图像格式（TIFF）或便携式网络图形（PNG）字节）→ 解码格式与载荷
  借用视图；交付字节长度取数据字节数（预算判交付口径）。不可失败——
  系统粘贴板数据是完整编码流，格式合法性由共享管线判。
- `ClipboardImageReader::read`：端口实现：把粘贴板变更计数与交付原语
  喂进共享一轮读取（三条分岔的行为契约见共享层记录）。
