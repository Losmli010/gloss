## 组合存储桩（2026-11-05，Windows 移植 P0）→ 已由真实实现替换（2026-11-10）

- 原 P0 桩口径：构造可用、逐操作失败，文档半边与密钥半边按移植方案后续阶段补齐——本条留档沿革，最新口径见下节。

## 组合存储落地（2026-11-10，Windows 移植 P3b 后续）→ 文档半边与组合体上移共享层（2026-11-14，架构重构 A3）

- 原 P3b 落地口径：与系统（macOS）组合存储同名镜像，文档半边（file，TOML 文件）加密钥半边（cred，凭据管理器）本文件与镜像文件各持一份——该镜像随 A3 去重：文档半边与组合体上移平台中立共享层（`common::storage`，决策与沿革见 storage 记录），镜像文件（file）整体退役。
- 最新口径：本文件收窄为系统（Windows）的密钥半边绑定——密钥端口 `SecretStore` 的出厂实现落在 [`cred::CredentialSecret`] 上：`secret`/`set_secret`/`delete_secret` 转发固有方法；出厂组合存储以类型别名落位（共享层的组合体接上凭据管理器密钥半边），`new` 经共享层的 `with_secrets` 装配，组装点（bootstrap）引用面不随迁移变化。
- 密钥半边在组合体内只取一份实例：文档与密钥经同一组合体注入（入口的 config_store 与 secret_store 同源），设置页与任务链路共享密钥缓存。
