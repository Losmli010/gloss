# ui/popup/mod.rs 决策记录

## `RenderState::attached`（经位附件图像的纹理缓存）

- 缓存键取源字节 `Arc` 的指针身份而非内容哈希：图像字节属敏感数据，
  哈希虽不外泄但为一帧内重复计算付成本；指针比较零成本且语义恰好——
  状态机对同一会话恒持同一 `Arc`（commit 时零拷贝留存），跨帧与重试
  自然命中，新任务（新分配）自然失配。解码失败也按 `None` 与字节绑定
  缓存：坏字节逐帧重解码是热路径浪费，换图（新指针）即重试。
- 同时至多驻留一份图像纹理：新图替换旧图。初版在「hide 边界不清纹理、
  有界驻留到下一图替换」与「会话结束即清」之间取了前者；评审定 LOW
  但指出敏感内容生命周期长于会话与本仓红线取向相悖，改为**无附件帧即
  清槽**（`draw` 入口判断 `attached.is_none()`，见 `RenderState::drop_attached`）
  ——收起、换任务、失败卡三个出口都表现为无附件帧，源字节 `Arc` 与解
  码纹理同帧释放；同图再上卡多付一次解码，会话内不发生。清槽成本是
  无附件帧上一次 `RefCell` 写（ns 级），热路径无感。
- 备选落选：把纹理挂进 `OverlayView` 变体——违反「不改 OverlayView 变
  体形状」的前置决策（§5.6）；把 `Arc<[u8]>` 直接塞进视图逐帧解码——
  违反「绝不逐帧解码」。

## `draw` / `render_content` 的 `attached` 参数

- 附件图像经参数随行而不进 `OverlayView`：图像字节是会话态（机器留存），
  视图是纯展示形态；参数随行使文本路径零改动（既有八份基线零漂移的
  前提）。`render_frame` 同步加参，自检 handler 与 bench 传 `None`。

## 图像卡的滚动位置（流式分支）

- 图像卡的经位图像随注/疏一起进 ScrollArea（滚动区吞高，超屏图滚动
  兜底）；文本卡的经位原文同样在滚动区内（2026-10-18 修正，见「长选区的
  经位并入滚动区」——原「文本经位留在滚动区外」的取舍在长选区下把页脚
  顶出窗外，已废弃）。
- 流式分支按 `attached` 二分而非在闭包里 if：图像卡与文本卡的经位内容
  类型不同（图像 vs 代码/原文），分段的闭包各自直读所需字段，不必在单
  闭包里判分支。

## 长选区的经位并入滚动区（2026-10-18）

- 现象：选中内容较长时，文本流式卡的经位原文留在滚动区外，自身无界高度
  把滚动区与页脚一路顶到窗外——窗口高度被壳钳到屏高的一半
  （`windows.rs` 的 `capped_height`），页脚「正在注解」因此不可见，用户
  看不到生成指示；经位原文本身也读不到尾部（没有滚动入口）。
- 处置：经位与注/疏同进一个滚动区（与产物卡、图像流式卡同形），页脚钉在
  滚动区下缘之外。原取舍的表面理由是「保 popup_streaming /
  popup_code_streaming 两份基线零漂移、`viewport_max` 在经位之后计」，
  但它把「页面结构不对称」换成了功能缺陷；修正后两份基线的差异只是经位
  整体的亚像素抗锯齿差（已逐像素确认后 `UPDATE_SNAPSHOTS=1` 重录）。
- 顺带收益：流式卡与完成态卡的正文滚动范围一致，TaskDone 定型时经位不再
  从固定区跳进滚动区。

## `outcome_body` 的 ImageCommentary 经位

- 经位三级回落：附件在场 → 图像本身；附件缺席但 source 非空 → 原文
  经位（缓存命中等会话边缘的兜底）；两者皆无 → 占位行。设计只要求
  「无图可渲染时优雅降级占位」，原文回落是顺手的健壮性——图像任务的
  source 恒空（机器侧测试锁定），正常运行不可达。
- 布局开关取 `attached.is_some()` 而非 classified/kind：与设计 §5.6
  一致，不依赖分类到达时序。

## `image_unavailable` 占位

- 占位走 i18n 新键 `gloss_popup_image_unavailable` 而非留白：经印章在
  而正文空白读作渲染事故；一行弱色楷体占位交代「图没能显示」。解码
  失败告警只含 `len`（红线：内容与字节不落日志）。

## 浮层宽度固定 480、删除宽度上限（2026-10-19）

- 原实现按内容高在 380/480 两档间滞回加宽（`sizing.rs`）：长文本先按窄档
  排版、越过阈值再整段跳宽，折行位置在阅读中突变；产品定稿改为固定
  480px，`sizing.rs` 整模块删除——宽度不再参与内容决策，`RenderState`
  的 `last_width` 滞回状态随之移除。
- 疏字号 13→14 同步定稿。疏与此前共用 13 号的两个位置（注区 markdown 的
  Small 样式、经位图像占位）解耦成 `SMALL_FONT`：疏正文调号不牵动它们。

## 经位图像的宽度策略

- `Image::max_width(available)` 只缩不放大：小图（复制的表情、小图标）
  按自然尺寸左对齐，避免放大糊图；「宽=卡宽等比缩放」的约束面是
  「不得超出卡宽」，等比由 egui 单维度约束天然保证。不设独立高度上限：
  高图由滚动区吞高、窗口按完整内容高申请、壳侧钳到屏，与正文同规。

## footer 的修复轮文案（2026-10-12，契约校验与重试方案 §6）

- 为什么 footer 加 `repairing` 参数而不是让调用方选词条：流式视图是唯一知道 repairing 状态的地方，但选词逻辑（含无障碍标签 `widget_info` 与 painter 落字两处）都在 footer 内部——参数进一层、选词一处，避免两个落点各判一遍漂移。
- 修复中的流式卡正文恒为空（`accept_repairing` 与清稿同帧）：L2 夹具按真实时序构造（raw 空 + repairing true），骨架条顶注位、只换页脚词——不加横幅不加计数是方案定稿。

## 印章/水印 galley 槽位缓存（本地门禁第 2 轮，2026-10-13）

- epaint 对布局结果本身有记忆化，但每次 `layout_no_wrap` 查询都要先构造
  `LayoutJob`（文本拷贝 + sections Vec，约 2 次分配）再算哈希——词卡帧上
  三枚印章加一处水印每帧白付 8 次分配。改为按槽位
  （`'static` 标签 + 墨色档/明暗 + `pixels_per_point` 位型）缓存
  `Arc<Galley>`，挂在 egui `Memory::caches`（`cache::CacheTrait`，egui 逐
  帧驱动其逐出钩子，这里键空间有界、恒不逐出）。稳态帧零分配，galley
  不可变故跨帧复用渲染逐像素一致（L2 快照守卫）；明暗、语言（标签内容
  入键）、DPI 变化自然换键重排。
- **锁次序坑**：`Context::fonts_mut` 与 `Context::memory_mut` 抢同一把
  Context 写锁——缓存未命中时 `layout` 闭包绝不能在 `memory_mut` 闭包内
  执行（epaint RwLock 非重入，debug 构建直接报死锁）。实现为先查后排、
  分两次拿锁；UI 单线程，无竞态。
- `seal` 的标签参数因此从 `&str` 收紧为 `&'static str`，`popup::draw` 及
  其内部链的 `text` 参数相应从 `&Text` 收紧为 `&'static Text`——全部调用
  方（壳、bench、测试 harness）本就传 `Text::get` 的 `'static` 引用。

## 字体换表失效 + 水印注释口径修正（评审第 1 轮，2026-10-13）

- **HIGH 修复**：槽位键不含字体表，而字体表启动期整体更换一次（内置快
  路径 → `FontsReady` 后台装载完整表）；旧 galley 若在装载窗口内入缓存
  会以内置字形滞留（CJK 印章成 tofu、量宽冻结）。失效点收在
  `ui::context` 的统一装入点：`install` / `install_fonts` /
  `install_kittest_fonts` 在 `set_fonts` 后调
  `popup::clear_cached_text_galleys(ctx)` 整体清空（egui 自身的 galley
  缓存随 Fonts 重建自然失效，本缓存挂 Memory 需显式清）。首装路径空表
  清空是空操作。
- **注释口径**：水印「逐像素相同」的机制断言撤回——新闭包经
  `WidgetText::into_galley`，job 的 halign/justify 是默认值（LEFT/不两
  端），与旧 Label 内部写 RIGHT 不一致；净落点由 `ui.put` 居中 + 槽宽
  （=galley 宽 + 对称余量）决定，差异至多余量级内缩，渲染一致性由 L2
  快照守卫而非此处机制保证。注释已改为如实表述。

## 符号注记（迁自代码内注释）

- `WIDTH`：浮层宽度（逻辑点）——窗口创建与每帧期望尺寸共用此值，不随内容
  变化。
- `HEADER_ICON`：页头应用图标的边长（栅格化与页头行布局共用）。
- `FOOTER_HEIGHT`：页脚带高——水印字形（`font::TAG` 11px）加合理上下余量
  的下限档。
- `PULSE_PERIOD_SECS`：骨架条与页脚呼吸点的脉动周期（秒）。
- `APPEAR_SECONDS`：出现动画时长（淡入，秒）——显示/重显后的第一帧从 0
  渐进到 1。
- `RenderCtx`：一帧内容分发的共享绘制输入——状态、文案表与本帧经位附件
  三件套随视图函数整组同行，捆一个结构免得逐函数穿参。
- `RenderState`：浮层的跨帧渲染状态（每窗口一份，由渲染管线持有）。
  - `cache`：markdown 渲染状态（egui_commonmark 要求跨帧持有）。
  - `drag_press_phys`：页头拖动的按压点（**物理像素**，按压帧的窗口内
    逻辑坐标乘当下 `pixels_per_point`）——拖动开始帧记录，结束即清。
    存物理口径是为跨 DPI 显示器的拖动：逻辑坐标随新显示器的缩放比例
    重标定，逻辑按压点会混尺；物理位移按当下比例还原成当下尺度的逻辑
    位移，与壳侧落点换算（`apply_overlay_drag`）同口径。清零后 egui 侧
    若仍有残留拖动所有权（见 `card::drag_strip`），热区保持惰性。
  - `icon`：页头应用图标的纹理缓存——键是栅格化边长（物理像素）。None＝
    尚未栅格化；内层 `None`＝该边长下渲染失败（同样只试一次，占位降级）。
    换显示器（`pixels_per_point` 变化）即按新密度重栅。
  - `attached`：经位附件图像的跨帧纹理缓存槽（见 `AttachedTexture`）。
  - `copied_at`：复制反馈的起点（居内时间，`Cell<Option<f64>>`）——复制
    钮点击时由页脚写入，`motion::COPY_FEEDBACK` 内页脚翻「已复制」反馈
    （见 footer 记录）；跨帧渲染态住 `RenderState` 与纹理缓存同一去处，
    视图每帧重建放不下它。
  - `copied_source`：反馈所属完成卡的原文（`Cell<Option<String>>`）——
    `draw` 每帧以它对照当前卡：卡已换（缓存命中快速换卡）即清反馈，避免
    「没点过复制却显示已复制」；原文相同即视为同一张卡（重试同源卡在
    反馈窗内换卡的唯一通路是缓存命中，而降级卡不进缓存——该残余面如实
    接受）。非完成态帧清空两者。
- `AttachedTexture`：经位附件图像的纹理缓存——键是源字节的 `Arc` 指针
  身份：同图跨帧与重试恒复用同一纹理，绝不逐帧解码；纹理 `None`＝这份
  字节解码失败（同样只试一次，占位降级），换图（指针不同）即重新解码。
  同时至多驻留一份图像纹理（新图即替换；会话离开图像卡即清空，见
  `RenderState::drop_attached`）。
- `RenderState::reset_drag_state`：清除页头拖动的按压点——壳在收起/显示
  浮层的边界调用（见 `app::overlay`）。跨显示残留的拖动状态由此失效：
  egui 的拖动所有权可能因隐藏期丢失的鼠标释放而残留（按压点已清，热区
  保持惰性）；残留所有权要到下一次释放事件才清零，其间的第一次按压
  拖动不产生 `drag_started`（所有权无 None→Some 迁移），整段惰性，
  松开即自愈——之后（所有权已清）的按压才重新握点。
- `RenderState::icon_texture`：页头应用图标纹理——矢量源按当前
  `pixels_per_point` 栅格化到物理像素级（纹理纹元 1:1 对应设备像素，
  图标锐利），装完跨帧复用；密度变化（跨显示器拖动）按新边长重栅，
  失败按边长缓存不重试。TextureHandle 内部是 Arc：克隆只递引用计数
  （零堆分配），缓存槽与当帧绘制各持一枚，勿改成逐帧重装纹理。
- `RenderState::attached_texture`：经位附件图像的纹理——首次见到这份字节
  时解码并装入当前上下文，之后跨帧复用（解码失败按 `None` 缓存，同字节
  不重试；换字节即重解码）。
- `RenderState::drop_attached`：清空经位附件图像的缓存槽——源字节 `Arc`
  与解码纹理一并释放。壳在无附件的帧调用（图像会话已被收起/替换/失败）
  ——图像字节属敏感数据，生命周期不得长于会话；同图下一帧重新解码即回
  （一次解码，不在会话内重复发生）。
- `PopupOutput`：一帧浮层绘制的产物——动作上交 + 内容期望的窗口尺寸
  （逻辑点）。`action`：本帧上交壳执行的动作，`None`＝无动作；
  `sizing`：本帧内容期望的浮层尺寸（壳据此调整窗口）；`drag`：页头拖动
  热区的状态——`Some(offset)`＝拖动进行中，offset 是指针自按压点起的
  **累计**位移（窗口内相对坐标，逻辑点；按下帧为零），`None`＝本帧不在
  拖动。壳以它换算窗口落点（见 `WindowManager::apply_overlay_drag`）。
- `OverlayAction`：浮层上交壳执行的动作——失败卡动作（重试/打开设置）、
  页脚动作区（确认/复制）与头部动作区（齿轮=打开设置、×=收起）。浮层只
  渲染、不副作用。
  `Retry`：失败卡「重试」，同代数同任务重发通道③；`OpenSettings`：设置
  入口（失败卡按钮或头部齿轮），走壳层统一 `open_settings`；`Dismiss`：
  头部「×」与待确认卡「取消」，收起浮层（壳层放弃在途任务回 Idle；待
  确认阶段无在途推理，收起零通道流量）；`Confirm`：待确认卡「注疏」
  主按钮，壳经 `confirm_pending` 组装下发请求后 send_run（2026-10-27，
  发送前确认方案）；`CopyAnnotation`：完成态卡「复制注疏」，壳取
  `annotation_text` 写剪贴板（2026-10-27）。
- `OverlaySizing`：本帧期望的浮层高（逻辑点，含内边距与框线）——宽度恒为
  `WIDTH`、不随内容变化（窗口创建与每帧期望宽同源此常量，不经此结构
  传递），只有高度随内容。`height`：期望窗口高度（完整内容高，壳侧按
  显示器钳制）。
- `appear_t0_id`：出现动画起点在 egui memory 里的键。
- `appear_progress`：淡入进度——给定居内已流逝秒数，返回 0..=1 的不透明度。
- `appear_fade_in`：出现淡入——起点在每次显示（壳侧清除后）的首帧重新
  写入；进度未满时请求短重绘推进动画。kittest 的 animation_time=0 与
  固定步进让快照恒为完成态，不受动画影响。进度未满时请求尽快再来一帧
  推进淡入（生产中被预测帧时长扣减后接近立即重绘，由呈现管道钳到
  vsync 帧率）。
- `reset_appear_animation`：清除出现动画起点——壳在每次显示时调用，让
  下一帧重新从 0 淡入（隐藏期无帧运行，起点留在居内无副作用；不清除则
  旧起点让重显直接落在完成态）。
- `draw`：画一帧浮层。根 `Ui` 覆盖整个窗口，卡片铺满它，圆角之外由透明
  窗口露出桌面。`view` 为 `None` 时显示渲染自检卡（预热与自检路径）。
  `attached` 是本会话经位附件图像（图像任务的原文，状态机留存，经访问器
  随行——不进 `OverlayView` 变体形状），仅图像卡渲染它。返回本帧绘制的
  产物——失败卡动作与头部动作区（齿轮/×）上交壳执行——浮层只渲染、不
  副作用；期望尺寸由壳经窗口管理器应用（内容自适应高度，超出屏幕滚动
  兜底）。划选即复制路径：全部文本可选中（含跨 widget 连选）。本帧无
  附件＝会话已离开图像卡（收起、换任务或失败）：立即清空纹理缓存槽——
  图像字节属敏感数据，源字节与解码纹理都不得驻留到会话之外（机器侧清
  attached_image 的渲染侧镜像，见 `RenderState::drop_attached`）。宽度
  固定不随内容变化；高度取完整内容高（超出屏幕由壳侧钳制、滚动兜底）。
