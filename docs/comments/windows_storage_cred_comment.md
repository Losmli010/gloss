## 密钥半边落地（2026-11-10，Windows 移植 P3b 后续）

- 凭据目标名为“服务名/键串”，与系统（macOS）钥匙串的“服务加账户”同构；载荷按通用凭据原始字节存取，UTF-8 解码失败按损坏凭据报错，不回空表值。
- 带进程内读取缓存（读未命中才访问凭据管理器，写删同步更新缓存）：任务链路每次执行都要取一次密钥，缓存把系统调用收敛到每进程每键一次；设置页改密钥经同一实例写入缓存即时生效，无需重启。
- 不设读入门禁（与钥匙串半边的差异）：凭据管理器不按访问方签名设访问控制，读取无弹窗，串行化首读无收益；并发首读各自撞一次幂等系统调用，缓存以先落者为准。
- 测试直面真实凭据管理器（键串带 `.test` 限定，收场即删）：写入无需提权、无授权弹窗。隔离纪律与系统（macOS）钥匙串半边同规——真实写入路径（往返）标 `#[ignore]` 进人工测试清单（评审定案：非忽略测试不写真实凭据库，断言中途失败会残留测试条目），只读与删缺失条目的四条照常进 CI。
- 密钥半边派生调试形（`Debug`）：缓存中的密钥值可经 `{:?}` 带出，当前代码无此调用点、密钥红线只靠约定守护——脱敏 `Debug` 待与系统（macOS）钥匙串半边同改（两侧镜像，单独重构）。
