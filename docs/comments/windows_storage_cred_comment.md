## 密钥半边落地（2026-11-10，Windows 移植 P3b 后续）

- 凭据目标名为“服务名/键串”，与系统（macOS）钥匙串的“服务加账户”同构；载荷按通用凭据原始字节存取，UTF-8 解码失败按损坏凭据报错，不回空表值。
- 带进程内读取缓存（读未命中才访问凭据管理器，写删同步更新缓存）：任务链路每次执行都要取一次密钥，缓存把系统调用收敛到每进程每键一次；设置页改密钥经同一实例写入缓存即时生效，无需重启。
- 不设读入门禁（与钥匙串半边的差异）：凭据管理器不按访问方签名设访问控制，读取无弹窗，串行化首读无收益；并发首读各自撞一次幂等系统调用，缓存以先落者为准。
- 测试直面真实凭据管理器（键串带 `.test` 限定，收场即删）：写入无需提权、无授权弹窗。隔离纪律与系统（macOS）钥匙串半边同规——真实写入路径（往返）标 `#[ignore]` 进人工测试清单（评审定案：非忽略测试不写真实凭据库，断言中途失败会残留测试条目），只读与删缺失条目的四条照常进 CI。
- 密钥半边派生调试形（`Debug`）：缓存中的密钥值可经 `{:?}` 带出，当前代码无此调用点、密钥红线只靠约定守护——脱敏 `Debug` 待与系统（macOS）钥匙串半边同改（两侧镜像，单独重构）。

## 读写删编排上移（2026-11-21，代码克隆治理 G3-P2）

- 进程内读取缓存、读写删编排、缺条目读空与错误降级自本模块上移平台中立共享层的密钥骨架（common::secret，取舍见 secret 记录）：生产侧编排两侧同构、测试骨架两侧逐字同体，合并后本模块只留凭据调用面与并发首读测试。缺条目读空（`ERROR_NOT_FOUND` 回空）留在凭据调用面模块（`ffi::cred`），UTF-8 解码留在本模块底层读实现——两者都是凭据系统语义；删后的缓存置空由骨架统一做。
- 缓存本体与回填编排上移后，“缓存以先落者为准”的并发语义随骨架单源（落定助手 `SecretCache::settle`）；本模块底层读无闸门，读后直调落定助手——与钥匙串侧的差异只在同步需要（其落定在闸门临界区内，见 secret 记录的“未命中回填入闸门”）。不设读入门禁的差异化决策不变——闸门不入共享骨架，钥匙串侧自持（凭据读取无弹窗，串行化无收益）。
- 缺条目读空、删除缺条目幂等与缓存读写一致三条测试随骨架合并到共享层（替身底层件承载，见 secret 测试记录）；本模块调用面的缺条目读空路径由并发首读测试继续覆盖——全新实例直逼未命中路径，真实凭据库回空。真实写入路径（往返）的 `#[ignore]` 纪律不变。
