## 组合通道（2026-11-06，Windows 移植 P2①，替换同日 P0 桩）

- 主路加兜底两级：用户界面自动化（UIA）文本模式优先，读不到落剪贴板兜底
  （模拟复制）。与系统（macOS）组合通道的差异：没有宿主激活闸门——系统
  （Windows）没有“树未激活”的唤醒常客问题（Chromium 系的无障碍树默认建
  树），文本模式缺席时等再久也读不到，注入才是解法；也没有权限缺失分支
  （系统（Windows）无授权门）。
- 让渡补读照搬系统（macOS）的节奏：空选区按几何节奏（二十五、七十五、
  一百五十毫秒）补读，睡眠段共享一份墙钟预算（七百毫秒，自进入读取起算）
  ——释放瞬间读到的空多半是还没写好，预算把无响应宿主上的等待钉死。
- 归一化边界与系统（macOS）一致：两通道产物在入口修剪两端空白，判空用
  修剪后的值，纯空白按空选区语义上抛；产物与收尾分离（恢复不挡在弹窗前）。
- 2026-11-06（P1 合入后适配）实现核心层文本取材端口（契约类型 `TextRead`
  ／`TextSettle`，收尾结构经 `TextSettle::deferred` 包裹移交调用方），
  本模块原先镜像的 `SelectionRead`／`SelectionSettle` 退役——端口是共享
  契约，镜像类型不再有位。
