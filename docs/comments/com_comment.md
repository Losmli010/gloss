## ComApartment（2026-11-06，Windows 移植 P2①）

- 组件对象模型（COM）单线程套间（STA）的初始化守卫：用户界面自动化（UIA）
  要求套间是单线程套间且调用线程固定（移植方案 §6），初始化放进平台事件
  线程的启动序（`init_sta`），守卫存活到泵退出时 Drop——按序 `CoUninitialize`
  与成功配对，初始化失败（`RPC_E_CHANGED_MODE` 等）只关掉 UIA 这一路：
  事件线程照常起，选区主路按读取不可用降级兜底。
- 返回 `Option` 而非 `Result`：失败语义是“该通道不可用”而非“启动失败”，
  调用方（事件线程）不因此退出。
- `create_automation`：进程内创建系统自动化对象；句柄只在事件线程创建与
  使用，跨线程传递不在契约内。

## drop

- 只在 `owns_init`（本次调用真正初始化成功）时卸载：已初始化的宿主套间
  （理论上不会出现，防御面）卸载会把别人的引用计数减掉。

## 线程固定由类型承载（2026-11-07，移植评审遗留 B8）

- 为什么守卫要 !Send：单线程套间的卸载规约（`CoUninitialize`）要求与
  初始化发生在同一线程，守卫可跨线程移动意味着 Drop 可能在错误线程卸载。
  处置为字段加哨兵类型（`PhantomData<*mut ()>`）包住裸指针——裸指针不实现
  `Send`，整个守卫随之 !Send，跨线程移动在编译期被拒；当前调用面
  （事件线程 `run_loop` 局部持有）不受影响，守卫在线程内建立、线程内
  Drop 的不变量由类型承载而非靠约定。这是编译期类型门（与密钥来源唯一
  同一口径），不是运行时检查。
