## 总览生成与校验单源（2026-11-14，方案 F1）

- 登记清单按包落位后，根 `bdd.md` 的总览节是唯一的跨文件视图，定为生成产物：本模块既是 `just test-index` 配方的再生成入口，也被行为清单门禁（`check_test_bdd`）导入做新鲜度比对，渲染与计数只有一份实现，生成与校验不可能漂移。
- 计数口径全机械：表格计登记行（表头与分隔行除外），非路径形态的三级小节标题计条目（人工两类按小节计）；逐源文件小节标题是路径形态（剥限定符尾巴与反引号后含分隔符），不是条目；总览章自身是生成产物不计。
- 列序与类目序是常量：根总纲打头，包清单按仓库分层顺序（与指令文档的目录结构一致），其余登记文件按名排后；类目行按标准六类先序，额外章名按名排后——两次运行结果完全一致，新鲜度比对才能逐行成立。
- 包前缀从登记文件名机械推导（`gloss-<包>` 推 `crates/<包>/src/`，`gloss` 推 `src/`，`bdd` 总纲不参与），无手工映射；包名取文件名整段（`gloss-core.md` 推出包 `gloss-core`），不是剥前缀的余段。
- 总览节携带根清单自身的行数，写回会改变根清单长度——再生迭代到结果稳定（总览行数与数字位数无关，两次内收敛），保证与门禁侧“对现场文件再生成一次”的期望一致。
- 仓库相对路径一律用分隔符（/）字面量比较，与版本库清单输出形态一致；只有文件系统开合处才走路径拼接。
- 根总纲缺失时再生成入口按无法完成判定退出（报错退出非零），不静默建文件；总览章缺失则插到首个章标题之前。
