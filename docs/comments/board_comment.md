## sequence_number（2026-11-06，Windows 移植 P2①）

- 剪贴板序列号：系统级单调计数，每次板更新递增——兜底读取器以基线差确认
  “目标应用确实写入了”，对提权进程注入被静默丢弃时序列号不动，兜底轮按
  未确认处理。零值表示查询不可用（无剪贴板站的会话），返回空交调用方按
  降级处理。

## format_count

- 数据格式计数：只读计数、不取数据，供快照区分“确认的空板”与“有格式的
  非文本板”（后者无法如实保全，兜底整体放弃，见快照记录）。计数在打开
  剪贴板的窗口内读取（与板的写者互斥）；打开失败返回空。后续阶段的图片
  哨兵（P2③）将复用同一查询面。

## png_format / has_image / read_format（2026-11-07，Windows 移植 P2③）

- 便携式网络图形（PNG）注册格式号：同名注册格式全进程同号，进程内缓存
  一次注册结果（含失败——零值缓存为空，调用方跳过该候选）。
- 图像存在性（`has_image`）：三格式（便携式网络图形（PNG）注册格式、版本
  5 位图（CF_DIBV5）、位图（CF_DIB））任一在板即真，`IsClipboardFormatAvailable`
  的纯元数据查询、不开板——哨兵的类型判定零副作用（不存在系统（macOS）
  “允许粘贴”授权流程）。
- 格式数据读取（`read_format`）：开板 → 取全局内存对象 → 字节上限在锁页
  与拷贝之前判定 → 锁页拷贝 → 解锁 → 关板。缺席、开板失败与数据查询失败
  都归缺席（单次尝试不重试，“交付不出”的降级语义归调用方）；拷贝长度取
  分配尺寸（可能大于载荷，解码器只读声明所需）。解锁容忍“末次解锁以假值
  返回 `NO_ERROR`”的系统约定（零错误码不计失败）。
- 标准剪贴板格式号（`CF_DIB`、`CF_DIBV5`）以常量落在本模块：绑定库把
  `CF_*` 常量放在组件对象模型（COM）先锋接口域（System::Ole），为两个
  整数值引整个接口域不值；值取自 winuser.h，与注入、消息泵常量的落点
  惯例一致。

## 开板守卫（2026-11-12，架构重构 A7 P0）

- 开板窗口收口为 `Drop` 守卫（`OpenBoard`，形态对齐系统（macOS）侧
  `OpenPasteboard`）：一次成功的 `OpenClipboard` 由守卫持有，`Drop` 是唯一
  关板点，各返回路径不再手工关板——早退路径漏关板的可能被结构排除，
  关板失败的降级留痕不变（`debug` 级“close clipboard failed”）。
- 守卫覆盖全部四个开板窗口函数（`format_count`、`read_format`、
  `write_formats`、`read_formats`）：方案定稿（2026-11-10）点名前两者时，
  后两者尚未存在（随 #330 的图片兜底路径于 2026-11-11 落地，同模式手工
  开关）；同一文件同一模式一次收口，不留半改状态。零行为变化：关板时点
  与失败留痕都与原手工路径逐一对应。
