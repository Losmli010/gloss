# comment_rules.py 决策记录

> 按符号锚定（不写行号，防漂移）。改到相关段落时同步更新本文件。
> 本文件随仓库跟踪（docs/comments/ 入库），文件内不留指向本文件的指针。

## 类别表（2026-10-26）

- 起因：初版按目录扫描（`scripts/hooks/comments` 与 `scripts/hooks/language_spec` 的
  `*.py`），顺序由文件名决定，与 AGENTS.md 的条目顺序无关；文档也就只能继续按脚本路径
  列条目，等于“谁管什么”在工具与文档各存一份。改成显式 `CATEGORIES` 表后，类别是唯一
  入口：文档只写类别名，路径、顺序、一个类别多个脚本都由表决定。
- 表项字段：标识（英文，命令行与自动化用）、类别名（中文，与 AGENTS.md 黑体名逐字
  一致）、路径元组、是否读放行标记常量。标识与类别名都可作命令行参数，精确匹配，不做
  前缀或模糊匹配——“源码”这类词太容易与其他词共享前缀。
- 放行标记是唯一不在任何文件头里的事实：五个标记名是 `gate_report.py` 的常量，故表项
  带开关，由工具用 `ast` 读现值打印，不抄第二份。
- 未采纳：把类别名做成脚本文件头的结构化字段（自描述）。文件头是注释门禁的受检面，加
  字段要改判罚口径，收益只是省一张表；而表在工具里本就可读、可 diff。

## 退出码（2026-10-26）

- 沿用全仓门禁约定：零通过、二用法错误（未知类别）、三无法完成判定（脚本缺失、文件头
  缺失或不可解析）。初版对“文件头缺失”返回 1，与“发现违规”同码，调用方分不清是读
  失败还是规则被违反。
- 退出 3 时已打印的部分不作完整性保证：调用方按退出码决定是否采信输出，脚本不缓存半份
  结果。无参调用先打印类别索引，再逐类打印正文，缺了哪一类一眼可见。

## 维护（2026-10-26）

- 新增判罚脚本时在表里加一行，并在 AGENTS.md“注释纪律”加同名条目。两处名字不一致不会
  报错，只会让读者拿到未知类别——这是有意的兜底：宁可命令报错并列出有效名，也不在文档
  里维护第二份映射。
- 文档侧的“测试面”并入“源码”：它在表里没有独立脚本，单列会造出一个不能当参数用的
  黑体名。
