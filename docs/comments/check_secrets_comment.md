## 匹配引擎委托 ripgrep（2026-10-25）

- 决策依据：同场实测现行逐行 2.73 秒、委托 ripgrep 热扫 0.03 秒，量级收益换新增工具依赖；版本钉进仓库根版本清单，环境初始化与持续集成安装同读。
- 分工：模式清单在本文件单点定义，运行时以编译产物的 pattern 源串拼装引擎的 -e 参数（大小写不敏感组加内联旗标前缀 (?i)），不复制第二份正则；引擎命中行回到本文件复跑逐模式归类——条目粒度（文件×类别×模式）与旧行文逐字一致，引擎只当候选行预筛。
- 文件清单仍取 git ls-files 且显式传参给引擎：不用引擎自带遍历（未跟踪文件会混进受检面）；实测显式传参不受忽略规则与隐藏规则影响，被忽略但已跟踪的文件照扫。
- 退出码翻回门禁口径：0＝有命中进后处理、1＝干净通过、2＝真故障当场失败不静默（工作区缺文件已前置滤除，剩余 2 类都是真故障）。
- 放行标记行由本文件对命中行后滤：引擎正则方言不支持负向预查，且标记过滤要按「行内任意位置含标记」判定，后滤在候选行极少的前提下成本可忽略。
- --json 输出规避「路径:行号:内容」切分对含冒号路径的不稳；取值字段有文本与字节（base64）两种形态，字节形态按容错解码还原。

## 引擎差异面的三处对齐（2026-10-25）

- 二进制（含空字节）文件前置整文件跳过：引擎会报出空字节之前的命中，旧实现整文件跳过——判定口径须零变更，故在传参前滤除。
- 字节序标记文件（UTF-8 与双字节两类前缀）改本文件逐行兜底：引擎会剥除 UTF-8 标记（旧行文保留该不可见字符）或按双字节编码整文件转码（旧按容错解码照扫），兜底路径逐字复刻旧行文与判定；此类文件罕见，成本不计。
- 其余编码差异（行内非法字节）：引擎按原始字节命中、旧实现按替换字符命中，对本清单的纯 ASCII 模式两者同判，等价比对含专项样本核实。

## 评审修正的三处差异面（2026-10-25）

- 事件流按换行符逐字切分：通用换行语义会把行文里未转义的三类换行字符（下一行、行分隔、段分隔）当切点，一条事件被撕成两段后解析即崩——旧实现正常报违规，崩在切分不崩在正则。解析异常（含字段缺失）收进运行时错误翻回门禁口径，不裸栈轨迹。
- 空白类超集展开：解释器的空白类比引擎（White_Space 属性）多四个控制分隔符（文件、组、记录、单元分隔），候选行由引擎预筛时这四符分隔的凭据会静默漏判——实测四例全部分叉。不敏感组的空白类在拼装参数时替换为超集字符类（White_Space 加四控制符），保证引擎候选面包含解释器可判面，判定仍由解释器侧清单模式收口（超集多筛的行会被归类丢弃）；引擎的方括号类支持嵌套，空白类出现在类内时替换也成活。
- 用户配置通道关死：引擎会读环境变量指到的配置文件，实测两行配置（编码指定为双字节）把真实违规静默判成干净——参数序列加 no-config 一词关死，本地与远端判定不随用户环境漂移，与钉版本动机同源。

## 反馈契约迁移：统一诊断出口与三类标识（2026-10-25）

- 违规报告改经统一诊断出口（gate_report）打印：每条违规一行「✗ error[标识]: 消息 (路径:行号)」加完整证据行与修复指引，末尾汇总计数等于明细数；消息保持英文，通过行确认消息不变仍走标准输出。
- 三类标识与模式组的对应：区分大小写组（服务商前缀与私钥块）整体归 SECRET-VENDOR；通用凭据赋值（带引号与裸值两形态）归 SECRET-CREDENTIAL；授权头持票人凭据从不敏感组拆出单归 SECRET-AUTH。拆分只改报告归类，模式清单逐条未动——同一输入的违规集合（文件×行）零变更。
- 源码形态：不敏感组拆成 CREDENTIAL_PATTERNS 与 AUTH_PATTERNS 两个清单再拼回 CASE_INSENSITIVE_PATTERNS（引擎参数与既有单测都按拼回后的清单序消费，行为不变）；RULE_GROUPS 固定「标识→消息→模式组」映射与报告顺序（文件序、规则序、行号序）。
- run() 保留旧返回形态（逐模式分组的字符串清单）：现有单测断言的就是它，这正是「判定未漂移」的证明，故不随输出迁移改签名；新增 findings() 产结构化条目供报告出口消费；两者共用同一次扫描 scan_hits，判定面同源。
- 退出码迁移：违规＝一不变；参数多余或根目录不存在＝二（用法错误，原为静默忽略多余参数或栈轨迹）；ripgrep 缺失或引擎故障＝三（无法完成判定，原为一）；git 清单枚举改走 run_git 统一包装，失败打 error[INFRA] 并退出三（原为裸 check=True 抛栈轨迹退出一）。
- 密钥域不加空扫描面守卫：落地方案的守卫表未列密钥域——刚 init 的空版本库属正常输入，扫描面为空按通过处置，不按失败关闭。
- 自命中豁免：RULE_SECRET_CREDENTIAL 常量行（常量名含凭据关键字、值是十七字符的登记名）被自家通用赋值模式命中，按既有放行机制行尾加标记与缘由——标识常量是登记名不是凭据，属合法字面量豁免的标准场景。
- 并轨入口兼容：main 保留 loader 可选参，run_text_gates 聚合时把非零退出码统一折算为整体失败，失败关闭语义保持。

## 豁免缘由机器化（2026-10-26，PR7）

- 放行标记须带缘由从口头约定升级为机器判定：命中行里的标记若缺同行非空缘由，按通用域的缺缘由标识报告，豁免语义本身不变（标记行照旧从各模式命中里滤除）；判定正则与条目构造收口在 gate_report 的共享助手。
- 判罚面钉在豁免现场：只有命中扫描模式的标记行才判罚——指引文案、常量定义与文档提及里的标记字样不是豁免现场，不判罚（否则本文件的修复指引会自命中）。
- run() 与 findings() 同源接入：运行函数追加「allow marker without reason」分组条目，结构化函数在规则组之后按行号序追加同判定条目；两路径共用 allow_reason_findings 一个判定点。
