# ui/popup/note.rs 决策记录

## `stream_note` → `stream_fields`（顺序双字段扫描器）

- 增强目标（设计 §5.7）：消除“描述流完后等整个响应”的静默期——
  `note` 值闭合后游标继续推进，`interpretation` 数组逐条渐进出。泛化
  而非并列两个扫描器：一次整段重扫同时产出两字段（每帧几十 KB 上界、
  无分配的既有口径不变），两扫描器并列会重扫两遍且要人为约定游标分工。
- `Cursor::json_string` 返回值加 `closed` 标志：双字段推进的前提是分清
  “值闭合（可继续推进游标）”与“值未写完（停在进度态）”。旧签名
  `Option<String>` 两种情形不可分；`skip_value` 的语义不变（只认闭合值）。
- `interpretation` 在写条目带反转义前缀上屏（与 note 的渐进口径一致），
  而非只出闭合条目：逐条整条出现会在长条目上复现“静默等待”——正是
  本次增强要消除的东西。数组元素不是字符串（模型异常输出）时停在已
  到达条目：流式期不猜，完成态由 finalize 的三层降级兜住。
- 字段次序不写死：prompt 模板固定 note 在前，但扫描器按任意键序工作
  （词卡 phonetic 在前是既有事实），顺序假设一旦写死，模板微调即碎。
- “未到齐即停在当前字段、已到达部分照常返回”取代旧“整体落进度态”：
  旧口径下 `{"phonetic":"/x/"`（外键闭合但逗号未到）会让已可见的注回退
  成骨架；新口径已到字段不因后字段未到而闪烁。旧测试里“未到齐返回
  空串”的断言全部只覆盖 note 为空的情形，行为兼容。

## 扫描器下钻 structured（契约校验步骤 3，2026-10-11）

- 契约嵌套化后疏证字段自顶层（interpretation/examples）搬进 `structured`
  对象。方案 §3 说“note 仍是首个顶层字段，扫描器逻辑原样工作”——对 note
  成立；但图像流式卡的疏条目渐进上屏是已交付的行为（PR #158），顶层键消失
  即静默丢失。取舍：给扫描器加一层 `structured` 下钻（内层认 examples），
  疏条目继续随流上屏；`StreamFields.interpretation` 同步改名 `examples`，
  与数据模型用词一致。
- 下钻只认一层：内层对象只识别 `examples`，`phonetic`/`code_language` 是
  字符串同胞键，走 skip_value——流式期不需要它们（角标只认产物回传）。
- `structured` 键的值若不是对象（违约形态），按普通值整体跳过，不阻断
  后续键扫描。

## `StreamFields`

- 流式期已到达的正文：注（`note`，反转义前缀）与疏（`structured`
  内 `examples` 已到齐条目 + 在写条目的反转义前缀）。

## `stream_fields`

- 流式正文的可见部分：对累积的原始流做**转义感知**的顺序双字段扫描。
  现行输出契约是纯 JSON 对象（见 `gloss_core::schema`），字段次序固定
  `note` 在前、`structured` 随后，扫描器逐对处理键值：`note` 值闭合后
  游标继续推进，遇 `structured` 下钻一层——`examples` 数组逐条渐进出，
  描述流完不用等整个响应，疏证条目随流上屏。任一字段“未到齐”即停在
  该处（已到达部分照常返回），正文区全空时由调用方落骨架。值到齐后按
  JSON 字符串转义规则逐段反转义；残缺的转义序列（尾部孤反斜杠、不足
  四位的 `\uXXXX`）本帧丢弃、下一帧补齐，UTF-16 代理对在流式期暂缺
  （完成态以 `outcome` 为权威源）。违约输出（散文、围栏）不含 `note`
  键，全程进度态，完成态落降级卡。

## `scan_fields`

- 单层对象的键循环：顶层认 `note` 与 `structured`（下钻），`structured`
  层认 `examples`；其余键跳过完整值。“未到齐”消费尽量少并停在该处
  （下一帧整段重扫，流式帧几十 KB 上界、无分配，无需增量缓存）。
- 键：字符串字面量；未闭合则停在已提取的字段上。

## `consume_value`

- 单个键的值消费：认得的键写入 `fields`，返回键循环是否继续——值未到
  齐或值非法（进度态停点）返回 `false`。
- 嵌套契约：疏证字段在 structured 对象里，下钻一层继续
  键循环（它消费自己的闭合括号）；不是对象则按普通值跳过。
- 其余键：跳过完整值；值未写完则停。

## `Cursor`

- JSON 前缀扫描游标：`rest` 恒为未消费部分；所有“未到齐”情形都消费
  尽量少并让调用方停在该处（下一帧整段重扫，流式帧几十 KB 上界、无
  分配，无需增量缓存）。

## `Cursor::strip`

- 剥掉前缀；不匹配则原样保留并返回 `false`。

## `Cursor::json_string`

- 提取一个 JSON 字符串的反转义内容（未闭合返回 `closed = false`，
  残缺转义就地截断、下一帧补齐）。
- 输入耗尽＝值未写完：已到达的部分照样上屏（下一帧整段重扫）。
- 残缺转义（尾部孤反斜杠/不足四位的 \uXXXX）就地截断、
  返回已到达部分——下一帧整段重扫后补齐。

## `Cursor::string_array`

- 提取一个字符串数组（`examples` 的流式形态）：已到齐的条目
  全量返回，在写条目带反转义前缀；数组闭合前 `closed = false`。
  元素不是字符串（异常输出）时停在已到达条目上，完成态由 finalize
  解析兜住。

## `Cursor::skip_value`

- 跳过一个完整 JSON 值（字符串/数字/true/false/null/数组/对象）；
  值未写完返回 `false`（进度态）。
- 数字与字面量（true/false/null）：读到结构性边界。
