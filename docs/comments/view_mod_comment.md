# view_mod 决策记录

> 按符号锚定（不写行号，防漂移）。改到相关代码时同步更新本文件。
> 本文件随仓库跟踪（docs/comments/ 入库），改名与合并用 git mv 保留历史；文件内不留指向本文件的指针。

## ViewInput

- 检视页的五路输入：报告分组聚合、用例配对、历史行、标注与基线资产；
  渲染层只读输入，不读环境、不落盘、不重算结算与聚合。
- `cases` 取用例定义与结算明细的配对切片：计划数据血缘（§6.7）要求测
  试用例表与展开态来自结算明细与用例定义两源，参考答案（期望类别或理
  想产物）只在用例定义一侧，结算明细不复制它；模块依赖图（§五）未列
  `view` 到 `dataset` 的边，本步补上这条类型依赖（纯类型、无输入输出
  （IO），无环），配对由流程装配完成，渲染层不查数据集。

## CasePair

- 配对以标识为键在装配层一次完成；渲染层假定两侧同标识，不重复校验。

## render_html

- 单文件（HTML）拼装：样式、四区骨架（顶栏、指标总览、历史曲线、测试
  用例）、内联脚本；零外部资源——系统字体、无外链样式与脚本，历史区
  块嵌入趋势模块的唯一出口产物，与 `eval history` 命令行同源。
- 页面不做本地持久化（避免与落库标注状态分叉）、不做深色模式、不做键
  盘快捷键与文本差异渲染（计划 §七 明确不做）。

## esc

- 外来文本（用例输入、输出原文、备注、理由）一律转义后才进标记语言，
  覆盖 `&`、尖括号、单双引号——测试断言注入载荷不落原文。

## fmt

- 数值展示格式：最多两位小数、去尾零（62.5、76.25、75），比率加百分号
  由各区块自行拼接。

## SCRIPT

- 内联脚本约四十行，职责固定为四件：三轴筛选（类型、契约、回归与运
  算）、展开折叠（原生 `details`，脚本不参与）、标注记忆（按钮单选、
  备注输入、导出计数实时更新）、导出（以 `Blob` 下载 `labels.json`）。
- 导出文档与 `eval label --import` 输入同构（`labels` 键包裹 `{id,
  verdict, note}` 行），导出文件即导入文件。
