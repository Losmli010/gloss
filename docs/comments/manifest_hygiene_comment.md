# manifest_hygiene.py（约束门禁·清单卫生）决策记录

> 按符号锚定（不写行号，防漂移）。改到相关检查时同步更新本文件。
> 本文件随仓库跟踪（docs/comments/ 入库），文件内不留指向本文件的指针。

## 约束「版本单点维护」（实现）

- 根清单工作区段的版本与语言版本字面量是唯一来源；子包一律 `*.workspace = true` 继承，出现字面量即违规。根清单缺失对应字面量同样判罚。

## 约束「依赖只开需要的特性」（实现）

- 本仓库路径依赖（不带版本）与工作区继承项不适用这条；条目按跨行拼接后的全文判定，特性字段写在后半段不误报。

## 约束「依赖无死条目」（实现）

- 声明的每个第三方依赖（非本仓路径、非工作区继承）必须能在所属包的源码面（源码、测试、基准目录）找到使用证据：路径引用（含属性宏与派生宏内的路径）、宏调用，或导入语句（重导出与别名导入同算）。
- 依赖键连字符按本语言（Rust）惯例转下划线后匹配；证据按文本匹配、不区分注释与代码（宽松判定防误报优先）。
- 条目行尾的放行标记（deps:allow）豁免该条（同密钥扫描惯例，须注明缘由）。
- 本仓路径依赖由「依赖方向」管辖，不在此判罚；本仓无构建脚本，若未来引入需把其纳入扫描面。

## 测试桩不进生产构建

- 2026-09-18 core 的 test-util 特性会打开 MockEngine 与 ports::mocks；生产装配只需要真实引擎（M4-T4 起），桩只该由下游 crate 的 dev-dependencies 开启。这条以前靠一次性人工 `cargo tree` 核对，现在钉成门禁：谁把它加回 [dependencies]（含 target 门控的非 dev 段），这里当场失败。

## 通过行的条件语义

- 版本单点与依赖特性两行无条件输出；死条目一行只在零违规时输出（计数含放行标记条数）——与拆包前一致。

## 反馈迁移（2026-10-25，PR2c）

- 三条判罚各挂规则标识（版本单点、默认特性、依赖无死条目），判罚消息去掉「constraint violation (xxx)」前缀；证据行完整不截断：默认特性与死条目判罚都带完整依赖条目全文。
- 版本单点判罚的行号取零：工作区段与包段的字段缺失属结构性判罚，不落在清单的具体行。

## 豁免缘由机器化（2026-10-26，PR7）

- 依赖条目的放行标记（deps:allow）缺同行非空缘由即按通用域的缺缘由标识报告，条目豁免本身不变（仍不计入死条目、放行计数照加）；条目全文保留行界，缘由判定逐物理行核对——标记所在物理行缺缘由即罚（位置＝条目首行加行偏移），多行内联表条目的续行内容不冒充同行缘由（PR7 评审收口）；其余子串判定（路径依赖、工作区继承、默认特性、标记存在性）一律在单行形态上做，断行键值不把放行翻成误报（二轮评审收口，断行形态有夹具钉住）。
- 特性字段检查不受放行标记影响，照旧单独判罚——豁免只豁「无使用证据」这一条。
