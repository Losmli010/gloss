# run_text_gates.py 记录文件

并轨入口的缘由、取舍与精确用法。方案依据：《门禁体系重构开发方案》第四节第 6 行（PR-P3）与裁决八；《门禁脚本执行效率提效方案》任务卡二-1 与附录协议。

## 为什么复用各门禁的 main 而不是重写输出

聚合输出要求与六条单跑输出拼接逐条一致。各门禁的输出（头部、即时违规行、汇总、修复指引）全部住在各自的 main 里；并轨入口直接依序调用 `module.main(loader=loader)`，输出一致性由构造成立，不复制任何格式化逻辑。代价是 main 必须能用缺省参数解析出与单跑相同的仓库根——各 main 的缺省根都从自身文件位置回溯，脚本住在仓库内即天然成立，故入口不再收参数：收了参数反而要按各门禁不同的参数口径（有的收根、有的收文档路径）逐一翻译。

## 内容装入器的接口与语义

`ContentLoader(root)` 四方法：`tracked()`、`manifests(root)`、`read_bytes(path)`、`read_text(path, errors="strict")`。

- `tracked()`：一次 `git -C root ls-files -z`，解码统一码容错（utf-8 加 replace），全部消费方共享同一结果。密钥门禁、行为清单（`-- '*.rs'` 路径规格过滤等价于全清单按 `.rs` 后缀过滤，git 通配符跨目录匹配）与约束门禁任务标记段原本就是这条命令；文档引用与注释门禁的缺省枚举原为非空分隔形态（text=True 严格解码），评审后一并统一到空字节分隔——单跑与并轨的枚举从此同形，两个门禁各带一条非英文字节（ASCII）文件名的回归测试锁住该形态。
- 枚举统一的原因（评审发现的潜伏分叉）：git 对会被引号转义的文件名——非英文字节（ASCII）、控制字符、引号与反斜杠——在非空分隔输出里做八进制转义，且转义先于任何解码发生，合法统一码的中文文件名同样中招（临时仓实测：文档.md 输出成 `"\346\226\207\346\241\243.md"`）。打引号的假路径在注释门禁过不了类型分派（扩展名判定吃到尾部引号），文件被静默漏检；在文档引用门禁则误报路径缺失、引用核对文件被静默排除——而并轨走空字节分隔拿到真名正常受检，形成单跑与并轨的判定分叉。当前树为时点快照：2026-10-25 跟踪 274 个路径、零引号转义名，统一对现树判定零影响（等价比对双跑实证）；快照会随新增跟踪文件漂移，枚举形态本身不再依赖该快照。
- `manifests`（2026-10-25 随约束内容缓存并入协议）：约束门禁的工作区清单枚举——枚举逻辑单点住约束共享层（并轨装入器首次调用回该处取结果），缓存住装入器实例，单次运行只枚举一次；此前并轨路径每扫描重复枚举约五次，属拆包遗留的预存成本，随协议补齐消掉。约束包缺省（不传装入器）路径由包内同款缓存覆盖。
- `read_bytes`：字节层缓存，键为绝对路径（相对路径并入根）。供密钥分流（空字节与字节序标记检查）、密钥兜底逐行、约束门禁任务标记段共用。
- `read_text`：解码层缓存，键为（路径，容错口径）二元组。实现用 `io.TextIOWrapper(io.BytesIO(...), encoding="utf-8", errors=...)` 包装字节层——与 `open(path, encoding=...)` 走同一读取机器，通用换行翻译（\r\n 与孤立 \r 折成 \n）与解码报错路径逐字节一致；不手工替换换行符是因为 `str.splitlines` 会额外按 \v、\f、\x85 等切行而文本模式不切，手工 replace 链则要重新证明与标准机器等价。容错口径进键的原因：注释门禁按严格口径把非法统一码文件报成不可读违规，其余门禁用容错口径，两种结果都要原样保留。

## 各门禁的枚举与读取改道点

枚举语义零变更：凡原本走 `git ls-files` 的枚举改读 `tracked()`；凡原本走目录遍历（约束门禁的 walk_rs、文案门禁的 os.walk）的一律保持遍历——遍历看工作区（含未跟踪文件），换成跟踪清单会缩小受检面。

- check_secrets.py：`scannable_files`、`fallback_hits`、`run`、`main`。
- check_agents_doc.py：`run`（跟踪清单）、`scan_lines`（文档与任务配方文件，严格口径）、`scan_quality_refs`（引用文件，容错口径）。
- check_test_bdd.py：`tracked_rs_files`、`src_test_names`、`target_test_names`、五个清单读取函数（`bdd_lines` 统一按行读取，严格口径）、`run`、`main`。
- check_constraints.py：模块级 `read_text` 收装入器；`pkg_name`、`section_body`、`dep_entries`、`stub_section` 与 `_checks` 内全部读取点透传；任务标记段改读 `tracked()` 与 `read_bytes`（字节层，保留原文手工解码——该段口径本就是原始解码，不做换行翻译）。
- 2026-10-25 约束门禁拆包后：上述接入点随文件迁入约束包——文本读取与清单解析住共享清单扫描模块，任务标记段的清单枚举与字节读取住源码卫生模块；内容装入器签名约定不变，并轨入口零改动（仅导入名随包名更替）。
- check_i18n.py：`literal_violations` 与两条逐行扫描（装入点、词条表），容错口径。
- comments/check_comments.py：`scan_files`（显式文件清单优先级不变）、`run`（严格口径，不可读报错路径保留）、`main`。

逐行读取改写说明：原先 `for line in fh` 的几处统一改成整读加 `split("\n")`。两者差异只有两点——行尾是否带换行（各消费方第一操作就是 rstrip 或无锚正则，不受影响）与结尾多出一个空串元素（逐条核对过全部消费方：startswith、整行匹配、正则搜索对空串一律不命中；约束门禁 dep_entries 里空串只会把跨行条目提前冲刷，冲出的元组与末尾冲刷一致）。用 `io.StringIO` 逐行迭代可以完全消除这层推理，但要在每个门禁里再引一层逐行包装；等价比对（头指针全仓加种子违规双跑逐字节一致）已实证当前改写无差异。

## 编排细节

- 门禁顺序固定为组合配方清单序：密钥、文档引用、行为清单、约束、文案、注释；顺序进 GATES 元组，单测锁死。
- 单个门禁抛 SystemExit（行为清单的前置失败：清单文件缺失、测试面为空）时按该门禁失败计并继续跑完其余门禁——单跑里这会直接以退出码 1 落地，并轨里换成等价的消息与失败标记，报告保持完整。其余异常照常穿透（门禁自身缺陷应当响亮失败，不静默吞掉）。
- check_comments 的 main 原先成功路径不带返回值（裸落底），并轨里 `None != 0` 会误判失败；现已补 `return 0`，单跑路径 `sys.exit(None)` 与 `sys.exit(0)` 退出码相同，行为不变。
- 任务配方层：`text-gates` 依赖新增的 `text-gates-merged`（调本脚本）再加五条工具格式配方，输出顺序与原清单一致；六条单门禁配方保留（远端分作业步骤与单项调试用）。

## 等价比对与计时（2026-10-25，本机）

- 比对方法：旧实现取 main 头指针的 scripts/hooks 全目录（git archive 解包到临时目录，显式传根运行），与新实现在同一工作树上各跑六门禁，另跑并轨入口；标准输出与标准错误分别拼接比对。干净树与种子违规树（六门禁各一条：假密钥、不存在的配方引用、未登记测试、任务标记、生产代码中文文案字面量、英文注释）各一轮，全部逐字节一致；种子树下六门禁全部失败、并轨退出码 1、六段报告齐全。
- 计时（热缓存三次取中位，`/usr/bin/time -p`）：见拉取请求描述；数字随环境漂移，只作同机前后对照。
