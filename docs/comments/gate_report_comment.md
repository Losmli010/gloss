## 模板与输出流（fail／summary／Finding）

- 模板原文：首行「✗ error[标识]: 消息 (相对路径:行号)」，证据行「四个空格＋证据: 违规行原文」，修复行「四个空格＋help: 修复动作或合规豁免方式」——证据与补救缺省（空串）时整行不打印；列号在场时位置追加「:列号」，路径为空（基础设施类条目无被检对象）时首行不带位置括号。
- 消息语言保持英文，与既有门禁输出一致；「证据」「help」两个栏名是模板固定部分，不随消息语言走。
- 证据行不截断：密钥门禁的验收就是完整证据行，出口层不预设长度上限；确需截断的门禁（如约束域的完整证据行改造）按各自迁移需求补「… (truncated)」声明逻辑，不在共享出口抢跑。
- summary 汇总行「error: N violation(s) found (see above)」，单数用 violation——计数必须等于已打印明细数，由输出锁定测试（三件套之二）断言。
- fail 返回同一条目，调用方边打印边汇集、末尾交 summary——打印与计数同源，从构造上杜绝「汇总数与明细数不一致」。
- Finding 用冻结数据类：字段序为规则标识、相对路径、行号、消息、证据行、补救、列号（缺省零），后四项可缺省——迁移中的门禁多数只有前四项可用。
- 报告全部走标准错误（file 参数可注入便于单测），通过行的确认消息仍走标准输出由各门禁自打，出口只管失败面。
- file 参数缺省取 None、调用时回退标准错误（PR5 起）：缺省参数在函数定义时求值，模块导入那一刻绑死的旧标准错误对象让进程内消费者（测试替换标准错误、并轨入口的捕获）收不到输出；改为调用时求值后生产路径行为不变，仍是当刻的标准错误。
- render（PR5 增）：违规条目渲染成「消息 (位置)」单行，位置缺席时只留消息——作为各门禁运行函数返回清单里的条目形态；此前该三行函数在文案与约束两域各抄一份，注释家族迁移时收进共享出口，存量两份不强制回改。

## 退出码（全脚本统一约定）

- 零＝判定完成通过；一＝判定完成发现违规；二＝用法错误（参数缺失或格式错）；三＝无法完成判定（版本库调用失败、工具缺失、输入不可读）——失败关闭，绝不因「没检查到」退出零。
- 钩子、任务配方与持续集成都按「非零即拦」处理，引入退出码三无兼容风险；并轨入口把各门禁的非零退出码统一折算为整体失败，失败关闭语义保持。

## run_git（统一包装版本库调用）

- 签名 run_git(args, cwd=None, file=sys.stderr)：成功返回完成态子进程（消费方自取 stdout）；失败（含找不到 git 可执行文件）打印 error[INFRA] 条目并 sys.exit(3)——消灭裸 check=True 抛栈轨迹的路径。
- 失败详情（子进程标准错误）折叠成单行做证据行——多行错误整段进证据会撕裂模板的行结构。

## 规则标识登记（REGISTERED_RULES 与常量）

- 命名规则：大写字母加短横线可含数字，前缀按脚本域；含义、判罚口径与豁免方式住登记表记录文件（gate_rules_comment.md，本地）。
- 两处同源：常量定义随本模块（通用域：RULE_INFRA／RULE_EMPTY_SURFACE／RULE_ALLOW_REASON）或各脚本常量区（密钥域三标识在 check_secrets.py）；代码引用只能取自登记处，登记表不进源码文件头（注释纪律禁止文件头罗列条目）。
- 持续集成里登记表（本地文件）不在场：代码侧 REGISTERED_RULES 是权威清单，一致性测试经它核对全部规则常量定义与规则实参；登记表在场时（本地）另做两边集合一致核对——缺席时跳过不判罚，这是有意取舍：CI 无本地文件，不能因文件缺席拦门禁。
- 一致性测试（gate_report_test.py）的静态扫描口径：常量定义按「RULE_ 前缀名 = "标识"」整行匹配（行尾允许跟放行标记注释——凭据域标识的常量名会被自家模式命中，须按豁免机制放行），值必须落在登记清单；规则实参按「rule=大写常量名」或「rule="标识字面量"」匹配——字面量直接核对登记清单，常量先核对定义再核对登记清单；位置传参不走关键字不被扫描覆盖，防漂移靠常量定义侧核对兜底（常量即登记物，任何常量的使用都已被定义侧核对覆盖）。
- EMPTY-SURFACE 与 ALLOW-REASON 两个通用常量曾先登记不使用（占位保证登记表首版全集与代码侧清单一次对齐）：前者随 PR2c 启用，后者随 PR7 启用。

## 豁免缘由判定（allow_reason_missing／allow_reason_finding，PR7）

- 正则「标记＋空白＋非空白」单点收口在本模块：标记经转义后拼「\s+\S」，消费方把标记所在行（或豁免条目全文）交给它，匹配不到即算缺缘由。
- 条目构造器只认「哪类标记、哪条位置、哪行证据」三个现场参数，消息固定「标记名＋marker without a reason」，补救指向同行补缘由——各门禁不重复拼消息，报告形态天然一致。
- 判罚面归各门禁自持：只有标记真正构成豁免的位置（密钥与文案的命中行、约束三模块的豁免分支、注释门禁源码与脚本两子检查的标记豁免行——后者随 PR7 评审补接）才调用判定；规则描述、修复指引文案与常量定义里的标记提及是惰性提及，不判罚——否则门禁自己的指引文字就会自命中。
- 五类标记全名清单（ALLOW_REASON_MARKERS）与整行扫描助手（allow_reason_findings_for_line）随评审补接落本模块：注释子检查面对的标记类别不定、且须按全名核对（「界面边界上下文」标记含后半段，短前缀核对会误报），逐标记核对同行缘由后汇总返回。
