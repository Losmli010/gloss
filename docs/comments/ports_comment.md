## 模块（async 方案定案）

- 2026-09-19 **不用 async-trait / trait-variant**：[`AiEngine::execute`] 以普通方法返回 [`BoxFuture`]，签名本身对象安全（`dyn AiEngine` 可用）、零宏；除 `futures-core`（[`TaskStream`] 的 `Stream`）外零额外依赖。若未来出现需要原生 `async fn` 的端口（无对象安全诉求时），再评估 AFIT，不回头改此决策。

## SelectionReader（与草案的偏差）

- 2026-09-19 草案返回 `Option<String>`，落地时收窄为 `Result`：错误需要区分权限缺失（引导授权）与普通取不到（静默降级）——文档以本定义为准。

## ConfigStore（密钥不进配置快照）

- 2026-09-19 「密钥不进配置快照」为 06 ADR 的决策：快照是跨线程共享的运行时视图且会落盘，密钥本体不得进快照或句柄。
- 2026-10-30 端口拆分（pre-image-refactor-plan 阶段 2 · R1）：配置持久化与密钥存取拆成两个独立端口——本节只答配置文档的整读整存，密钥三方法迁 [`SecretStore`]；拆分前平台包被迫发明内部接口拆半边再粘回，只需密钥的调用方（内建引擎、启动预热、设置会话、评测桩）提着从不使用的 `load/save`。组合实现同时实现两者，`ConfigHandle` 与配置读写路径不变。
- 端口契约：配置存储是应用配置文档的读写边界。全部方法取 `&self`（实现方以内部同步保证并发安全），适配器才能以 `Arc<dyn ConfigStore>` 注入。
- 方法语义：`load` 缺文件时返回出厂默认（并尽力落盘）；`save` 整份写入（设置页保存路径）。
- 红线：读取配置失败时错误文本不得转述配置文件内容（解析错误常引用出错行或取值，而用户可能把密钥贴错字段），只给位置与类别。

## SecretStore（密钥来源唯一由类型系统承载）

- 2026-10-30 与 [`ConfigStore`] 拆分同步新增：密钥存取（读、写、删）收口在唯一的密钥端口，只需密钥的调用方持 `Arc<dyn SecretStore>`，类型上就造不出「从配置快照拿密钥」的路径——密钥来源唯一从评审条目升级为编译期事实。
- 端口契约：按 keychain 条目标识读写系统安全存储。全部方法取 `&self`（实现方以内部同步保证并发安全）。
- 方法语义：`secret` 读取密钥、`None` 表示未设置；`set_secret` 写入（或覆盖）；`delete_secret` 删除密钥、条目不存在视为成功（幂等，设置页「清除密钥」用）。
- 密钥红线：入参与返回值都是凭据，实现方禁止将其写进日志、错误消息或 [`GlossError::EngineResponse`] 这类携带诊断文本的变体。

## SceneProbe（无失败面的端口，2026-09-24）

- 形态上与前几个端口相反：`facts()` 返回 `SceneFacts` 而**不是** `Result`。理由不是「这里不会出错」，而是「出错时的正确行为恰好等于默认值」——读不到场景就当没有敏感场景（防护的默认姿态是不打扰），一次系统接口变更不该让划词彻底失效。这与 [`SelectionReader`]（读不到选区 = 任务失败，必须让用户知道）是两种失败性质，因此两个端口的形态不同。
- 为什么放在 core 而不是让 gloss-app 直接调平台：判定的输入必须是纯数据，否则「给定场景该不该拦」就没法用 L1 测试全矩阵驱动（见 guard_comment.md）。
- 端口契约：触发前场景探针读一次当前场景事实（安全输入态与前台应用），供 [`crate::guard`] 的场景闸门判定。实现方必须纯查询、不阻塞、不索取新权限：每个平台事件都会读一次，无论它最后是否成为取材。

## TaskChunk（流条目升级为枚举，2026-10-11，契约校验与重试方案 §5）

- `TaskStream` 条目从裸 `String` 升级为 `TaskChunk::Delta | Done{finish_reason}`：结束原因要在流里走；「Err 不保证终结流」的既有端口契约不动——`Done` 是**正常**终结条目，其后的增量没有契约地位。
- 通道④ `Event::TaskChunk` 仍只转发 Delta：本步没有主线程消费方，终结条目由 core 编排层（`run`）消费；等修复轮需要把结束原因带上 UI 时再扩通道载荷，避免一次引入无消费者的字段。
- 契约：`TaskChunk` 是任务产物流的单个条目（文本增量或服务端声明的流结束）。`Done` 携带服务端声明的流结束（SSE `data: [DONE]`）的 `choices[0]` `finish_reason`（`stop` / `length` / `content_filter`…；未声明为 `None`），是终结条目：其后的增量没有契约地位，实现方不再产出；`finish_reason` 结束原因原文不转译，消费方按需判定。

## BoxFuture

- 装箱 future：trait 方法要返回异步结果又不能丢对象安全（`dyn AiEngine`），只能装箱；`Send` 供消费端在 tokio 上轮询。

## TaskStream

- 任务产物流：文本增量与服务端声明的流结束。上层的流式通道只转发 [`TaskChunk::Delta`]，结束条目由编排层消费。
- `Err` 是普通增量的一种，**不保证终结流**：实现方可在 Err 后继续产出，消费方以**首个 `Err` 为终结**并丢弃半截产物。

## EngineRequest

- 引擎请求：**已渲染**的对话消息 + **已解析**的模型 id。渲染归 core 编排（含模态校验），引擎只负责送出请求、流回响应——不做渲染，也不回读配置。
- 字段：`messages` 渲染好的消息（多模态 content 数组随图像任务扩展）；`model` 本任务使用的模型 id（App 在触发时按配置冻结）；`max_tokens` 回复的 token 上限（OpenAI 兼容 `max_tokens`），`None` = 不设限——需要截断回复的调用方（如分类只回一小段 JSON）按请求性质自行携带。

## AiEngine

- AI 引擎（端口）：统一入口，不按输入模态拆分——文本/图文只由消息 payload 与模型 id 决定。**模型不回读配置**（随请求携带）；引擎自己读快照的只有端点与 provider 条目。
- 实现方保证：`execute` 返回的 future 与流都是 `'static` 且 `Send`，**不得借用 `self`**；`request` 按值接收，实现方把数据移入 future 即可。取消不进本端口：调用方以 `CancellationToken` 在 await 侧竞速，实现方只需保证 future 被丢弃时连接随之关闭（异步客户端的默认行为）。

## AppIcon

- 应用图标（端口）：把品牌图标交给平台外壳（Dock / 应用切换器）。
- 这是**降级端口**：安装失败（调用线程不对、系统拒绝、字节解不出图）只让图标退回系统默认，不影响启动，因此**不返回错误**——只回报是否成功，供调用方记一行日志定位。
- 调用方保证：在**主线程**上调用，且晚于 winit 的 `EventLoop` 构建——macOS 的 `NSApplication` 单例在 `EventLoop::new` 之前访问不受支持。
