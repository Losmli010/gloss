# check_agents_doc.py 决策记录

> 按符号锚定（不写行号，防漂移）。改到相关检查时同步更新本文件。
> 本文件随仓库跟踪（docs/comments/ 入库），文件内不留指向本文件的指针。

## 脚本存在的原因

- 2026-09-18 这份文档原本叫 AGENT.md（单数），而客户端解析指令文件时只认 AGENTS.md，于是它在从未被加载的状态下漂移出了已删除的命令（`cargo run -- --overlay-selftest` 随自检迁入 tests/ 后失效，无人发现）。“命令能打印出来就别在文档里复述”这条原则靠人记不住，交给脚本。

## 检查 5（约束名指名引用）

- 2026-09-18 引用一律指名、不写条号的原因：条号会随重排失效（上一轮重排就断掉了两处源码注释里的“第 N 条”）；改了约束名忘了改引用，这里当场失败。

## 扫描范围的取舍

- 2026-09-18 代码块内同样算数的原因：命令清单本来就写在代码块里，漏掉它等于放过了最该校验的部分。
- 2026-09-18 路径只认行内反引号包裹的仓库相对路径的原因：代码块里的树形图与行尾注释混排没法可靠切词。

## 配方名提取正则

- 2026-09-18 不用 `\b` 的原因：BSD grep 对词边界转义的兼容性不稳，改用“行首或非词字符 + just ”并排除 justfile 这类无空格的词。
- 2026-09-18 正则形状（结尾要求空白或行尾、`[^:=]+`）防两类误报：避免 `logs` 命中 `logs-dir:`；挡掉 `coverage_min := "70"` 这类变量赋值。
- 2026-09-21 `[^:=]+` 放宽为 `[^:]+` 的缘由：配方参数带默认值（`bench-check name="last":`）是合法 just 语法，`=` 会卡住旧正则、把存在的配方判为不存在。原两类误报防护不受影响——`logs` 命中 `logs-dir:` 靠“参数段必须以空白起始”挡住，变量赋值靠首个 `:` 之前无可匹配的参数段挡住。

## 约束名引用的扫描范围

- 2026-09-18 不含 *.md 的原因：文档里“”另有用途（设计文档里的“约束”是另一套语境），扫进来只会误报。
- 2026-09-18 本脚本自身与其单测按构造就含“AGENTS.md … 约束“””模式（正则字面量与夹具数据），故显式跳过。

## 接入统一诊断出口（2026-10-26，gate-pr4）

- 五类引用核对各挂一个规则标识：配方、路径、裸文件名、测试目标、质量条目指名引用分别对应文档引用域五标识，加上受检文档缺失的 DOC-INPUT 共六标识落脚本常量区（登记表见 gate_rules_comment.md），代码引用只取常量。
- 判定面与计数语义不变：旧违规字符串改为“消息（位置）”渲染行，旧断言核对的子串（消息骨架与引用条目名）原样保留；质量条目引用违规补行号——原字符串不含行号，旧断言只核对条目名，不受影响；违规行原文进证据行，旧末尾三行汇总指引拆进各标识的修复行。
- 受检文档缺失从“报错返回一”改为 DOC-INPUT 条目退出码三：文件不在场等于无法完成判定，按违规（一）处置会模糊“文档写错”与“门禁没跑成”的界线；登记表该行自首版即注明退出码三。
- 命令入口参数处理升级为退出码二语义（参数多于一个即用法错误）；清单枚举保留“非仓库根回退工作区遍历”的降级路径不动——自测夹具多数不是版本库，改走失败关闭会全数破坏该路径。

## 横幅与收尾随统一出口迁移（2026-10-29）

- 通过态补横幅、失败收尾改经统一收尾出口（`gate_report` 的 `banner`／`finish`）：六条文本门禁的横幅有无此前不一致，并轨输出的分段标记补齐；通过行、判定面与退出码语义不变。
