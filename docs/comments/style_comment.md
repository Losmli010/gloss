# ui/style.rs 设计取舍

## 为什么阶梯语义命名而不是数字命名（S12/S10…）

数字命名一改值就全体改名，语义名稳定；档位的「用在哪儿」写在每个常量的文档注释里。同值合并的取舍：音标(13)并入 NOTICE、释义(14)并入 BODY、按钮/词性/例句/头部标签(12)并入 CAPTION——原 popup.rs 六个字号常量本就是「值不同的阶梯档位」，收编后按角色归档，值零变化。将来某角色需要独立出档时，从阶梯加新档并改引用即可。

## 为什么设置提示文案与浮层圆点共用 ACCENT

settings.rs 的 notice 颜色与 popup.rs 的 BRAND_DOT 是同一个值 `#D85A30`（品牌珊瑚橙的两次独立硬编码）。集中化把它们合成一个语义 token。若将来提示文案想换更刺眼的警示色，应新开 token（如 WARN）而不是直接改 ACCENT。

## 为什么设置大区块间距(10)与浮层分区间距(12)不共用一档

两窗口视觉节奏不同（浮层内容紧凑单卡、设置窗分区留白更松），强行统一就是改视觉、违反快照零变化验收。阶梯里 SECTION(12) 与 GROUP(10) 并存，文档注释写明各自的使用窗口。

## 为什么有 ladder 严格递减测试

阶梯的契约是「档位有序且不塌缩」——将来加 token 时若两档撞值，说明要么是笔误要么该合并档位，测试当场暴露。它不锁具体像素值（像素由快照锁），只锁阶梯结构。

## 范围裁决

- 浮层宽度档位（380/480/滞回阈值）是**布局行为**不是样式，留在 popup.rs。
- 动画时长（APPEAR_SECONDS）不是样式，留在 popup.rs。
- 设置输入框宽度（160/110）是控件尺寸、单窗口私有，留在 settings.rs 原处。
- 头部圆点几何（8px 分配、4px 半径）是绘制细节、单点使用，留在 header() 内联。
- Spinner 尺寸是 `font::TAG + 5.0` 的派生表达式——跟随标签档位，不单独设档。

## 设置窗 TIGHT/ITEM 档位落点的布局方向坑（评审整改时确认）

settings 的 draw 用 `bottom_up` 布局：**先画的在底部**。视觉自上而下实际是
「滚动区 → ITEM 6px → 提示行 → TIGHT 4px → 动作行」。token 文档因此按
「X 与 Y 之间」措辞，不写「上方/下方」——按绘制顺序读会读反。首轮评审对
TIGHT 落点（提示行上方）的认定即因此读反，整改时一并纠正为「提示行与动作
行之间」。

## 头部动作图标字形尺寸（2026-09-21 T5）

popup.rs 的 `ACTION_ICON_SIZE`（16px）沿用「窗口私有量不进阶梯」裁决：它是单窗口单区域的图标字形尺寸，不是两窗共用的文本阶梯档位；进阶梯反而诱导设置窗误用。模块文档的私有量清单已同步补举此例。

## 错误色 DANGER（2026-09-22 T7）

owner 拍板错误色与品牌色分离：新增 `color::DANGER`（#C62828，与 ACCENT
同饱和度带的正红），用于设置页校验下划线/就地提示/汇总行与保存失败等
运行时提示。ACCENT 收窄为品牌场景（浮层圆点、保存主按钮）。原「设置
提示文案用 ACCENT」的口径就此废止。

## 强调色并入朱砂色板（2026-10-02）

品牌从珊瑚橙换纸墨朱砂后，ACCENT 单档装不下「同一色相明暗两读」——
拆为 `ACCENT_LIGHT`/`ACCENT_DARK`（别名 `SEAL_ZHU_LIGHT`/`SEAL_ZHU_DARK`，
不另存值）。消费点不再直接引常量，走 settings.rs 的 `accent(ui)` 按
`dark_mode` 取档：浅底用压暗档、深底用提亮档。设色逻辑从此与印章
（`seal_zhu`）同构：强调色＝朱砂，只是一次换装、不是新语义。上文
「ACCENT 收窄为品牌场景」的口径不变，值与取色方式随本条更新。

## 阶梯与颜色 token 的用途注记（迁自各常量文档注释）

- font 阶梯（px，从大到小四档）：`TITLE` 标题（正文标题、自检强调行）；
  `NOTICE` 次要说明（流式来源、失败提示、音标、自检行）；`CAPTION` 弱化
  小字（动作按钮、词性、例句、设置区块标与行内提示）；`TAG` 标签（任务
  类型标签、输入源标签）。
- space 阶梯（px，从大到小五档）：`SECTION` 分区之间（浮层标题行与正文
  分区之间）；`PARAGRAPH` 段落之间（浮层正文分区之间、设置网格列距）；
  `ITEM` 条目之间（释义组之间、设置网格行距、设置提示行与滚动区之间）；
  `TIGHT` 紧邻元素（设置子分组之间、设置提示行与动作行之间）；`INLINE`
  行内（例句行之间）；`CARD_PADDING` 浮层卡片 Frame 的内边距。
- `radius::CARD` 浮层卡片圆角；`stroke::CARD` 浮层卡片框线宽。
- color 语义 token：`ACCENT_LIGHT`/`ACCENT_DARK` 品牌强调色（朱砂·明暗
  两档）——设置保存主按钮与开关钮的着轨，与印章、朱丝栏、品牌划线同一
  色板，压暗到白底/提亮到深底可读；`DANGER` 错误色——设置页校验失败的
  下划线与就地提示、校验汇总行，与朱砂强调色同饱和度带的正红，明暗主题
  下均可读；`SEAL_ZHU_LIGHT`/`SEAL_ZHU_DARK` 朱砂——经注疏印章的实心印
  与朱丝栏的线色源；`CODE_BG_LIGHT`/`CODE_BG_DARK` 代码面板底色——经位
  代码面板专属底（demo code-bg #f5f7f9 / #16181e），以底色本身与近隐形
  边从卡片上定界；`CODE_BORDER_LIGHT` 代码面板边色（浅色）——demo
  card-border 的 10% 墨色（预乘 rgb(2,2,3)），近隐形的定界，不与卡片框线
  争抢；`CODE_BORDER_DARK`（深色）——demo card-border 的 9% 白（预乘）。
