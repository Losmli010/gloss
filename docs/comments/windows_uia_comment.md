## UiaReader（2026-11-06，Windows 移植 P2①；同日评审整改为惰性创建）

- 选区文本主路：读取器不持有任何系统状态——自动化对象在每次读取的调用
  内创建、调用内释放（对象与接口指针都是套间亲和的：绑定库的接口类型不是
  Send，持有即跨线程；而文本取材端口带发送约束（`TextAcquirer: Send`），
  取材通道要随装配句柄从主线程整体移交事件线程，两者不可两立）。逐读创建
  让读取器构造零系统调用、跨线程移交零系统指针，与系统（macOS）读取器
  逐读创建系统级元素的形态同构；创建与使用同线程同调用，套间与线程固定
  要求由构造内生满足。整改缘由（2026-11-06 评审，两轮）：初版在构造里
  急切创建（CoCreateInstance）落在主线程——winit 不在主线程初始化组件
  对象模型（COM），创建将拿到未初始化错误，主路静默失效、全部划词降级
  剪贴板注入兜底；二版改惰性槽仍持接口指针，在 P1 的发送约束下根本编不
  过（指针非 Send），且即便能过也构成指针跨线程移交。逐读创建是约束下的
  唯一同时满足三方（套间亲和、发送约束、装配移交）的形态。
- 逐读创建的代价（写明的取舍）：每次取材多一次进程内对象创建（类对象在
  进程内有缓存，成本远小于同调用的跨进程读取），取材节奏是人的手势级，
  不在热路径；换得的是零跨线程状态、零不安全发送实现。
- 错误映射（`interpret`）：有非空文本直读采纳；空串＝属性在而无选区→空
  选区错误（组合通道先让渡补读）；空值（超上限拒取）与错误码（文本模式
  缺席、调用失败）→读取不可用（组合通道落兜底）。系统（Windows）无授权
  门，权限拒绝语义不存在——组合通道没有“权限缺失不兜底”分支。

## MAX_SELECTION_BYTES

- 选区文本字节上限（二百五十六kibibyte）：与系统（macOS）读取器同值；
  超限按读取不可用上抛，不为超大选区扩流式通道。
- 常量落点随取材字节预算单源（2026-11-14，方案 A4）：定义上移平台中立
  共享层（common/image.rs，与图片取材字节预算同处单源），本模块经共享层
  引用；与系统（macOS）读取器同值的口径由单源直接保证。
