- 线性轴刻度：`top = 4 × nice(peak/4)`（档位 1/1.2/1.5/2/2.5/3/4/5/6/8×10^k，
  与 demo 逐面板核对一致）；预算值计入 peak，另加「预算线不得贴顶」递推——
  预算恰等于 top 时（如 show 面板 100/100）升一档（→120），否则渐晕区高度为
  0、预算线压轴，视觉失效。count 面板 step 下限 1，防 0.8 类碎刻度。
  负值扩展（评审指出净增长类可为负、负点会画出 0 轴压进 x 轴标签区）：有负
  值时轴向下按同 step 整数倍延伸（lo = -⌈|vmin|/step⌉·step），0 轴保持在
  网格线上并沿用深色轴线语义，网格线数量 = 5 + 负向档数；无负值时 lo=0，
  映射与布局与原 0 基轴形态逐字节一致（改造后真实 fixture 三图 sha 不变验证）。
  同一意见引出的伴随修正：变化行方向曾按 (cur-prev)/prev 定号，负值基线下
  符号翻转（净增长 -340→-520 是改善却标 ▲ 红），改为方向按数值本身比较、
  幅度 = |Δ|/|prev|——正基线行为逐字节不变，负基线方向归正（单测 8 例：
  负基线改善/回归、持平、正基线回归、prev=0）。
- 预算状态 chip 只按注册表中 judge=预算门禁 的系列判定（app.startup_ms 等
  仅记录同面板系列不参与）；预算系列缺数据时不挂状态 chip（宁缺勿谎），
  预算 chip 与红虚线照挂——预算数值来自点 budgets 段，与该点有无测量值独立；
  history 连 budgets 段都还没有（预算值未入库，T2 合入后首个折算点入库前的
  真实状态）时挂「预算未入库」chip——评审前曾回退挂「仅记录」，与同卡
  「预算常量：…」小字自相矛盾，评审指出后改为显式未入库语义（不挂仅记录、
  不画红线，常量名小字照挂：常量是静态代码事实，与数据无关）。

  4.2 要求图面不堆砌文字，任务卡要求标常量名，图例行右端是 demo 已有的

## 产物与确定性（2026-10-05）

- SVG 而非 PNG 入库：文本可 diff、GitHub 直接渲染、可用 qlmanage 预览；图表是
  基线 JSON 的派生工件，随 `just perf-baseline` 重绘。SVG 里不含生成时刻——
  core 图的环境行取自 JSON 的 env 字段（快照时固化），同一 JSON 重绘逐字节
  一致，diff 只反映数据变化。
- 纯标准库无 matplotlib：仓库 Python 脚本均零第三方依赖（bench-summary.py 先例），
  CI 无需装环境。

## 两张图的口径（2026-10-05）

- clone-stats.svg 三面板：crate 计数（线性）、热点分配次数（线性）、分配字节
  （对数——22 B 到 57 KB 跨三个数量级，线性会让小值不可见）；每行精确标注数值。
- core-baseline.svg 按基准组分面板（cache_key/complete/prompt_render/task_cache），
  组内线性条宽 + 人类可读时长（ns/µs/ms 自适应）；页头必带环境行（时间/系统/
  CPU/rustc/commit）——墙钟数字离开环境无意义（AGENTS.md「数字连同运行环境
  一起记录」）。core 图**只记录不判罚**：墙钟有噪声，判定归 criterion 自身机制
  （bench-check 的 95% 区间），与「基准不是门禁」同一口径。

## 布局教训（2026-10-05，视觉验收四轮后定稿）

- 数值与单位必须单锚点输出：双 text 锚点（752/756）在渲染端叠印不可读。
- SVG 开标签的 height 依赖布局结果，先收集 parts、末尾统一拼装；不要先插占位
  再字符串替换——常量改动会让替换查找串失配，产物静默变 height="0"（空图根因）；
  `</svg>` 同理由返回处统一补，避免遗漏（XML 非法、渲染中断的根因）。
- 交付前过一遍真实渲染（qlmanage 转 PNG + 视觉验收）：Python 侧「生成成功」
  与「渲染正确」是两件事。

## 趋势化改造（2026-10-05 第二版，需求反馈后重设计）

- 需求两条：可视化要**连续曲线**；clone 要**整体情况**、不铺明细。图表从条形
  改为趋势曲线：数据源改为 baselines/history.jsonl（perf-history.py 每次
  perf-baseline 追加一个快照点，commit 去重）；单快照=单点是预期形态，随基线
  更新逐点延展。
- clone 面板收敛为四条整体聚合线：总数、密度、热点分配次数合计、分配字节
  合计——分配合计是跨六项基准的**指数**（每迭代之和），不是物理量，只作
  趋势相对比较；每 crate / 每基准明细退回 JSON 与 PR 表格。
- core 保持明细：按基准组分面板，线=基准，组内对数纵轴（cache_key 跨
  ns→ms），图例 4 列；环境行取 core-baseline.json 的 env 字段，拆两行防右缘
  截断（clone 摘要行同理拆两行）。
- 布局教训（视觉验收四轮）：①面板内点位必须加 plot_y 偏移——scale 只算面板
  内偏移时点会全画到画布顶部（负坐标标注还被顶缘裁掉）；②同一 x 列的标注
  自下而上保持 13px 垂直间距去重叠；③去重叠后标注会压到别的系列的标记上，
  标注加白色衬底（halo）最后绘制才干净；④摘要/环境行长度按「960px 画布 ×
  ~0.58em/字符」估算，长行一律拆行。

## 验证管线陷阱（2026-10-05，两点曲线验收时发现）

- `qlmanage -t` 生成**正方形**缩略图时按 cover-crop 处理：宽扁 SVG 左右各裁约
  53px、高瘦 SVG 上下裁切——曾把完好的右端点/标注误判成「右缘裁切」。复核用
  等比补白副本（把 viewBox 高度补到与宽度相同再渲染）后再下结论；GitHub 按
  SVG 声明宽高比渲染，无此问题。
- 趋势图只在线的**最新一点**标数值（趋势图惯例，点多后逐点标注会糊）；x 轴
  commit 标注补足定位信息。

## 文件头迁出的用法与图目（2026-10-24，注释纪律）

- 用法：`scripts/perf/perf-chart.py` 读 baselines/history.jsonl 重绘三图；
  `--history H --out D` 覆盖数据/输出目录（本地验收用）。
- 三图实名：`perf-latency.svg`（响应性：启动耗时 / 划词→首帧 / 隐藏延迟与动画帧时间 /
  外部依赖·LLM 延迟（仅记录不判罚））、`perf-resources.svg`（资源与体积：稳态内存 /
  显隐 RSS 净增长 / 处理器 / 二进制体积 / 窗口句柄数）、`perf-hotpath.svg`（热路径：
  core 四组分面板（组内对数轴）+ clone 分配合计与 clone 计数密度）。
- 峰值类指标 `rss_peak` / `footprint_peak` 与 `frame_missed` 不入图，仅在
  perf-report 总览表呈现。
- 起始提交小字的避让实现在 `_partial_note`。
- 状态 chip 判定口径实名：只按注册表中 `judge=预算门禁` 的系列判定。
