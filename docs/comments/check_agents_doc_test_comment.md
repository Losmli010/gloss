## 反馈契约三件套（2026-10-26，gate-pr4）

- 报告格式：违规行首匹配 `error[大写标识]` 且带（`路径:行号`）位置段，证据行与修复行在场；五类违规标识各一条的夹具断言标识全集（DOC-INPUT 走退出码三的独立夹具）。
- 汇总数＝明细数：汇总行的 N 等于实际打印的违规行数（夹具为五）。
- 确定性：同一夹具两次运行，标准输出与标准错误逐字节一致。
- 退出码语义：违规夹具一、用法夹具（参数多于一个）二、受检文档缺失三、干净夹具零。
- 前置守卫用进程内断言：受检文档缺失抛系统退出且码为三。

## 跟踪清单枚举失败关闭（2026-11-14，方案 F3）

- 夹具建仓 helper（init_repo）：`git init` 加全量 `add -A`，check 与 run_gate 两个入口助手统一调用——枚举失败关闭后夹具必须有跟踪清单，判定面与持续集成同口径；“未跟踪文件判违规”“非英文字节名原样枚举”两例保持自有建仓形态（选择性 add），语义不变。
- 失败关闭两例：进程内（run 抛系统退出码三）与子进程端到端（退出码三、标准错误带 `error[INFRA]: git command failed`）各一，端到端例即“单独运行时 git 失败退出码为三”的验收锁定（方案 P1）。
- “受检文档缺失”端到端例的夹具不建仓即退出三（DOC-INPUT 前置守卫先触发），两失败关闭路径互不掩盖。
