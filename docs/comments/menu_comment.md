## 为什么自建菜单（install）

- 2026-10-29 应用菜单随系统语言本地化，并新增“设置”项直开设置窗。窗口库（winit）的缺省菜单词条硬编码英文（About/Services/Hide/Quit 等），且窗口库 0.30 未公开菜单应用程序接口（API）——自建是唯一路。菜单经系统框架（AppKit）绑定在平台层整体装配：词条、分隔、服务子菜单、快捷键（设置 ⌘,、隐藏 ⌘H、隐藏其他 ⌥⌘H、退出 ⌘Q）一次装齐，`NSApp.setMainMenu` 整体替换缺省菜单。
- 2026-11-03 词条“设置…”去省略号（用户反馈：该项开窗即达，不是弹出后续对话框的项），中英两表同步为“设置”/“Settings”。
- 装配点在应用壳 `init`（事件循环启动后）：缺省菜单在事件循环启动时安装，先装会被盖掉；壳侧另以 `with_default_menu(false)` 关掉缺省菜单，免英文菜单闪帧。
- 系统语言在装配时读定（进程启动期一次），不随设置页的界面语言热切——菜单是系统壳层件，语言口径与提示词模板的“跟随系统”同源（locale 模块同一份判定）；系统语言变更需重启，与该模块口径一致。
- 词条常量落在平台层而非应用文案表：装配发生在应用文案表装入点之前，且平台层依赖方向不允许反向读应用层资源；以 `i18n:allow` 放行标记显式豁免文案门禁，中文词条仍守“纯中文”语言规范（有测试锁定）。词条表住处（2026-11-14，方案 A7 随 P2）：双语表与档位查取上移平台中立共享层（common），本模块按装配所需词条取用，缘由随词条表迁入共享词条记录。

## SettingsAction（菜单动作目标）

- 设置项的动作目标是自定义 `NSObject` 子类，实例变量收 `Box<dyn Fn() + Send>` 回调，动作方法 `glossOpenSettings:` 直呼回调。壳侧回调经 `EventLoopProxy` 送 `UserEvent::OpenSettings`（见 events 记录）。
- `NSMenuItem` 对 target 持弱引用（AppKit 的 `unsafe_unretained` 约定），回调对象必须自持：存主线程 `thread_local` 槽——菜单与动作只在主线程触发，主线程存活即进程存活，与菜单同寿命；重装菜单覆盖槽位，旧对象随新槽释放。

## install 的降级

- 离主线程返回 false（有测试锁定）：装配点在壳 `init`，恒在主线程，false 实际不可达；保留返回值是为把“装配失败”显式化，壳侧告警降级保缺省菜单（已关缺省时即无菜单，仍不崩）。

## 接入应用菜单装配端口（2026-11-05，Windows 移植 P1 · 方案 D4）

- 新增 `SystemMenuController` 实现核心层菜单装配端口，委托既有装配函数：回调从泛型参数改为装箱对象（对象安全所需），装配语义与降级布尔不变。

## on_quit 直通参数（2026-11-07，Windows 移植 P2④）

- 端口 `install` 新增 `on_quit` 回调（托盘退出项需要退出路径，见 ports 记录）；本实现不消费：退出走 AppKit 原生终止词条（`terminate:`），参数下划线收下不接线。
