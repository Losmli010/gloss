## 定位（执行编排）

- 对精选集逐条驱动一轮对话并调契约与评审结算，产出逐例明细与延迟样本；回归结算与产物落盘不在此——回归归流程装配层（计划依赖图：流程 → 回归、报告），执行不知资产存在。
- 轮数据一律经生产循环取得：分类走生产分类循环（含首项截止与修复预算），任务走生产任务修复循环加语言轮（与生产同一提示词渲染、同一校验入口），评测数字度量的才是生产行为。
- 延迟采样住执行：逐例端到端墙钟是实跑轨的采集面，采样器（`Latency`）从旧指标模块迁入——旧模块只剩采样器，按计划模块表执行编排持延迟类型，旧模块随之退役。

## drive_rounds（按子类分派）

- 分类与任务的分歧只有驱动一轮对话的那一个函数（计划 §一）：分派产出逐轮原文，后续契约结算、评审资格、明细组装全走同一条路径。
- 请求失败带痕迹降级：明细带引擎故障标记、轮轨迹置空、该例继续跑完——单例故障不中断一轮评估（长循环的健壮性优先于快速失败；故障在契约轴与聚合里可见）。请求失败时轮内半截文本不成轮，不进结算。

## settled_detail（结算组装）

- 回归字段恒置 `None`：回归判定是流程层拿基线与标注折算的，执行层无从判定——字段语义“空当且仅当契约故障”由流程层的调用序保证（先执行后回归结算）。
- 评审资格复用契约四态派生：评审关闭、分类用例、引擎故障、契约降级一律不打分；软缺口照评（结构化缺失计入完整性维度，不打分的是字段不在场以外的质量问题）。
- 评审请求失败或解析失败按 `None` 处理：该例在评审覆盖率分母里，缺评在报告可见——降级有痕迹（覆盖率掉），不伪造分数。

## RunCtx（上下文收口）

- 引擎句柄、模型标识与评审开关收进一个上下文小结构：驱动、结算、评审三段函数的参数面统一，避免参数清单随功能漂移。
