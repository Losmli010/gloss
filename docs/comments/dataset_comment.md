## EvalCase / Reference（用例定义类型）

- 用例定义住本模块、结算明细住 `detail.rs`：前者是评测的输入，后者是评测的产物，分属两层（计划 §五 硬规则）。
- `kind: EvalKind` 是明细层的子类词汇（分类是任务的子类），用例层复用它而非另立词表；`target: Lang` 是文件自然语名加载时映射的语言枚举。
- `Reference` 与理想产物同构：任务侧复用核心库 `OutcomeStructured`，评审拿到的参考答案与被评产物逐字段同形，四维打分有锚点；分类侧只考路由，仅持期望类别。
- `reply_json` 渲染生产词面：任务侧为注加疏证平面（JSON）对象（与任务校验器所吃形状一致，不带变体标签）；分类侧按分类回复词面渲染——通用任务在分类回复里叫 `Fallback`（生产校验器把 `Fallback` 映射通用），故期望通用时渲染 `{"kind":"Fallback"}`。

## load_curated / parse_curated（加载校验）

- 校验一次做全，即时失败带行号：标识唯一非空、类型合法（`Classify` 与四个文本任务子类；图像解读不在精选集——它没有文本输入可驱动）、目标语言为已知语名（当前仅中文）、参考答案按子类结构。
- 任务侧参考答案先过生产校验器 `schema::validate_task`（注非空、疏证按子类成形），再查子类必带键（词卡音标、代码代码语言）——生产校验器对缺键有缺省，参考答案作为理想产物不设缺省；键值为 `null` 仍算在场，与契约的字段完整检查同口径，保证每份参考答案都能通过自己用例的契约结算（该不变量由测试钉住）。
- 空数据集是硬错误：编译期嵌入路径断裂或资产清空不该静默产出零用例的一轮评估。

## EXPECTED_KINDS（期望类别合法域）

- 分类用例的期望类别限任务四名之一；图像解读不可指期望（它不进精选集）。合法域与计划 §二 的构成表一致。
