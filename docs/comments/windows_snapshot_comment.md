## snapshot_decision（2026-11-06，Windows 移植 P2①）

- 快照的放弃边界（与系统（macOS）同构、按系统（Windows）裁剪）：可读文本
  原样保全；板上无文本且格式计数为零＝确认的空板，按空板保全（恢复轮清
  板）；板上无文本但有格式（图片等非文本内容）无法如实写回——整体放弃、
  不注入（对应系统（macOS）“条目的风格全部读不出即整体放弃”：注入后原
  内容无法如实写回，恢复轮会清空剪贴板）；板状态读不出同样放弃。
- 与系统（macOS）的已知差异：快照只保全文本。系统（macOS）按条目与数据
  风格保全原始字节；系统（Windows）文本轮先走剪贴板库（arboard），多风格
  保全随图片取材阶段（P2③）评估——当前边界下“有图片就放弃兜底”比“注入
  再毁图”安全，牺牲的是图片板上的兜底可用性（主路不受影响）。
- 决策函数纯化（文本读取结果加格式清单查询两个入参）：单测以替身驱动全
  矩阵，不碰真板。

## PendingRestore

- 恢复收尾：`restore_now`（恢复并返回写盘数）与 `skip_restore`（明示不恢
  复）；Drop 时未明示即恢复——调用方崩溃路径的兜底（与系统（macOS）同形）。
  恢复失败经统一出口记错误（环节、写盘数），不恐慌不上抛。
