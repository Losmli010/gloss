## 被驱动面与桩形状（2026-11-18，架构重构方案 C3 线级验收）

- 被驱动面是方言中立的线级入口 `transport::send_with_retry`（生产客户端与线级测试
  共用同一发送序列）；不驱 LlmClient 门面——端点解析强制 https，明文回环桩进不去，
  而本地 TLS 桩需要改机器信任库，都不是测试该付的成本。端点/密钥解析已有配置层
  单测，本文件专补“流级单测覆盖不到的传输协议（HTTP）面”。
- 桩服务器是手搓的最小超文本传输（HTTP）/1.1 服务器（标准库套接字 + 保活循环），
  不引服务端框架：请求按内容长度整读，响应按分块传输编码（chunked）手写帧——
  桩要造的恰是分块边界与帧终结这些线上形态，框架反而挡住。
- 错误信封用例断言的是 `send_with_retry` 的返回错误而非流条目：非成功状态在流建立
  之前就终结请求（连接阶段），流条目错误只发生在流中途——两处出口在流级单测里各
  有锁定，本文件锁的是“真实状态码与真实响应体走线上”的那一半。
- 重试用例的 `retry-after: 0` 是刻意的：解析出零等待即零退避，用例不付墙钟成本，
  又真实走了 `Retry-After` 头解析与退避调度。
- 连接复用用例要求流把响应体读尽（终结帧排水）后连接才回连接池——它锁的就是
  传输层“终止后排水”这条口径，见 transport_comment.md 的 SseStream 节。
- 慢流用例停顿 1 秒是场景构造不是计时断言：断言的是“无总超时/读超时会杀活流”，
  机器越慢断言越容易过；静默悬死的终结（空闲看门狗）由流级单测以虚拟时钟锁定，
  本文件不付 60 秒墙钟也不在真实套接字上混虚拟时钟。
