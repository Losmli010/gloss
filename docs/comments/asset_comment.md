## 定位（运行时资产存储仓）

- 标注（labels.jsonl）、基线（golden.jsonl）与单次输出（iterate.outputs.jsonl）三类评测资产的唯一碰盘点：文件读写不外溢——回归结算只见类型（`LabelMap`、`GoldenMap`），执行编排不知资产存在，落库与固化的装配归流程层。
- 类型与读写同模块：计划依赖图以“资产类型 → 回归”与“流程 → 资产读写”分列两条边，落位在一个文件（类型是纯数据，读写是唯一输入输出面）。

## LabelRow / GoldenRow / OutputRow（行形状）

- 行形状即计划 §6.2 的文件契约：标注 `{id, verdict, note}`（`note` 可选，序列化缺席不带键）；基线 `{id, rounds, accepted_at}`，`rounds` 为逐轮原文的嵌套数组（外层轮次序、内层该轮文本分片、按序直连拼接）；单次输出与基线同形状无固化时间。
- `accepted_at` 随基线行携带而非落库时丢弃：检视页基线列要悬停展示固化时间，映射层丢掉它就断了数据血缘（计划 §6.7）。

## load_labels / load_golden（读）

- 文件缺失按空表处理：首轮无历史是常态，不是错误；坏行与未知道具拒绝（带行号）——评测资产是受控工件，静默跳过会污染回归判定（历史行加载的坏行容错是历史文件的语义，不适用资产）。

## upsert_labels / upsert_golden（合并写）

- 按条目以标识合并、后写覆盖先写；落盘按标识排序，文件内容确定性不随合并顺序漂移；一律原子写（复用历史层的原子写助手，临时文件加进程号后缀再改名）。

## read_outputs / write_outputs（单次输出）

- `read_outputs` 是固化的唯一输入，文件缺失当场报清晰错误并指明补救（先跑迭代）——固化出一份空基线是不可逆的静默损害；已存在但零行的文件读作零行（每次迭代覆盖写后的合法状态）。
- `write_outputs` 每次迭代覆盖写（不追加），仅成功用例落行由执行侧保证（契约故障无输出不落行，防固化失败输出）。
