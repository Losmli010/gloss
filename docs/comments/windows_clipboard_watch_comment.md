## 哨兵源桩（2026-11-05，Windows 移植 P0）

- 轮询恒空集：变更监视对应 Win32 `GetClipboardSequenceNumber` 轮询（保持 poll 形状），随 P2 落地；桩保留构造、观察句柄与轮次标记的同名镜像，组装段的取材管线可原样装配。

- 2026-11-05（P1）桩改实现核心层剪贴板监视端口：轮询恒产出空集；事件源（`EventSource`）镜像实现移除。

## 哨兵源实现（2026-11-07，Windows 移植 P2③）

- 状态机与系统（macOS）实现逐行同构（自节流、基线武装、开关与轮次闩锁的
  计数归因），唯一差异是注入的查询闭包：变更计数换成剪贴板序列号
  （`GetClipboardSequenceNumber`，纯元数据查询，无需开板），类型清单判定
  换成三图像格式的存在性查询（`IsClipboardFormatAvailable`，同样不开板、
  不取数据——系统（Windows）无“允许粘贴”授权流程，元数据查询零副作用）。
  判罚面按移植方案执行序 P2③ 的“保持 poll 形状”定案。
- `WatchRoundFlag` 从单元结构改为持轮次闩锁的真实结构（与系统（macOS）
  同形）：选区兜底（P2①）在真机上以自报写盘数归因注入与恢复写盘，桩的
  空实现会把自身写盘误判为用户复制；真实机的选区兜底活测（`#[ignore]`）
  依赖该归因。
- 测试名加 `seq_` 前缀：与系统（macOS）同文件名镜像（`watch`）跨文件同名
  无法用文件限定符区分（清单限定符按文件名主干绑定，两文件同主干），沿用
  选区兜底（P2①）的按测试主体前缀惯例，`seq` 指序列号这一变更源。
- 人工测试（`#[ignore]`）：真机写真实剪贴板（位图（CF_DIB）与便携式网络
  图形（PNG）注册格式各一轮）观察哨兵与取材读取器的端到端协作，步骤登记
  测试行为清单的人工测试节；写板助手在测试内以不安全块合成全局内存对象
  （仅测试目标编译，真机验证归第四层）。

## 活测写板失败的收板顺序（2026-11-07，移植评审遗留 C2）

- 活测辅助 `write_format` 的写板失败断言先前在 `CloseClipboard` 之前
  `expect`：失败即恐慌时进程内剪贴板保持打开，后续活测全部连坐失败。
  处置为先收板再断言——失败路径也走 `CloseClipboard`，写失败只让本条
  活测失败；仅影响 `#[ignore]` 的第四层（L4）真机目标，属卫生修复。
