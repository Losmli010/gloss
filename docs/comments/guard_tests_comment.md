## 2026-09-26 真机漏报后的用例补面

- 报障是“前台选中含 `sk-` 的假密钥没拦住”。补的四条各钉一个“用户实际会
  选中的样子”：`tokens_embedded_in_structured_text_are_detected`（JSON/查询
  串/URL/围栏里嵌着的令牌）、`short_dummy_keys_are_detected`（十几字符的手写
  假密钥与被换行截断的令牌）、`invisible_characters_do_not_hide_a_token`
  （零宽字符与软连字符）、以及反面的
  `hyphenated_words_are_not_mistaken_for_prefixed_tokens`（英文复合词不能
  因为含 `sk-` 就中）。四条都是变体验证过的：关掉短档、去掉“前面不是字母
  数字”的边界、去掉不可见字符剥离，各自让对应用例变红。
- 漏报的教训写在 guard_comment.md 的判据节：**判据的形状面必须按“用户会
  选中的样子”枚举一遍**（引号、括号、JSON、URL、换行、零宽字符、短串），
  只测“干净的单词令牌”会把最常见的几种整片漏掉。

## 为什么这批用例的**误报侧**比漏报侧更密

- 判据调紧（前缀更长、熵阈值更高）会让漏报变多，调松则误报变多。这里把
  测试重心放在误报侧：漏报是“少问一次”，误报是“用户被无端打断一次”，
  而这次修订后闸门对用户不可见、也关不掉：被挡住的人没有开关可关，只会认为
  划词坏了。因此
  `prose_about_tokens_is_not_a_hit`、`identifiers_and_prose_stay_below_the_entropy_threshold`、
  `ordinary_text_is_never_flagged` 三条各自钉一类**看起来像**但不是的内容
  （本仓库自己的文档原话 / 长标识符与散文 / 日常中英文本与代码片段）。
- `prose_about_tokens_is_not_a_hit` 的输入直接取自 `docs/11` 与 AGENTS.md 里
  描述本任务的原话（“`sk-`/`ghp_`/`AKIA` 前缀”这一类句子）。这不是凑数：
  它同时钉住了“阈值不能松到把这份文档自己判成敏感内容”这条底线，而这句
  话正是将来最有可能被抄进别处的一段文本。

## 形态说明

- 每条用例只断言一个判定面（场景闸门 / 前缀 / 熵 / Luhn / 顺序），不把多个
  判据混在一个用例里——判据之间是“或”关系，混在一起会让某条判据失效时
  测试依然绿。
- `card_numbers_pass_luhn_only` 同时给“差一位”与“全零”两个反例：前者钉
  Luhn 真的在算（不是“有 16 位数字就算卡号”），后者钉“至少两个不同数字”
  这条附加条件（全零串也过 Luhn）。
- `token_prefixes_are_detected` 的用例表同时钉**形态**与**前缀**两个维度：
  同一批前缀要分别以裸词、带引号包裹、`NAME=` 赋值三种形态出现。它当初红
  的第一条正是赋值形态（实现只认词首前缀，`.env` 行整片漏掉）——这条用例
  的价值不在“sk- 能被认出来”，而在覆盖用户实际复制的那几种排布。

## 夹具在运行时拼装，源码里不留密钥形状的字面量（2026-09-24）

- `filler` / `entropy_filler` 两个助手把“像令牌的长串”在运行时拼出来
  （`format!("sk-{body}")`），而不是写成整串字面量。原因有两条，第二条是硬的：
  1. `check_secrets.py` 按 provider 前缀扫**全部跟踪文件**（含测试），`sk-` 后
     接 20+ 个 `[A-Za-z0-9_-]` 就会命中——夹具与真泄漏在字面上无法区分；
  2. 该门禁的既定放行方式是行尾加 `secrets:allow` 并注明缘由，而**测试代码禁止
     注释**（AGENTS.md“注释纪律”）。两条规则在“测试里的假密钥”这一处正面
     冲突，运行时拼装是唯一同时满足两者的写法：既没有可被误判的字面量，也不
     需要在测试里写注释。
- `entropy_filler` 用固定步长在字母表里跳（而非顺序取前 N 个）：顺序取 52 个刚好
  落在大小写两段上、一个数字都没有，会被“三类字符齐备”这条判据挡下——第一版
  就是这么红的（`high_entropy_strings_are_detected`）。夹具本身要过判据，否则测的
  是夹具不是判据。
- `AKIA` / `xoxb-` / `Bearer` / PEM 四类夹具同理：前缀保留（不然测不到前缀判定），
  主体一律由助手生成；赋值形态用 `format!("GITHUB_TOKEN=ghp_{body}")` 现拼。
