# logging.py（约束门禁·日志）决策记录

> 按符号锚定（不写行号，防漂移）。改到相关检查时同步更新本文件。
> 本文件随仓库跟踪（docs/comments/ 入库），文件内不留指向本文件的指针。

## 约束“日志统一出口”（实现）

- 2026-09-18 日志三件套（tracing、tracing-appender、tracing-subscriber）只有核心库（gloss-core）可以依赖——它是唯一日志出口所在地；其余包直接依赖即违规。通过行按依赖条目属主去重计数。

## 与标准库日志模块同名（附录钦定的模块名）

- 2026-10-25 模块名按拆包方案附录钦定，与标准库日志模块同名。风险面（评审提出、已实测复现）：按路径直连执行包内命令入口时，解释器把包目录放进导入搜索路径首位，此后进程内任何对标准库日志模块的导入都会解析到本领域模块，并以相对导入错误当场崩溃。当前包内与直连执行进程无人导入标准库日志，故全绿。
- 约束：包内代码与直连执行形态的进程不得导入标准库日志模块；后续动包（共享层内容缓存、反馈迁移）时保持。若未来确需标准库日志，先改掉直连执行形态的搜索路径引导或本模块命名（需同步方案附录）。

## 约束“日志一律英文”（实现）

- 2026-09-18 日志要面向终端诊断、不做本地化，所以实参里出现非 ASCII 字节即违规。
- 判定实现：把源文件折成一行再抓日志宏的实参（到第一个右括号为止）；行内反引号与注释里的中文不受影响（不在宏实参里）。多行宏实参因此同样命中。

## 反馈迁移（2026-10-25，PR2c）

- 两条判罚各挂规则标识（日志出口、日志实参非英文），判罚消息去掉“constraint violation (xxx)”前缀；证据行完整不截断：出口判罚带完整依赖条目，实参判罚带完整宏实参。
- 日志实参判罚的行号取零：源文件折行扫描（多行宏实参命中）后行内位置不再对应原文行，虚报行号比不报更糟。
- 本模块与标准库日志模块同名，包内代码不得导入标准库日志模块——反馈迁移只增统一诊断出口导入，未触碰该约束。
