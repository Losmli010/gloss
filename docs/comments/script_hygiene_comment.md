## 落点与判罚面（2026-11-28 首版）

- 脚本卫生两规则落约束门禁子包的单模块双规则形态，与源码卫生平行（面向本语言源码）：标识 SCRIPT-DEP 管脚本桶间依赖，SCRIPT-BOOTSTRAP 管路径引导；判罚面是 scripts 树下全部 Python 文件，客户端钩子目录（.zcode/hooks/）不在重构面——其跨桶消费与自带引导属客户端约定路径的既有形态，不进本域判罚。
- 依赖判定只看生产脚本：测试的跨目录导入走包限定形态，随生产引导归位自然收敛，判了反而把测试侧的过渡插入重复计罚；引导判定看全部脚本，测试文件零插入是定案形态的一部分。

## 桶模型与依赖判定

- 桶按 scripts 的顶层目录划分（ci、dev、hooks、perf、release），scripts 根自身是单点小库桶；子包归属宿主桶（comments、constraints、language_spec 都算 hooks），不单独成桶。
- 跨桶导入的出边只开放 scripts 根：dev 桶与三个叶桶禁入。提供者按顶层导入名静态定位（模块文件按名登记、包目录的初始化文件按目录名登记）；提供者与导入方同桶、或存在 scripts 根提供者、或命中过渡白名单即放行——同名多桶并存按宽松处置（宁漏勿误，现实脚本面无遮蔽形态，多出的提供者只是保留合法的解析路径）；标准库与第三方（提供者缺席）不判。
- 脚本面缺席按跳过处置并照常出两条通过行：约束单测的假仓夹具没有 scripts 目录，失败关闭会把既有聚合单测全部打红；真实仓库的脚本面缺席意味着仓库形态根本改变，由其余门禁兜底。文件不可读与解析失败走基础设施条目（失败关闭），两类通过行同时缺席。

## 引导判定

- 目标按解析后的路径判定，不锁字面写法：静态解析走抽象语法树，名字查模块级赋值与 for 循环目标（同名重绑按并集近似——现实引导块一变量一赋值，并集不引入误判面），支持 os.path 家族（abspath、realpath、dirname、join、normpath）与 pathlib 家族（Path 构造、parents 下标、parent、resolve、除法拼接）。
- 字符串成分在拼接中保持相对形态，仍为相对的最终结果锚定脚本所在目录——运行时相对路径锚定当前工作目录，惯例引导全部自文件路径构建，两者在实际写法下同值；pathlib 的 parents 下标按 pathlib 语义折算（下标 n 自路径连取 n 加一次父目录，下标零即直接父目录）。
- 定案目标两类：子包文件的宿主桶根、跨桶单点导入的 scripts 根；同目录插入与桶根文件的桶根插入按冗余判罚（裸跑时路径首位与 pytest 自动插入已覆盖）；解析不了的目标即罚（失败关闭方向）——改惯例形态或行尾放行标记加同行缘由。
- 数量口径：插入调用计数按调用点（for 循环一处插两目标算一处），非测试文件至多一处；放行标记豁免目标分类，不豁免数量上限。标记缘由核对复用共享助手，缺缘由走通用域 ALLOW-REASON；标记只服务引导豁免现场，不进源码注释面的共享标记清单（对齐拉取请求快照标记的先例）。

## 过渡白名单

- 两规则各带显式过渡白名单，条目带缘由字段，与依赖单向化拉取请求的归位步骤一一对应：依赖三边（克隆门禁取版本单点、记录名门禁取命名映射、映射单点反向消费门禁基建），引导四处（映射单点插 hooks 桶、克隆门禁插 dev 桶、记录名门禁插 dev 桶、记录标点测试的函数体内插入）；白名单整段随该拉取请求删除。
- 任务清单的过渡口径只列两条 hooks 到 dev 的依赖边：映射单点反向消费门禁基建的 dev 到 hooks 边同样是现存存量，不放进白名单约束门禁即红、与红牌不进主分支的承诺冲突——按最小偏离补第三条，随映射单点归位一并删除。
- 引导白名单的测试插入按文件加解析目标锚定，不锚行号（上游记的行号随引导清理漂移，符号锚定不受影响）。
