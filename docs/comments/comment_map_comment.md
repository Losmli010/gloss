## 跟踪清单枚举委托统一出口（2026-11-14，方案 F3）

- `tracked_files` 委托 `gate_report.tracked_files`：`git ls-files -z` 加空字节分割与容错解码此前在多脚本各写一遍，本模块是其中一处且在门禁消费方直调时裸抛 `CalledProcessError`（不经统一退出码）；委托后 git 失败按无法完成判定失败关闭——统一诊断出口打 `error[INFRA]` 条目、退出码三，命令行与门禁消费方看到同一失败形态。
- 命令行入口（main）原先的 try/except 打一行消息返回三随之移除：失败打印与退出码全走统一出口，本模块不再自带第二套基础设施失败形态。
- `detect_root` 的“脱离版本库退回工作目录”是显式降级（探测失败本身不算故障），保留不动；随后的清单枚举在非版本库目录照常失败关闭，两段语义不冲突。
- 本模块（scripts/dev/）引入 scripts/hooks/ 的共享模块经显式 `sys.path` 注入，与注释纪律门禁的记录名检查（check_record_names）同款做法。
