# events（系统（Windows）平台事件线程）测试记录

> 按符号锚定（不写行号，防漂移）。改到相关测试时同步更新本文件。
> 测试代码禁止注释（AGENTS.md“注释纪律”节），测试的验收意图与辅助契约记录在此。

## 测试目标与层

- 第一层（L1）：抽干结构（tick、guarded、汇点）与泵宿主的组装行为，进程内
  时序，不碰真实窗口服务的可见性（泵线程与定时器是进程内真实线程，属
  第一层的组装测试面，与系统（macOS）目录同口径）。
- 名称前缀（`pump_`、裸 `tick_`）：与系统（macOS）目录的同构测试互相区分
  （清单限定名唯一按文件绑定，系统目录同短名不可重名，见 check_test_bdd
  的限定符绑定规则——两平台同名文件的限定符同为目录名，无法消歧，故以
  行为规格前缀区分）。

## 辅助契约

- `tick_drains_commands_before_polling_sources`：命令队列先于事件源抽干，
  一命令一事件。
- `pump_*` 组：真实泵线程上命令按序消费、迟来命令仍被消费、事件源轮询与
  转发、回调与源恐慌不杀线程（恢复后继续）、汇点容忍关闭的接收端、成功
  发送唤醒主线程而失败发送不唤醒。
