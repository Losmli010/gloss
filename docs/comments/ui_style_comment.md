## 为什么把样式边界钉成门禁

样式统一（docs/plans/style-unification-design.md）把深浅色解析、字体族
构造与设计常数收进样式层后，边界全靠约定迟早被照抄破掉——按「能自动化
的新检查项优先补门禁」原则落成约束门禁的界面样式域四条检查，与本地
提交前门禁、持续集成同源。

## 四条检查的口径与取舍

- 语义色（`UI-STYLE-COLOR`）：界面库色构造只在 `ui/style/palette.rs`。
  只匹配色类型的构造调用，图像数据容器的同名构造（图标与截图解码）
  不同名不误报；色板自身是唯一定稿点。
- 明暗态（`UI-STYLE-DARK`）：明暗只在 `ui/style/mod.rs` 的解析点读一次。
  调色板数据上的判别字段（`is_dark`）不是界面库明暗态，不误报。
- 字体族（`UI-STYLE-FONT`）：字体句柄构造只在字体基建（`fonts.rs` 与
  `fonts/imp.rs`）与排印模块。测试模块整体不在受检面（生产行按测试
  模块标记截断），代码高亮测试的等宽构造属测试目标，天然放行。
- 设计常数（`UI-STYLE-CONST`）：界面层生产代码的常数声明若含数值字面量
  即拦，除非住样式层六文件或登记在非设计常数白名单。对档位的算术
  （如 `FOOTER_HEIGHT + PARAGRAPH`）不含字面量，天然放行；类型名里的
  数字（如 `Color32`）按词边界匹配不误报。

## 非设计常数白名单（登记表）

- `ui/fonts/imp.rs`：系统字体探测打分与字节面数上限——算法阈值，无设计语义。
- `ui/i18n.rs`：文案资产装入——内容表，非几何。
- `ui/code_hl/`：语言别名表、语法名表与作用域映射表——语言资产表。
- `ui/popup/icon.rs`：图标栅格化的画布几何——资产几何，随图标源定稿。

白名单外的文件出现数值常数即被拦：要么是设计常数该迁样式层，要么是
新的非设计常数该在此补登记——两态必居其一，不允许不登记的第三态。

## 豁免标记

`style:allow` 是本域的放行标记（登记进统一诊断出口的标记清单），设计
文档原提复用上下文域的 `constraints:allow-context`，实施时改为独立
标记——语义各归其域，缘由机器判定机制共用。
