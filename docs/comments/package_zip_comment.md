## 载荷面：可执行文件加旁置动态库（2026-11-07，Windows 移植 P3a）

- 只收可执行文件本体与同目录旁置的动态库（dll），其余构建目录的散文件一律不进包——发布目录里混进的杂散文件会跟着自更新换装进用户目录，清单面按扩展名与本体名收紧。
- 旁置动态库按显式放行名单收口（2026-11-07，移植评审遗留 E4）：只按扩展名
  放行曾把构建目录里的杂散动态库（合成实跑出现过的 `legacy_helper.dll`）
  打进包，随自更新落到用户安装位。处置为 `--allow-dll` 显式参数（可重复，
  缺省为空，大小写不敏感）：名单外的动态库与放行而缺位的动态库都显式报错
  不打包——发布链路当 loud 失败而不是静默多装；当前构建无旁置动态库，
  发布工作流不传旗标即为空名单。单测（`package_zip_test.py`）钉：空名单
  无动态库、放行收入、大小写不敏感、杂散拒绝、放行缺位拒绝、重复旗标
  单条目（名单可重复传参，解析边界即去重，载荷清单不因重复旗标出重复
  条目——2026-11-07 评审补充）。
- 包根平铺（不带顶层目录）：自更新的载荷定位按可执行文件名在解包现场搜索、不假设层数，两种结构都成立；平铺是最小形态，用户解压即用。

## cargo-bundle 不支持 Windows，便携 zip 即最终产物（2026-11-07）

- 系统（macOS）的分发走应用包加镜像（dmg）；系统（Windows）本期只有便携压缩包（zip），NSIS/WiX 安装包按移植方案后置另立计划——本脚本是发布链在系统（Windows）侧的打包单点，与解压端（更新模块共享核心）的载荷结构契约同源。
- 压缩形态用 deflate，与解压端开启的特性面对齐；产物名沿用版本加目标三元组口径（`gen_manifest.py` 的产物齐备检查同款命名），清单扩展归 D8。
