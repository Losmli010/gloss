# check_commit_msg.py 决策记录

## 头部（本地钩子不做消息校验）

- 2026-09-18 原因：git 跑 pre-commit 时消息还没落盘，读到的会是上一条提交的消息。
- 2026-09-30 缺口改由 `.githooks/commit-msg` 补上（PR #80 的 CI message 返工暴露）：commit-msg 阶段消息已写入 `$1` 文件，正是落定后、提交完成前的可校验时机。钩子只做转发（调本脚本），merge commit 的自动消息跳过——与 CI 校验的 `--no-merges` 口径一致，squash 后的 PR 标题另有一道。pre-commit 不做消息校验的结论不变，两条钩子各守各的阶段。

## MAX_SUBJECT_LEN = 81

- 2026-09-18 81 = 72 + 9：为中日韩标题多留 3 个汉字的余量（混合中英文标题在 72 下屡屡触线），对纯 ASCII 标题几乎无感。

## 空行判定用 awk NF

- 2026-09-18 原因：跨平台（GNU/BSD/mawk）行为一致，避免 sed 的 `[[:space:]]` 字符类在不同 locale/sed 实现下的差异。

## 注释行剥离仅限多行输入（PR #97）

- 2026-10-02 原因：`#` 剥离服务的是 git 编辑器场景——COMMIT_EDITMSG 里 git 追加的注释块。单行输入没有注释区，`#` 是标题本身（issue 引用式 PR 标题如 `#97: xxx`），此前被剥掉后误报「commit message 为空」。判据用行数而非调用方显式开关：脚本无法感知调用语境（git 钩子/CI/手动），而「单行 = 无正文 = 无注释区」在三种语境下都成立；git 场景下纯注释单行原先报「为空」、现报「格式不符」，都是拒绝，语义只更准确。

## 三个消费方（头注不再写路径，注释纪律门禁只许纯中文）

- 2026-10-24 本地提交钩子 `.githooks/commit-msg`；ZCode 客户端 PR 标题钩子 `.zcode/hooks/check_pr_title.py`；CI 的 Commit message check job。
- 2026-10-25 消费面细分：钩子与客户端标题钩子只调校验函数 `run()`；命令行入口 `main(argv)` 的多文件形态只服务 CI——持续集成把一次推送或拉取请求的全部消息各落一个临时文件后一次进程吃进（配套钩子工作流并作业），免逐提交起解释器。

## LIST_ENTRY_RE（正文清单条目的类型前缀豁免）

- 2026-10-25 起因：PR #229 压缩合并后推送门禁误拦合并提交——GitHub 生成压缩提交信息时可把拉取请求内各提交的主题列成清单写进正文，条目形如 `* refactor(comments): 中文主题`；主题行的类型前缀本有豁免，正文清单行没有，前缀字母被中文书写规则判成外文字母。
- 决策：条目前缀按主题行同规剥掉再判罚——清单是托管平台生成的结构性内容，不是作者表述；类型沿用 `ALLOWED_TYPES` 白名单加可选范围与叹号，比主题行的任意小写词更收紧，条目符号认 `*`、`-`、`+` 也可缺省。条目前缀之外的正文照旧逐行受检（英文残留、非白名单类型、含空格范围仍拒）。
- 关联豁免：`ISSUE_SUFFIX_RE` 剥主题尾编号后缀，`TRAILER_RE` 放行版本库尾注——三者同属结构性要素豁免。

## 多文件命令行入口（判定口径零变更）

- 2026-10-25 起因：钩子工作流并作业的配套小项——提交信息作业原逐提交起一次解释器，改为一次进程吃进全部消息。
- 决策：`main(argv)` 遍历参数里的全部路径逐条送 `run()`，逐条输出与单文件调用逐字一致（成功打勾行、失败整块错误报告）；任一违规整体退出 1、全部通过退出 0、零参数退出 2。`run()`、`split_message()`、`prose_problems()` 一字未动，单文件与标准输入减号形态行为不变。
- 聚合语义取舍：旧循环在首条违规即被 `bash -e` 拦停，新形态先报全部违规再退出——被拦的集合不变，反馈更完整；CI 只看退出码，无下游解析输出。

## run() 违规列表与六标识（反馈迁移）

- 2026-10-26 起因：门禁失败反馈标准化——诊断要带稳定规则标识，退出码与输出出口全脚本统一，`run()` 从单错误串改为违规列表（`COMMIT-EMPTY`、`COMMIT-FORMAT`、`COMMIT-SUBJECT`、`COMMIT-LENGTH`、`COMMIT-BLANK-LINE`、`COMMIT-PROSE` 六标识，登记于统一登记表）。
- 判定口径不变式：`findings()` 保留原单错误串的短路顺序——空、格式、主题、长度、空行逐关放行，书写规则殿后；一关不过不判后关，与旧实现报告的违规集合逐一相同。书写规则的底层条目（语言规范库的书写判罚）统一归入 `COMMIT-PROSE` 标识，消息、证据与补救随条目保留。
- 输出出口：命令行入口与本地提交钩子都经统一诊断出口逐条打印（标识、位置、证据行、修复指引）加末尾汇总；钩子的用户可见形态保持——前置空行、拦截横幅与尾部补救指引三段不变，中间的诊断块从旧自由文本换成统一格式。

## simulate_squash 合并模拟单点（收敛四处抄写）

- 2026-10-26 起因：编号后缀占位的拼装此前抄写在四处（拉取请求内容门禁、客户端标题钩子、持续集成提交信息作业的落盘行），改占位形态要四处同步；开发方案第五节裁决五把它并入本次迁移收敛为单点。
- 决策：`simulate_squash(title)` 是唯一拼装处——标题剥首尾空白后追加五位编号占位；拉取请求内容门禁与客户端钩子在进程内改调它，持续集成作业经命令行的合并模拟形态（`--simulate-squash` 旗标传入标题、打印模拟消息落盘）改调它，与其余消息同一进程吃进。占位文本只在本模块与测试夹具中出现，客户端钩子与工作流不再各抄一份。
- 行为差异说明：客户端钩子原先不剥标题首尾空白、内容门禁剥；单点统一为剥（客户端钩子的标题入参本就先剥过，实际输入下无差异）；持续集成作业从壳层字符串拼接改为经脚本输出，尾部换行形态不变。
