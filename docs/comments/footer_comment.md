## footer.rs 的由来（2026-10-27，自 card.rs 拆出）

- 页脚原本只有“生成指示 + 水印”两种静态内容；发送前确认方案给它加了
  第一批**交互出口**（待确认卡的确认/取消、完成卡的复制钮），card.rs 同
  步触及 500 行上限的行数纪律。按“页脚带 = 一个自洽部件”整段迁出，
  发丝线与 galley 缓存基建留在 card.rs（`pub(super)` 供本文件取用）。

## `FooterMode`

- 页脚形态：`Static`（自检/降级/失败卡等静态带）、`Streaming { repairing }`
  （生成指示 + 呼吸点，`repairing` 区分“正在注疏/重新注疏”）、`Pending`
  （确认/取消按钮组）、`Done { unverified }`（复制钮，语言降级加校对徽章）。
  形态枚举由视图层（views.rs）按卡片变体选定，页脚内部不再读视图——选词
  与选形态两件事分属两层。
- 为什么是枚举而不是 `Option<Action>` 式回调：页脚的交互出口只有两处且
  各自的绘制形态完全不同（按钮组 vs 图标钮），枚举让 `match` 穷尽每一
  形态的绘制分支，新增形态时编译器强制补齐。

## `footer`

- 页脚带（常驻）：上缘细线，左端随 `FooterMode` 变化，右端恒为 Gloss
  水印。返回本帧页脚上交的动作（确认/取消/复制，其余形态 `None`）——
  与正文动作在 `scrolled_card` 合并后透传给调用方。
- 带内各要素（状态文案与呼吸点、按钮组、图标钮、水印）统一垂直居中于
  带体——细带只有一条中轴语汇；个别要素曾对发丝线做半像素下移补偿，
  随居中定稿去除，全部以带体几何中心定位。

## `footer_confirm`（待确认卡按钮组，2026-10-27）

- 朱砂实心“注疏”主按钮 + 弱色“取消”次按钮：主按钮用印色实心是
  “唯一前进出口”的视觉权重（取消等价于头部 × 走共用收起路径，视觉
  主动降级）；圆角取 `radius::SEAL`（与印章同一圆角语汇）。
- 按钮内边距走全局按钮档（`TIGHT`）：曾改界面库的 `small()` 形态（垂直
  内边距清零）救窄带溢出，2026-10-27 评审定稿回归常规内边距——按钮更
  饱满，高出带体的部分落在卡片底部内边距里，不出窗不遮挡。
- 按钮组的绘制区域相对页脚带整体下移一档 `space::TIGHT`（4.5 像素，
  2026-10-27 评审定稿，曾用 `ITEM` 档）：不留位移时按钮上缘几乎贴住
  分割线；下移后上缘留出约三像素空隙，带体不可见底缘下方由卡片底部
  内边距承接，不会出窗。
- 无障碍标签即按钮文案（egui Button 自带）——kittest 测试按“注疏/取消”
  定位（见 `pending_card_exposes_the_source_and_its_two_exits`）。

## `footer_copy`（完成态卡复制钮，2026-10-27）

- 方块命中区（带高扣边距，与确认钮同高）内自绘复制图标；点击置
  `RenderState.copied_at`（居内时间）并上交 `OverlayAction::CopyAnnotation`
  ——**写剪贴板不在页脚做**：浮层只渲染、不副作用，平台触点收在壳层
  （见 actions 记录的 `copy_annotation`）。
- “已复制”反馈：`copied_at` 在 `motion::COPY_FEEDBACK`（1.6 秒）内视为
  在反馈期——图标翻朱砂对勾、右侧出“已复制”小字、请求帧节拍重绘推进
  倒计时；反馈过期自然回落图标态，不常驻不占位。时长放动效档（不是常
  量就地写死）：反馈是动效语义，调档只看 motion。
- 为什么反馈状态放 `RenderState`（`Cell<Option<f64>>`）而不是视图：
  反馈跨帧驻留（点击后若干帧内持续），视图是纯展示形态、每帧重建；
  跨帧的渲染态住 `RenderState` 与纹理缓存同一去处。居内时间（`i.time`）
  而非墙钟：kittest 的固定时间让快照与测试确定性可复现。
- 图标矢量现画（两片圆角方块叠置，前片以窗底色填充遮住后片被叠部分）
  不依赖字形：内置字体里没有语义稳定的复制/对勾字形，靠 Unicode 字形会
  随字体表漂移。圆角取 `radius::ICON` 小圆角档——曾用 `radius::SEAL`，
  其值恰为方块边长一半，方被圆角吃成两个圆环（评审截图实证）；描边取
  `stroke::LINE` 细线档——初版粗线，评审定稿回细，细带里的图标不复用
  页头关闭 × 的粗细语汇；两片方块的联合边界以命中区中心对中（曾按后片
  方框定位，错位使视觉中心偏上）。臂长统一 `ICON_ARM`（原 `CLOSE_ARM`
  改名收编：关闭 × 与复制方块同一臂长档，一族矢量图标一个几何语汇）。
  命中区取带高扣 `INLINE` 边距（22 像素方）：图标本体 16 像素上下，细带
  里给点击与悬停留足余量；命中区与按钮组同规，相对页脚带整体下移一档
  `space::TIGHT`，两处交互出口相对分割线的空隙一致。

## `footer_unverified` / `paint_alert_icon`（完成态卡校对徽章，2026-10-28）

- 语言降级（`degraded` 且内容完整）时页脚左端出琥珀三角徽章，标记由
  `FooterMode::Done { unverified }` 承载、视图层传 `outcome.degraded`：
  提示落在状态带而不在正文——修复轮的进行时叙事（“重新注疏”）本就住
  页脚，修复失败的结局落回同一处；正文首行让给内容。
- 徽章是纯信息件：`Sense::hover` 不可点击，悬停出提示词条
  （`gloss_popup_output_unverified`，随语言整句交付）；无障碍标签取
  短词条（`gloss_popup_output_unverified_label`）。不挂重试：与失败卡
  不同，重试会丢掉已有的可用内容，重新划词就是天然出口。
- 图标矢量现画（三角轮廓加感叹，闭合折线带圆角连接），与复制方块同一
  `ICON_ARM` 臂长档、`stroke::LINE` 细线档；琥珀色走新语义档
  `Palette.warn`（明暗两份数据，语义色只在调色板定稿）。
- 平台限制记录：完整提示句只产视觉悬停层，该版本界面库的 tooltip 不入
  `WidgetInfo`——读屏用户只拿到短标签，非遗漏。

## `footer_status` / `footer_dots` / `footer_watermark`（自 card.rs 迁入）

- 行为与原记录一致（见 card_comment.md 的迁移注记与既有规格）：状态文案
  与呼吸点仅在推理中请求动画；水印走 Label 进无障碍树、槽宽按实测宽加
  余量、直接吃缓存槽里的 galley。文案词条随 2026-10-27 的注疏改名更新
  （正在注疏/重新注疏），缓存键是 `'static` 标签本体，改名自动换键重排。

## footer_annotation / paint_annotation_icon（降级批注方案 §4，2026-10-30）

- 2026-10-30 批注图标移位与改形制（取代上节“完成态卡校对徽章”的位次与
  形制定稿，悬停词条键与无障碍标签沿用）：自复制钮**之前**移到**之后**
  （附属信息不占主动作前位，间隔取 `space::TIGHT` 档）；形制自警告三角改
  **批注气泡**（圆角气泡内两行字样、左下尾角，“旁批即对话”的评论语汇，
  与失败卡的警示语汇分家）；色随复制钮同一套着重规则（常态弱色、悬停与
  按下转强），不再取 `warn` 语义档——`warn` 档保留给失败卡与异常提示。
- 悬停分派（判据在 views.rs，随 `FooterMode::Done` 传明细）：清单非空出
  文案表标题（弱色）加行清单（常规色），字号取 `size::TAG` 档，宽度交给
  界面库 tooltip 自适应；清单为空（契约无效直降、旧缓存条目、注册表缺键）
  回落现泛化文案，键与值都不动。展开方向向下——窗口为批注卡在页脚之下
  留余量（见 geometry 记录），不因此改回向上遮挡正文。
- “已复制”瞬态反馈接排在批注图标之后，瞬态信息恒在最右，与常驻批注
  互不挪位。
- `FooterMode::Done` 增 `violations` 明细列（`Option<Vec<String>>`）并随之
  失去 `Copy`（明细随帧重建，视图层按产物现算现传）。
