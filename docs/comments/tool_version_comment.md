# tool_version.py 决策记录

> 按符号锚定（不写行号，防漂移）。改到相关段落时同步更新本文件。
> 本文件随仓库跟踪（docs/comments/ 入库），文件内不留指向本文件的指针。

## 存在缘由

- 2026-10-25 钉版本的安装与校验此前散在工作流与环境初始化脚本两处，双源漂移即“本地过、远端挂”。收敛为仓库根版本清单（`tools.toml`）单点：持续集成安装步骤经命令替换读本助手取钉版本（`pip install ruff==$(python3 scripts/dev/tool_version.py ruff)` 与 `npm install -g tombi@$(...)` 同款），环境初始化校验经 `parse_sections` 直接消费同一文件。升级只改清单一行。

## 为什么手写 `parse_sections` 而不用标准库解析器

- 门禁与脚本的解释器下限是 3.8（本机系统解释器即 3.8.2），标准库解析模块要 3.11 才有；引入第三方解析依赖又违背“运行器自带解释器零新依赖”。手写行扫描只认“段头”与“单行字符串赋值”两种结构——版本清单自持且体量极小，这个子集够用；同款先例是发布标签校验脚本解析根清单工作区段的写法。
- 非字母数字的值原样保留（`floating = true` 解析成字符串 `true`），调用方自行解释；清单结构坏了不静默——消费端取不到钉版本就按缺件报错，安装步骤当场失败。

## 条目形态（清单语义）

- `version = "x.y.z"`：钉全版本，消费方全等比对（环境初始化）或精确安装（持续集成）。
- `min = "x.y"`：记下限，环境初始化按不小于校验（当前只有解释器条目）。
- `floating = true`：显式浮动，只校验在场、不比对版本；缘由写在条目注释（just：命令入口只分发配方不参与判定；pytest：运行器不承载判定，断言在各检查器自身）。
- 本语言（Rust）不进清单：原生钉版本文件（`rust-toolchain.toml`）是唯一权威，工作流用 `rustup toolchain install` 按文件解析安装（裸 `rustup show` 依赖已弃用的自动安装，实测弃用告警后弃用）。
- ripgrep 暂未入列：密钥门禁改道落地时随其工具链配套增补。

## 退出码

- 0＝打印钉版本（标准输出只有版本串，供命令替换消费）；1＝该工具不在清单或未钉全版本（报错进标准错误）；2＝用法错误。
