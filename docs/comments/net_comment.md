## MAX_MANIFEST_BYTES

- 清单是几百字节级的小文档，1 MiB 已远超合理尺寸；按块累计、超限即断，因而 content-length 缺省时上限照样生效。

## fetch_manifest（拉取并解析更新清单）

- 只认 200 与 UTF-8，body 按块累计、超限即断。
- 分块累计、超限即断：content-length 缺省（HTTP/2 常见）时上限照样生效，不给无界缓冲留入口。

## shared_client（进程内唯一的 HTTP 客户端）

- 建连/读超时、明确 UA、不跟随重定向（重定向会把请求交给别的宿主，破坏「清单与产物都来自 https」的假设）。macOS 上构建要解析整套信任设置（秒级 CPU），故只建一次常驻。
- 先构建：失败直接传播且不污染缓存，下次任务重试自然重建。get_or_init 只认胜者：并发首建时输家的这份被丢弃。
