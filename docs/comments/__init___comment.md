## 头部（不覆盖哪些约束，以及为什么）

- 2026-09-18 纯 Rust 技术栈：按项目决定只作口头约束，不落门禁——这类判断发生在“要不要引入这个新依赖”的评审现场，枚举包名的 deny 名单覆盖不了没见过的运行时。
- 2026-09-18 组装点唯一：“是否持有组装逻辑”没法靠模式匹配可靠判定（构造适配器的写法无穷），硬造门禁只会变成误报源，留人工评审。
- 2026-09-18 注释纪律：要判的是语义（有没有澄清情况、有没有跟代码打架），措辞层面扫不出来；能扫的少数形态（任务编号与待办标记词）在实际代码里是合法写法。留人工评审。
- 2026-09-18 生产路径传播错误 / unsafe 有据 / 公共 API 有文档注释：均已由 clippy 与 rustc 的 deny 级 lint 承担，见 AGENTS.md 的“门禁对照”表。

## 拆包口径（纯移动＋接口化）

- 2026-10-25 拆包自原单文件门禁脚本：判定串、判罚消息与通过行全部逐字保留；聚合保持“通过与失败两个清单”的返回形态——违规随执行流即时打到标准错误，通过项由命令入口汇总打印，退出码零一语义不变。规则标识、守卫与统一诊断出口随后续反馈迁移落在各领域模块上。
- 2026-10-25 领域模块聚合序为：架构、日志、界面边界、清单卫生、源码卫生。通过行与违规行的输出顺序随模块序重排（最显著的是“桩副本一致”一行从第三位移到第十位）；无任何消费方依赖行序——测试按内容断言、并轨入口与持续集成只看退出码。
- 2026-10-25 各领域模块自带同形运行入口（仓库根＋可选内容装入器），可独立驱动（各域单测即这样用）；清单扫描与源码遍历住共享清单扫描模块。内容缓存已于同日落共享层：聚合入口缺省自建单次扫描缓存（清单与文件各只读一次，同一文件每层只开一次），装入器在场时共享其缓存；单模块直跑仍各自读取。
- 2026-10-25 命令入口在包内独立文件：按路径直接执行与按模块方式调用等价；仓库根缺省按入口文件位置向上回溯三级。
- 2026-10-25 反馈迁移（PR2c）：命令入口的参数处理升级为全脚本统一的退出码二语义（多参与根不存在打用法行），与密钥门禁同形；违规汇总行走统一诊断出口的汇总行（计数＝已打印明细数），其后保留既有两条“修代码或先改文档”的指路行；单文件报告超限的剩余数声明紧随汇总行之前打出。
- 2026-10-25 运行入口增可选报告器参数：报告器承载即时打印与返回清单两面，聚合与各领域模块共享同一实例——单文件上限与剩余数声明因此逐次扫描成立（每聚合运行一个报告器）。
- 2026-10-25 聚合入口（模块注册表、聚合序与条件通过行）由路由聚合单测锁定：基线夹具断言十二条通过行齐全且序固定，违规夹具断言判罚穿透聚合——受检面缩水即变红。

## 横幅与收尾随统一出口迁移（2026-10-29）

- 横幅改经统一出口（`gate_report` 的 `banner`）打印，聚合运行入口不再内联拼装——横幅归命令入口（与其余文本门禁同形），聚合运行入口只做判定聚合。
- 失败收尾（空行、汇总、剩余数声明、两条指路行）改经统一收尾出口（`gate_report` 的 `finish`）单点打出；剩余数声明的落点从汇总行之前移到之后——声明与汇总行仍相邻，“汇总数＝已打印明细数”的动机不变，声明行文的精确数口径不变。

- 领域聚合增第七域：语言规范单源（constraints/langspec，规则 LANGSPEC-LITERAL），聚合序为架构、日志、语言规范、界面边界、界面样式、清单卫生、源码卫生；路由聚合单测的通过行词干清单与通过计数断言随域扩改。
