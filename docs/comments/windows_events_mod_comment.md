## 消息泵宿主（2026-11-06，Windows 移植 P2①，替换同日 P0 桩）

- 与系统（macOS）运行循环宿主同构的抽干结构：命令（通道2）先于事件源
  轮询，恐慌不穿线程边界（`guarded` 包裹回调与源轮询），源产物经汇点回传
  并唤醒主线程。宿主差异只在机制：系统（macOS）跑运行循环（CFRunLoop）
  加周期定时器，系统（Windows）跑消息泵（`GetMessageW`）加线程队列定时器
  （`WM_TIMER` 节拍，约三十三毫秒，系统合并同类节拍）。泵的退出条件是
  通道 2（取材命令）的接收端断开：节拍抽干报 `Disconnected` 即跳出泵循环，
  与模块头的通道 2 口径一致（2026-11-07 评审遗留 B4 改准，先前误写为
  通道三——通道 3 是主线程到异步后台的命令通道，与本线程无关）。
- 启动序里的组件对象模型（COM）单线程套间（STA）初始化：选区文本主路
  （用户界面自动化（UIA））要求套间与调用线程固定（移植方案 §6），全部
  读取调用发生在本线程；初始化失败只降级 UIA 通道，不阻断事件线程。
  泵循环对非节拍消息照常转译分派（单线程套间的跨套间调用依赖消息泵运转）。
- 线程名沿用 `gloss-event`；鼠标监听在独立线程（见鼠标手势源记录）。
  节拍消息的标识取定时器创建的返回值（系统可改派，见外部函数接口钩子
  记录），按申请值比对会让宿主在取消息上无限阻塞（2026-11-06 真机测试
  作业挂起的根因）。

## 共享形状迁往事件线程骨架（2026-11-07，移植评审遗留 A1）

- 事件源契约（`EventSource`）、汇点（`EventSink`）、线程句柄
  （`EventThread`）、`spawn`、恐慌屏障（`guarded`）与节拍抽干（`tick`）
  是两平台完全一致的平台无关形状，原各持一份完整拷贝、无门禁锁同文；
  处置为抽到平台无关共享模块（`gloss-platform/src/event_thread.rs`），
  两侧引用之——抽取可行的原因是差异面只在运行循环宿主（运行循环
  （CFRunLoop）定时器对消息泵），线程名、节拍周期（`TICK_MS`）与日志口径
  一并收拢。`spawn` 经函数指针注入各平台的运行循环，公开签名不变。
  纯共享行为的三条单测（抽干顺序、汇点容忍关闭、成功发送唤醒）随代码
  迁入骨架模块，两平台各自保留泵宿主端到端的五条。
