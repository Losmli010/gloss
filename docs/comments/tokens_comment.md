## 为什么阶梯语义命名而不是数字命名（S12/S10…）

数字命名一改值就全体改名，语义名稳定；档位的「用在哪儿」写在记录文件（用途注记节）。同值合并的取舍：音标(13)并入 NOTICE、释义(14)并入 BODY、按钮/词性/例句/头部标签(12)并入 CAPTION——原 popup.rs 六个字号常量本就是「值不同的阶梯档位」，收编后按角色归档，值零变化。将来某角色需要独立出档时，从阶梯加新档并改引用即可。

## 为什么设置大区块间距(10)与浮层分区间距(12)不共用一档

两窗口视觉节奏不同（浮层内容紧凑单卡、设置窗分区留白更松），强行统一就是改视觉、违反快照零变化验收。阶梯里 SECTION(12) 与 GROUP(10) 并存，用途注记写明各自的使用窗口。

## 为什么有 ladder 严格递减测试

阶梯的契约是「档位有序且不塌缩」——将来加 token 时若两档撞值，说明要么是笔误要么该合并档位，测试当场暴露。它不锁具体像素值（像素由快照锁），只锁阶梯结构。

## 范围裁决（原 ui/style.rs 时期，后续样式统一再收编）

- 浮层宽度档位（380/480/滞回阈值）是**布局行为**不是样式，留在 popup.rs。
- 动画时长（APPEAR_SECONDS）不是样式，留在 popup.rs。
- 设置输入框宽度（160/110）是控件尺寸、单窗口私有，留在 settings.rs 原处。
- 头部圆点几何（8px 分配、4px 半径）是绘制细节、单点使用，留在 header() 内联。
- Spinner 尺寸是 `font::TAG + 5.0` 的派生表达式——跟随标签档位，不单独设档。
- 头部动作图标字形尺寸 ACTION_ICON_SIZE（16px）沿用「窗口私有量不进阶梯」裁决：它是单窗口单区域的图标字形尺寸，不是两窗共用的文本阶梯档位；进阶梯反而诱导设置窗误用。

## 设置窗 TIGHT/ITEM 档位落点的布局方向坑（评审整改时确认）

settings 的 draw 用 `bottom_up` 布局：**先画的在底部**。视觉自上而下实际是
「滚动区 → ITEM 6px → 提示行 → TIGHT 4px → 动作行」。token 文档因此按
「X 与 Y 之间」措辞，不写「上方/下方」——按绘制顺序读会读反。首轮评审对
TIGHT 落点（提示行上方）的认定即因此读反，整改时一并纠正为「提示行与动作
行之间」。

## 阶梯 token 的用途注记（迁自原 ui/style.rs 各常量文档注释）

- font 阶梯（px，从大到小四档）：`TITLE` 标题（正文标题、自检强调行）；
  `NOTICE` 次要说明（流式来源、失败提示、音标、自检行）；`CAPTION` 弱化
  小字（动作按钮、词性、例句、设置区块标与行内提示）；`TAG` 标签（任务
  类型标签、输入源标签）。
- space 阶梯（px，从大到小五档）：`SECTION` 分区之间（浮层标题行与正文
  分区之间）；`PARAGRAPH` 段落之间（浮层正文分区之间、设置网格列距）；
  `ITEM` 条目之间（释义组之间、设置网格行距、设置提示行与滚动区之间）；
  `TIGHT` 紧邻元素（设置子分组之间、设置提示行与动作行之间）；`INLINE`
  行内（例句行之间）；`CARD_PADDING` 浮层卡片 Frame 的内边距。
- `radius::CARD` 浮层卡片圆角；`stroke::CARD` 浮层卡片框线宽。

## 拆分沿革（2026-10-27 样式统一阶段 1）

原 `ui/style.rs` 拆为 `ui/style/{mod, tokens}.rs`：阶梯（font/space/radius/stroke）原样搬入 tokens.rs，颜色语义留在 style/mod.rs；阶梯单测随迁，快照基线不动。上述「范围裁决」是拆分前的窗口私有量政策，按样式统一设计（docs/plans/style-unification-design.md）该政策废止，控件几何与动效将在后续阶段收编进 style/，届时逐条更新。

## rem 再定稿（2026-10-27 样式统一阶段 4）

空间尺寸的唯一设计单位改为根相对字号（rem，0.125 网格），解析根住样式
出口（初值 12px，接用户字号或缩放时是唯一改动点）。间距与圆角档位按
设计对照表再定稿：SECTION 12（12）、CARD_PADDING 13.5（14）、PARAGRAPH
7.5（8）、ITEM 6（6）、TIGHT 4.5（4）、INLINE 1.5（2）；radius::SEAL 4.5
（5）、SHIMMER 4.5（4）、CARD 7.5（8）、CODE_PANEL 10.5（10）。描边与
发丝线是像素例外（渲染意图，不随字号缩放），三档收编登记：HAIRLINE
0.5（原 stroke::CARD）、LINE 1（代码面板边）、THICK 2（关闭叉与朱丝栏）。
类型统一为 f32（原 i8/u8）；界面库的整型口径（Margin i8、CornerRadius
u8）在消费点就近取整，是渲染边界的实现细节。
