## 清单数据格式的表述词路（2026-11-02，语言规范治本方案第二期随改）

- 行内注释“标准输出只含数据格式（JSON）”在存量迁移中改写为“标准输出只含 JSON 数据格式”：`JSON` 已登记裸用（裸词加盘古空格），塞括号不补译名的退化形态按锚点硬规则照拦，登记词裸用是正路。
- 发布脚本与其它脚本同一注释判罚面，不因产物数据格式另开口径。

## 发布矩阵平台条件化（2026-11-07，Windows 移植 P3/D8.2）

- **产物齐备矩阵单点**：`PLATFORM_EXTS`（target → 应交产物扩展名）是发布
  矩阵的唯一事实源，`TARGETS` 由它派生（`tuple(PLATFORM_EXTS)`）——双
  darwin 各要 zip 与 dmg，`x86_64-pc-windows-msvc` 只要 zip（便携压缩包即
  最终产物，安装器 NSIS 后置另立计划）。齐备性检查按平台查表，缺文件即
  失败的口径不变。
- **条目字段按平台条件化**：`entry_for` 只在平台矩阵含 dmg 时写
  `dmg_url`——Windows 条目恰为 `url/size/sha256` 三键，不带安装器字段；
  客户端校验对象（zip 的 size/sha256）与 schema（保持 1）都不变，老版本
  读新清单不受影响（未知键与未知字段同样被忽略）。
