# ui/popup/image.rs 决策记录

## `decode_attached`（经位附件图像解码）

- 独立成模块而非并入 icon.rs：icon 的解码含画布比例裁剪（Dock 图标专
  用），图像卡的解码是原样 RGBA 容器——共享的只有 `load_from_memory`
  一行，合并反而把两种降级语义搅在一起。
- 参数收 `&Arc<[u8]>` 而非 `&[u8]`：告警里要记字节长度，`Arc` 直取免得
  调用方两处解引用；更主要是与 `RenderState::attached_texture` 的指针
  身份缓存口径对齐（解码失败的 None 也与这份 `Arc` 绑定）。
- 失败告警只含 `len` 与错误本体：红线（§6）要求图像内容与字节不落日志，
  长度与像素尺寸是允许的元数据面；错误消息是 image crate 的格式描述，
  不含像素数据。
- 不复用 icon 的 `OnceLock` 全进程缓存：附件图像按会话换新（指针身份
  缓存在 `RenderState`），全进程单例语义不成立。
- 解码经位附件图像（剪贴板取材产物，平台侧已做过尺寸设界）；失败隔离
  降级——记一条只含字节长度的告警（图像内容不落日志），绘制侧落占位，
  不影响其余内容。参数化 PNG 来源，解码与降级分支可经 L1 测试直接驱动。
