# rumdl.toml 决策记录

> 按符号锚定（不写行号，防漂移）。改到相关段落时同步更新本文件。
> 本文件随仓库跟踪（docs/comments/ 入库），文件内不留指向本文件的指针。

## 工具选型（2026-10-26）

- 选 rumdl（Rust 单二进制、检查与格式化二合一、规则集与 markdownlint 高度兼容）
  而非 mdformat 加 pymarkdownlnt（两条 Python 工具）或 markdownlint-cli2 加
  prettier（Node 栈）：单工具撑起 fmt-md 与 lint-md 一对配方，接入模式与 ripgrep
  同款（钉全版本、uv/pip 渠道、CI 免编译装轮子）。pre-1.0 的行为漂移风险由钉
  版本单点兜住。
- 版本钉 0.3.0（PyPI 与 crates.io 同源），升级只翻 tools.toml 一处。

## 受检面

- 任务配方用 `git ls-files '*.md'` 圈定：进版本库的标记语言文档统一受检，未跟踪
  的本地记录（docs/comments 等）不进判定面，本地与 CI 看同一批文件。
- 提示词目录（crates/*/prompts、gloss-eval/prompts）一并进排版面：模型资产字节
  即语义是排除注释书写纪律的缘由，排版规则（空行、列表、围栏）不改语义；评测
  回放按用例编号匹配夹具、不按提示词内容做键，格式化不破坏评测轨（用户决策）。
- 拉取请求模板与测试行为清单照常受检：模板必需小节核对与行为清单双向核对都只
  认标题文本与表格行，格式化不动这些键。

## 规则取舍

- 关 `MD013`（行长上限）：中文无空格折行，行长无判定意义；长表格行与清单行属
  常态，放开后 124 处命中全是此类。
- 关 `MD041`（首行须一级标题）：提示词以指令正文起头、拉取请求模板以二级标题
  起头，都是有意为之；改文档迁就规则等于给模型资产加内容。
- 其余规则全开，含结构三罚的对应规则（`MD001` 标题递进、`MD024` 重名标题、
  `MD046` 未闭合围栏——第三罚在工具侧可自动修复）：自注释门禁移交而来，移交
  时全仓存量已清零（234 处自动修复加两处手修，含 bdd.md 一节缩进混排的手修）。
- 已知盲区：rumdl 的围栏开合翻位与注释门禁逐行遍历的翻位口径未必逐点一致
  （信息串带属性等边缘形态），两边同时跑、口径漂移时以显式失败暴露，不静默。
- 口径差异两条（评审注记）：重名标题（`MD024`）按规范化文本比对（忽略大小写
  与空白差异），比旧自研的逐字匹配更严，且不可自动修复、须手改标题——嫌严可
  配 `MD024.siblings_only` 并在此注明缘由；标题递进（`MD001`）修 `general.md`
  跳级后，该卡的次级标题升为二级，与其余无一级标题的提示词卡（次级标题从三
  级起）层级形态不一致——各卡层级是卡自有形态，不强行拉齐。
