## 验收意图

- 摘要配方锁定为登记的 recipe（标题、单换行、正文逐字节进哈希），标题或正文任一
  变化必改摘要，空正文折算空串并入配方——配方漂移即基线整体失效，这是快照可信
  的根，配方测试逐字节断言。
- 计划指定的三条样例各落一处：改写红灯在比对决策层断言（当前摘要异于快照且无豁
  免，产出快照规则条目、不重写）；恢复转绿断言当前摘要与快照一致放行且零条目；
  豁免改写后基线更新落两层——比对决策层断言豁免返回重写动作，打桩主流程断言重
  写调用收到的摘要恰为当前正文摘要（基线跟手，不是旧值）。
- 豁免解析逐形态：标记加缘由有效、标记缺缘由给通用缺缘由条目且豁免无效、反引号
  包裹与裸形态等价、首行之外的标记不构成豁免、无标记无条目。
- 失败关闭两条：头提交无快照条目按基础设施退出码三（绝不因没检查到而放行）；描
  述字段残缺与载荷形态不对同样失败关闭。
- 命令行端到端锁定用法退出码（缺参与未知模式都是二），是工作流两步骤的调用契约。

## 辅助契约

- 托管平台交互全部经模块属性打桩（pytest 的 monkeypatch），测试不触网不调命令行
  工具：桩接在取数、重写与快照读取三个接缝，仓库标识一并打桩，工作区离开版本库
  上下文也可复跑。
- 比对决策是纯函数（当前摘要、快照摘要、正文三元进，动作与条目出），主流程只做
  输入输出编排——红灯与转绿的判罚事实全部在纯函数层锁定，打桩主流程只补副作用
  （重写调用、退出码）。
- 打桩用例兼锁退出码三态与违规输出进标准错误（统一诊断出口的契约），重写调用清
  单为空断言「红灯不重写基线」——基线只随有效豁免与写入事件移动。
