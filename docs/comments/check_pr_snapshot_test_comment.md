## 验收意图

- 摘要配方锁定为登记的 recipe（标题、单换行、正文逐字节进哈希），标题或正文任一
  变化必改摘要，空正文折算空串并入配方——配方漂移即基线整体失效，这是快照可信
  的根，配方测试逐字节断言。
- 计划指定的三条样例各落两层：比对决策层（生产路径 main 经同一函数决策）断言
  改写红灯（当前摘要异于快照且无豁免，产出快照规则条目、不重写）、恢复转绿（当
  前摘要与快照一致放行且零条目）与豁免返回重写动作；打桩主流程断言豁免重写调用
  收到的摘要恰为当前正文摘要（基线跟手，不是旧值）。两层锁定同一份生产代码，决
  策漂移即两层同红。
- 豁免解析逐形态：首行起头的标记加缘由有效、标记缺缘由给通用缺缘由条目且豁免无
  效、反引号包裹与裸形态等价、标记不在首行起始（首行中途提及、被写进句子、作更
  长标识符前缀）不构成豁免也无条目、无标记无条目。
- 失败关闭两条：头提交无快照条目按基础设施退出码三（绝不因没检查到而放行）；描
  述字段残缺与载荷形态不对同样失败关闭。
- 命令行端到端锁定用法退出码（缺参与未知模式都是二），是工作流两步骤的调用契约。

## 辅助契约

- 托管平台交互全部经模块属性打桩（pytest 的 monkeypatch），测试不触网不调命令行
  工具：桩接在取数、重写与快照读取三个接缝，仓库标识一并打桩，工作区离开版本库
  上下文也可复跑。
- 比对决策是纯函数（当前摘要、正文与惰性取快照回调三元进，动作与条目出），生产
  路径 main 经同一函数决策、自身只做输入输出与退出码编排——判罚事实与生产执行
  共用一份代码，纯函数层与打桩主流程两层互为印证；豁免在场断言回调不触发（不需
  要快照），快照读取报错在决策层折算为基础设施条目、由 main 按条目规则定退出码。
- 打桩用例兼锁退出码三态与违规输出进标准错误（统一诊断出口的契约），重写调用清
  单为空断言「红灯不重写基线」——基线只随有效豁免与写入事件移动。
