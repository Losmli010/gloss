# scripts/hooks/check_i18n.py 决策记录

## 扫描面只取 gloss-app src 与根包 src（2026-10-01，feat/i18n-gate）

界面文案表（i18n/*.toml + Text）只服务应用界面；其余 crate 的 locale 文本各有所属：
gloss-core 的 prompt 面向模型（`classify_allowed_block` 的分任务描述按 locale 内嵌是
既定形态）、gloss-eval 是开发工具的中文 CLI 输出、gloss-platform/gloss-core 的字符串
是日志诊断（英文，`for_error` 的映射表在 gloss-app 侧把变体翻成文案）。全仓扫描会让
三个 crate 永久挂满豁免，等于把扫描面缩回 gloss-app 还多背噪声，故直接收窄。

## 词法判罚面与豁免面

- 属性 `#[...]` 内部整体不判罚：`reason = "中文"` 是 lint 理由（开发者面向的元信息），
  逐行加 allow 标记会训练出豁免疲劳。属性内的字符串仍参与 `]` 配对的跳过。
- `#[cfg(test)]` 修饰的 mod 项按花括号配对整体跳过，闭合后恢复扫描——测试断言按
  惯例用中文钉文案；且 gloss-app/src/lib.rs 的测试模块不在文件尾（`mod stubs` 在
  头部、windows.rs 有两个测试模块），按标记行裁到 EOF 会漏掉模块后的生产代码。
- 只识别字面 `cfg(test)`（空白归一后）。`cfg(not(test))` / `cfg(all(test, …))` 不在
  跳过面——宁可多判不可漏判，命中可就地 allow 或改写。
- char 字面量与生命周期的区分靠三字符前瞻（`'x'` vs `'a`）；`\u{…}` 转义写法的非
  ASCII 在源码层是 ASCII，文本上不可见，属评审面。

## i18n:allow 的语义

同 secrets:allow：只放行所在行（python 侧按命中行过滤）。首批评过的合法字面量：
⚙ 图标字形、例句列表的 `·` 前缀、自检卡的 pangram 字样——都是符号/夹具而非词条。
列表符号不能进文案表还有一层：`every_entry_is_translated` 要求 en≠zh，符号类词条
两份值必然相同，结构上进不去。

## 真违规的修复路径示范（同 PR 落地）

popup.rs 的「凡 N 言 · N 行」小记原是 `format!` 硬编码，已搬进文案表
（gloss_popup_seal_note，zh/en 各一条带 {{chars}}/{{lines}} 占位符），Text 补字段、
i18n.rs 的钉数测试 99→100、templated 清单同步——这正是门禁失败信息里给出的修复路径。

## 扫描面扩展至 gloss-core 与 gloss-platform（2026-10-01，同 PR 跟进 commit）

全仓排查确认其它 crate 的非 ASCII 字面量共四处性质：prompt.rs 的模型面向双语注入
片段（任务描述/判别规则/语言名/schema 示例值）、guard.rs 的中文标点剥离清单、
sse.rs 的诊断省略号、eval 的 CLI 中文与 benches 语料（后两者维持扫描面外）。

处理方式：core/platform 纳入字面量判罚面；prompt.rs 作为**模型面向文案的统一
处理点**整文件豁免——与 i18n.rs 之于界面文案对称，模板主体本就是 prompts/ 文件
资源，豁免的是该文件的注入片段；guard.rs / sse.rs 两处合法字面量按惯例挂
i18n:allow（标记须与命中字符同行，放行语义是按行）。eval/benches 不纳入：
开发工具与夹具语料的中文是既定形态，纳入只会制造永久豁免噪声。

## 接入统一诊断出口（2026-10-25，gate-pr3）

- 三条检查各挂一个规则标识：字面量、装入点、词条表分别对应文案表域三标识（登记
  表见 gate_rules_comment.md），代码引用只取脚本常量区的常量。
- 去 `break` 全量报告：装入点与词条表两检查原先每文件只报第一条，修复者一轮只能
  修一处、再跑再撞下一条；改为逐行全量并补行号，等价比对口径——字面量检查新旧
  （文件，行号）集合逐一相同；装入点与词条表新版为旧版每文件首条的严格超集，新增
  即同文件后续命中行。
- 消息与位置双载：既有单测断言钉住字面量消息里「路径 行号」的文本形态（续行符
  行计数用例），故消息保留旧文本骨架，结构化位置（路径:行号）并列进统一诊断出口
  的模板位置段；旧消息里的修复指引（zh/en 词条键约定、非文案走放行标记）整体挪进
  修复行，末尾汇总后的两行指引取消，内容无损失。
- 目录缺失守卫：四个源码目录任一缺失按失败关闭退出（通用域空扫描面标识，退出码
  三）——目录缺席若静默跳过，对应扫描面悄然缩水，等于没检查到却放行；单测夹具
  基线随之补建四目录。
- 用法错误（参数多于一个、仓库根不是目录）退出码二，对齐全脚本统一约定；本门禁
  不调版本库，无基础设施路径，退出码三只来自目录守卫。

## 豁免缘由机器化（2026-10-26，PR7）

- 字面量命中行的放行标记缺同行非空缘由即按通用域的缺缘由标识报告，原豁免（该行不再报字面量判罚）保持不变；判定收口在 gate_report 的共享助手，判罚位置与字面量判罚同位同行。
- 只有字面量命中行里的标记才构成豁免现场——注释或纯代码里的标记提及不判罚。

## 检查四：词条语言规范（I18N-LANGUAGE）

- 2026-10-28 词条本身纳入语言规范：中文表词条必须含汉字、英文表词条必须纯英文，字符面（汉字面 `CJK` 与全角面 `CJKWISE`）取语言规范库（`language_spec.chinese`）同源定义，不另立口径。
- 2026-10-28 评审修正：不留任何词条豁免——初版给语言自称词条（`gloss_ui_language_en`）留了中文表保留英文原样的特例清单，语言门禁的价值恰在无一例外，特例一开就给「忘了翻译」留了合法通道；中文表该词条改写为「英语（English）」（汉字在场即合规，括注保留语言自称的辨识度），界面侧翻译一致性测试的同键特例随之删除。
- 2026-10-28 二次评审修正：中文表从「含汉字」收紧为「纯中文」——括注自称也算混语，用户口径是界面词条全中文，目标语言表既有词条（「英语」「日语」）即现成先例；技术名词随词条一并改写为中文（「JSON 输出模式」→「结构化输出模式」、「API Key」→「密钥」（随「清除密钥」既用词）、「OpenAI 兼容服务地址」→「兼容服务地址」、「模型 ID」→「模型标识」、「DMG」→「磁盘映像」、窗口标题「Gloss 设置」→「设置」——品牌在窗口创建期硬编码（`APP_NAME`），不进文案表），判罚改用拉丁面（`LATIN`）同源定义：剔模板占位符与地址方案符后残留英文字母即拦。
- 判罚口径只锁语言归属、不锁文风：模板占位符（`{{detail}}`）、地址方案符（`https://`）与快捷键符号（`⌘⇧5`）是记号不是外文，随词条保留；注释规则里「外文必须进全角括号注记」与「代码引用一律判罚」的散文全规不套词条。锁的就是最低必要规范：中文表是中文、英文表是英文（漏翻的英文中文词条、中文渗进英文表都在拦面上）。
- 解析按行正则取 `键 = "值"`，注释与空行自然跳过；它不是（TOML）解析器，键一致性仍由类型化文案表的（serde）解析测试把关，这里只看语言面。
- 词条表文件缺失按失败关闭退出（`guard_catalog_files`）：任一份缺席则语言面悄然落空，宁可报（INFRA）也不放行。随检查四在通过行尾追加实检词条数，让「查了多少」可见。

## 检查五：措辞注册表（提示词模板重设计方案 §5.2，期三，2026-10-29）

- 规则标识 I18N-REGISTRY 登记 gate_report 注册清单与 gate_rules 记录；语言
  违规沿用语言规范库的既存标识（PROSE-FOREIGN、PROSE-ENGLISH 等）。
