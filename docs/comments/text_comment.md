## parse_field / ParseState

- 2026-10-28 事件流折叠：Text 事件按序拼接为 `FieldText`（字符 + 所属文本节点号）；软硬换行计为新节点并插入换行符占位——跨行的盘古之白不误判（换行即空白隔断），数学配对天然跨不过节点边界。
- 2026-10-28 剔除面：行内码、围栏内容（CodeBlock 深度内）、HTML（块与行内）、自动链接文本——都是机器语法或 URL，不判语言标点；普通链接的可见文本照常判定（是目标语正文）。
- 2026-10-28 结构节点判定（禁 markdown 任务）：`Start(Paragraph)` 之外的一切 Start、Code/Html/InlineHtml/Rule/脚注引用/任务列表标记都算结构——设计 R6 列举（围栏、行内码、强调、标题、清单、链接、引用块）之外从严，反引号当着重号由此顺带解决。
- 2026-10-28 事件穷举：`InlineMath`/`DisplayMath` 只在开启数学扩展时产生（本实现用默认选项，事件不会出现），为穷举归入结构臂——若未来开数学扩展，`$...$` 会被解析器吃掉，与自研数学切分冲突，届时须二选一。

## math_ranges

- 2026-10-28 定界符三态：`$$`（块）、`$`（行内）、`$`+数字（货币，非定界符）；顺序扫描配对（开槽留最后一个未配定界符，类型与节点一致才闭合，否则被新定界符替换为未配——原开符落回正文按孤立 `$` 豁免）。设计 1.2 的“落单不判”与 §4 货币豁免由此同点实现。

## 评审修复（2026-10-28，PR #259 评审 P2-5）

- 数学配对的节点边界：段内软换行不拆（公式的正常折行形态，`$a +\nb > 0$` 此前被判正文标点——`+`、`>` 出界），硬换行与段落边界（空行，`End(Paragraph)`）都拆。设计 1.2“跨节点不拼装”针对的是 markdown 事件边界造成的吞并风险；段内折行按宁漏勿误放行配对，跨段的落单 `$` 不配对（防字段级吞并豁免区；初版实现只在硬换行递增节点、空行段界不拆，复审实测跨段吞并后补上段落边界）。副作用登记：同段内两个非货币 `$` 之间的区段会成对豁免——修复前各自孤立也放行，增量风险由宁漏勿误兜住。另登记一个既有边缘（复审不阻塞）：数学配对不看容器边界，“（式 `$x`）与（`y$`）”类跨括号配对会把两括号间的定界符掩掉——实测该形态放行且不误判，后续再动 `math_ranges` 时一并处置。
