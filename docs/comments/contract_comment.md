## 结算口径（2026-11-01，评测工具链重构步骤 2）

- 校验器单点：逐轮还原直接调核心层 `schema::validate_task` 与
  `schema::validate_classify`，评测自带等价解析的备选延续旧轨已被否的
  结论——两份实现漂移后评测数字不再度量生产行为。末轮定降级与检查
  项，逐轮还原违约计数与修复轮次（修复轮次 = 轮数 − 1，与生产循环的
  轮记录同口径）。
- 降级与软缺口分账：生产校验器失败（空回复、不可解析、注缺失、类别
  越清单）记降级；解析成功而检查项未过——任务的结构化字段缺失、分类
  判定与期望不符——记软缺口。分类的“解析成功但类别不符”是模型行为
  不是格式违约，混进降级会把准确率信号吞进格式桶，故分两态。
- `required_fields` 按子类形状（词卡要音标与例证、代码要代码语言与展
  开、句译与通用要例证），从旧轨的全类目统一 `examples` 升级而来：旧
  口径对缺音标的词卡与缺代码语言的代码讲解不设软缺口，与提示词模板的
  输出形状（计划 §二 参考答案形状）不符。字段在场检查只看键在不在，
  不看内容好坏——内容归评审完整性维度（计划 §6.5 互相指界）；词卡音
  标键值为 null 仍算在场（模板允许 `string|null`）。
- `derive_state` 判序：引擎故障最先、降级次之、检查项未过即软缺口、
  否则有效（计划 §6.5），互斥完备由四态派生矩阵测试钉住。
