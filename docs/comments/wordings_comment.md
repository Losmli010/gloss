## 注册表的落位与形态（提示词模板重设计方案 §4.3，期三，2026-10-29）

- 注册表落位提示词资产目录（prompts/wordings/，中英两份，配置格式（TOML）、
  编译期嵌入），装载模块住本文件：一次性惰性解析进静态量，装载失败整表
  缺席、查键未中单键缺席，一律警告后返回空——组合层回落固定措辞，无
  `panic` 路径（方案 §6 决策 2）。解析失败不重试：嵌入数据合法性由完整性
  测试前置锁定，运行时降级只作兜底不作为依赖。
- 分区与键空间四区：修复骨架区（头、行、尾、截断注、回指句五键）、格式
  违约区（违约级四键 + 细节五键，措辞行形态为位置加动作）、语言违约区
  （按规则标识收动作）、分类定义区（按类别标识收定义）。与方案 §4.3 分区
  示意的偏差：骨架区多一个回指句键——回指是修复轮措辞的一部分，放代码
  会把中文回灌进组合层，放骨架区则归注册表语言检查管；行格式与截断注等
  其余骨架键与示意一致。
- 格式违约区把违约级键与细节键收在同一区（键名空间不撞：违约级是变体名
  帕斯卡形态，细节是蛇形小写）：方案 §4.2 的“两键在注册表各有一行”按
  同区两键实现，查表规则是有细节用细节键、无细节用违约级键。
- 语言违约区与分类定义区的值是单语散文，键是枚举标识；类别标识不进值——
  分类条目由组合层以“类别标识 + 定义”拼行，值保持纯语言（中文表中文、
  英文表英文，由文案门禁的注册表检查逐条判罚）。
- 分类条目的行前缀（列表记号与冒号）与骨架回指外的静态散文不进注册表：
  纯格式与无枚举键的散文按方案 §6 决策 6 的口径留在组合层与静态模板。

## 查键入口

- registry / frame / format_row / lang_action / classify_definition：五个
  入口覆盖组合层全部取词路径；frame 只在整表缺席时为空（骨架键是结构体
  字段，缺键即解析失败），其余入口按键查映射，未中警告留痕。警告字段只有
  键名与线程角色，不携带措辞值与回复内容。
- 线程角色按调用方标注：format_row、lang_action、classify_definition 走
  提示词渲染（引擎侧），violation_name 经批注清单渲染被界面逐帧调用（界
  面侧），缺键警告分别标引擎线程与界面线程；registry 装载首调可在任一侧
  发生（惰性一次性），线程标注随首个调用方。

## violation.name 规则名区（降级批注方案 §3.4，2026-10-30）

- 新分区按规则标识收界面语短名，与语言违约区（动作）同册——模型修什么、
  用户看什么，同键可对；完整性测试与键集对齐测试同步扩区。查键未中有痕
  降级，批注清单整体回落泛化文案。

## 注册表新加区（2026-10-30，语言规范统一阶段四 G4）

- 四个新分区随文案迁移落地：目标语言名区（target_lang.zh/en，随 D5 缩为
  两态）、聚合一区（repair.aggregate.joiner，例句序号连接符——修复轮行清
  单与降级批注行共用的同一份事实，自代码常量迁入）、例句位置一区
  （repair.example_position 的单复数两条模板，占位符 {{joined}}；中文单复
  数同形，两键在两份表各持一份以守键集相等）、分类段头一区
  （classify.section 的标题词与分隔符，标题记号“###”留在代码——它是结
  构记号不是措辞）。四区都是结构体字段而非映射：键的存在性由解析器保
  证，缺区即整表解析失败、走整表缺席的有痕降级。
- 例句位置的措辞拆成“字段键 examples（代码，ASCII）＋措辞模板（注册
  表）”两段拼装：字段键是产物契约的标识符不是措辞，住代码；中文模板里
  不夹裸外文，注册表逐条值守中文区判据（文案门禁）才可通过。
- 完整性测试扩区：新区非空、例句位置必须携带 {{joined}} 且可渲染。
