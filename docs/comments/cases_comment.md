# cases 决策记录

> 按符号锚定（不写行号，防漂移）。改到相关代码时同步更新本文件。
> 本文件随仓库跟踪（docs/comments/ 入库），改名与合并用 git mv 保留历史；文件内不留指向本文件的指针。

## render

- 测试用例区：区标题行右侧常驻导出标注按钮（初始计数为已标注例数），
  标题下色块图例覆盖契约、回归、标注三组全部枚举（色板与徽标共享），
  筛选分类型、契约、回归三行（与运算组合，纯文字按钮不带计数），过滤
  结果为空时显示“该筛选下无用例”；列表固定最差优先排序。

## sorted / order_key / badge_rank

- 最差优先排序键分层（先到先得）：引擎故障最先，契约降级次之；带回归
  徽标者按回归、待复核、未改善排；其余按最低维分升序、未评排已评之后；
  同级再按总体分升序，仍同按用例集序（稳定排序保序，不用索引键）。

## card

- 列表七列：用例标识、输入、任务类型、轮次、契约、回归、模型评分——
  标识与内容四列在左，三条判定列在右且两条规则轴相邻；契约列四态徽
  标、回归列五态徽标（待比无徽标），徽标悬停带逐态注释；模型评分为总
  体分（四维均值派生），未评分显示占位符。

## columns

- 展开态三栏并排（输入、本轮输出、基线输出），无基线退化为两栏；本轮
  输出取结算轮原文，基线输出取固化行的末轮分片拼接；引擎故障不显示原
  文，输出栏落请求失败说明。

## reference

- 参考答案整行：任务用例显示理想产物（与被评产物同构），分类用例显示
  期望类别（`expected` 键）并改列名点明。

## settle

- 结算明细统一三行：契约（徽标与检查项按固定顺序罗列，降级追加未收敛
  轮数与违约计数）、回归（徽标与差异摘要，待比按有无基线区分文案）、
  模型评分（四维分、总体与理由；未评分写明原因——分类不打分、契约故
  障与降级跳过、评审未开启三档）。
- 违约类别沿用生产校验器枚举的变体名（如 `NotJson`），不在本包另拟别
  名；逐轮轨迹折叠中同款变体名作轮标签。

## markline

- 标注按钮组（合格与不合格，纯文字单选）与备注输入按既有标注预填；备
  注记录判断依据，随导出落库、长期留存。

## group_key / contract_key / regression_key

- 筛选轴的数据属性取值用半角短词（`classify`、`valid`、`pending` 等），
  与内联脚本的筛选按钮一一对应；图像类型预留给数据集未含的类型，筛选
  行不设按钮，“全部”下可见。
