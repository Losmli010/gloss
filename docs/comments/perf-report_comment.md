## 定位（2026-10-08，T5）

- 本脚本是趋势数据的人读静态视图（设计 4.4），只读 history.jsonl 与
  selftest.jsonl，不写任何数据；判定仅参考非门禁——clone-check 与 L3
  自检退出码才是门禁，对比表头与摘要都显著标注。
- 输出确定性：内容全部派生自数据、不含生成时刻，同输入两次运行逐字节
  一致（与三张 SVG 同纪律），数据 PR 里报告 diff 即数据 diff。

## BUDGET_SIGNAL_FIELDS（2026-10-08，T5；同日 PR 评审后补导入期校验）

- 预算指标的 PASS/FAIL 按信号行内「该指标值 ≤ 行内预算字段」逐指标转述，
  而不是直接引用 overlay 信号行的 verdict 字段：该字段是 show+rss 合并口径
  （首帧超预算或尾段超预算任一即 fail），逐指标转述会互相污染（首帧超支
  时尾段行也会显示 FAIL）；startup 信号行则根本没有 verdict 字段（判定走
  退出码，wrapper 不把退出码写进 selftest.jsonl）。行内值/预算字段就是
  自检做同一判定所用的同源数据，按它对比是最忠实的逐指标转述；判定权
  仍在自检退出码。
- 已验证（2026-10-08 夹具自测）：first_ms=138/fail 且 tail=340 KB 时，
  show_first_ms 显示 FAIL 而 rss_tail_growth_kb 显示 PASS——合并 verdict
  字段做不到这个区分。
- 映射与注册表预算门禁指标的对应由 _validate_budget_signal_fields 在
  import 期校验（初版只靠信号行下标的条件性 KeyError，评审指出绝大多数
  无信号文件的运行不暴露——采纳，改成与 metrics.py import 期自检同模式
  的确定性失败，缺映射/多余映射都带指引）。新增预算指标时同步此映射
  （对照 metrics.py 的 BUDGET_CONSTS）。

## 总览判定列（2026-10-08，T5 初版；同日 PR 评审后改为呈现 judge+note）

- 非预算行呈现注册表 judge 与 note 括注（如「仅记录（外部服务波动）」、
  「精确计数门禁」）：初版按任务卡 bullet「仅记录类标『—』」实现成恒
  「—」，评审指出这与设计 4.4 样例及已合入的 T1 注册表契约
  （metrics.py Metric docstring「报告判定列随 judge 一并显示」）冲突，
  三处来源必须对齐——采纳按样例+契约实现。bullet 重新解读为「这类行
  不标门禁判定（PASS/FAIL）」，与「判定发生在 L3 自检，报告只转述」的
  上文连读语义自洽；这行没有可转述的判定信号，呈现判定语义本身。
- 预算数值与 PASS/FAIL 任一缺席时只展示在场部分：信号文件缺席（本机没
  跑过 wrapper）时预算行显示「预算 4,000 ms」不带判定；历史里还没有任何
  点携带预算时只显示 PASS/FAIL；两者都缺才「—」。任务卡「否则标『—』」
  指判定部分，预算数值子句（「取最新携带预算的历史点」）不随之失效。
- 预算数值取「最新携带预算的点」（如启动预算 15000→4000 的变更时间线上
  取 4000），与信号行内携带的预算字段可能不同步（Rust 常量已改、历史未
  重采），此时以历史点为准展示——报告是趋势视图，不是实时配置查询。

## vs 上一点 / vs 首点（2026-10-08，T5）

- 对比锚点是该 id 自身在此前/此后的最近携带点，不是文件里相邻的点：某
  源（如 eval）隔了几轮才再采集时，与图表数值槽同口径（每系列对上一
  非缺失点比），不制造伪「—」或伪跳变；id 仅最新点才有（首次采集）时
  两列都「—」。
- 首点取「该 id 的首个数据点」而非文件首点：后者会让中途新增的源永远
  显示「—」，列失去信息量；「自引入以来的变化」更有趋势价值。

## 对比视图（2026-10-08，T5）

- 无数据计数 = 注册表 id 在两点恰缺其一（对称差）的个数：恰缺其一说明
  采集覆盖面在两期间变了（新源接入或旧源缺席），审查时值得知道；两点
  都没有的 id 与本次对比无关，不计入。缺源即缺行：明细表只列两点都有
  的 id。
- 判定映射：精确计数门禁类（clone.total/allocs/bytes）按整数对照，上升
  即回归、下降即改善、相等标「持平（精确计数）」——与 clone-check 同向
  但非门禁（门禁基线随 history 最新点走，这里只是两期快照对照）；其余
  全部（含预算门禁指标）走注册表 noise 阈值启发式。旧值为 0 时 Δ% 无法
  定义，标「—」，新值非 0 即判回归（从无到有按最坏情况提示）。
- 指标列显示 id 不显示中文 label：虽然 Metric 的 docstring 说 label 供
  报告表格使用，但 4.4 示例与任务卡都用 id（可 grep、可对照 history
  diff），且全表 label 会让表格显著变宽；label 继续由图表图例消费。

## 数据路径与 v1 兼容（2026-10-08，T5）

- `--history` / `--selftest` 覆盖缺省路径（相对路径按仓库根解析，与
  selftest_wrapper 的 --out 同惯例）：T2 未合入时真实 history 还是 v1，
  开发与自测靠本地 v2 夹具驱动（夹具放 target/ 不入 git）；T7 数据 PR
  生成对比表时走缺省路径即可。
- v1 旧点无 metrics 段按缺源处理，本脚本不做 v1→v2 迁移：迁移是
  collector 写回时的一次性职责（设计 3.1），视图层重复实现会掩盖「忘跑
  collector」的错误；T2 合入前对真实 history 跑总览得到空表（头部 +
  表头），是预期行为不是缺陷。
- 头部环境行取最新点 env，最新点为空（v1 迁移点 env 空对象）回退最新
  非空 env，与 3.2 图表口径一致；os/arch/cpu 按数据原值拼接不做美化
  （env::consts::OS 给 "macos" 就显示 "macos"），视图不改写数据。

## 文件头迁出的用法与视图（2026-10-24，注释纪律）

- 用法：`scripts/perf/perf-report.py` 总览最新点；`scripts/perf/perf-report.py --from
  a1b2c3d --to e4f5a6b` 两期对比；`scripts/perf/perf-report.py --history
  /tmp/h.jsonl --selftest /tmp/s.jsonl` 覆盖数据路径（相对路径按仓库根解析）。
- 数据文件：`baselines/history.jsonl`（v2 扁平点）与 `target/perf/selftest.jsonl`
  （L3 自检信号 handoff）；输出 Markdown 到 stdout。
- 总览视图：最新值、vs 上一点、vs 首点、判定；预算门禁指标转述自检信号
  （预算数值 + PASS/FAIL），其余行括注 judge 与 note。对比视图（`--from/--to`）：
  改善/回归/持平/无数据摘要 + 明细表。
- 预算判定转述口径：PASS ⟺ 自检信号行携带的该指标值 ≤ 行内携带的预算字段；信号文件、
  信号行或任一字段缺失即「—」。
