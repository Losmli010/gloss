## 验收意图

- 评论正文书写规则的单测覆盖：直角引号是收口计划的指定样例（字符白名单外即拦，
  对应验收项“含直角引号的行内评论触发红灯”）、英文整句与汉字拉丁连写各归其标
  识、反引号与围栏及链接和勾选框的结构性豁免面放行、多行评论逐行判。
- 空正文放行（含纯空白与全角空白）锁定排除语义单点在钩子工作流的作业条件：脚
  本不做第二份排除判定，这条边界由本测试钉住，防止日后误加空正文规则造成两处
  口径漂移——与评审结果门禁的空正文判罚相反，那里空正文意味着正式产物缺席，这
  里空评论只是没有评论。
- 软约束候选用例锁定透传不改标：候选保留原标识、走警告属性、不计入运行函数的
  违规清单；标识沿用登记表内的书写规则标识，用例断言不出现新标识。
- 命令行端到端锁定反馈契约：违规行带规则标识与补救指引、汇总计数与明细数相等、
  同输入两次运行输出逐字节一致、合规输入退出码零、标准输入减号取数可用、缺参
  退出码二。托管平台上的端到端（真实评论事件触发作业红灯）随作业上线由工作流
  承担，不在单测面。

## 辅助契约

- 夹具正文按书写规则白名单组句（合规样例不含白名单外字符），防止夹具自身误触
  判罚；违规样例的违规面刻意单一（一行只带一处违规），让计数断言可读。
- 被测入口是发现函数与运行函数，不落进程；端到端用例经子进程跑脚本本体，锁的
  是持续集成作业的调用契约（文件路径取数与退出码）。
