## inject_copy（2026-11-06，Windows 移植 P2①）

- 模拟复制键序：修饰键（Ctrl）按下、C 按下、C 释放、修饰键释放，一次
  `SendInput` 投递四事件——与系统（macOS）逐事件注入不同，系统（Windows）
  的注入接口按数组原子投递，部分失败只发生在事件数不被全收时。
- 部分失败按已注入的按下键逆序补放（`releases_before`）：不留卡住的修饰
  键；补放本身再失败则留给下一轮兜底注入（key-up 幂等），不重试出死循环。
- 对提权进程的注入被系统静默丢弃（用户界面特权隔离（UIPI））：本层收到的
  仍是“成功投递”——写没写由剪贴板序列号确认（见剪贴板兜底读取器），
  按移植方案定案不做提权、不上报为权限错误。

## copy_sequence / releases_before

- 纯函数：键序与补放列表供单测钉住顺序契约（修饰键先按后放、键夹中间、
  失败点之前的按下键逆序）。
